### 格式与工具链

- **[强制] 遵循既有风格**: 修改代码时优先匹配项目现有命名, 分层, 错误处理和测试组织方式.
- **[强制] 小步变更**: 优先做局部, 可验证, 易回滚的修改; 不把无关重构混入功能变更.
- **[强制] 明确验证**: 修改后运行与变更范围匹配的测试, lint 或构建命令; 无法运行时说明原因和替代检查.

### 错误处理

- **[强制] 错误显式传播**: 不吞掉错误或异常; 捕获时保留原始上下文, 不把错误静默降级为默认值或空结果.
- **[默认] 失败可定位**: 错误信息应足以定位发生位置与触发条件, 不向调用方或用户暴露实现细节与敏感数据.

### 并发与资源

- **[强制] 资源显式释放**: 文件, 连接, 锁等资源用语言习用的确定性释放机制 (RAII / try-finally / with / defer), 不依赖手动记忆释放.
- **[默认] 避免全局可变状态**: 共享可变状态通过明确接口或依赖注入传递, 不通过全局变量隐式串联模块.

### 安全与边界

- **[强制] 不信任外部输入**: 来自网络, 用户输入, 环境变量和持久化存储的数据在信任边界做校验, 不直接用于命令拼接, 查询或反序列化.
- **[默认] 类型与边界清晰**: 公共接口, 配置项, 持久化结构和协议字段应保持兼容性, 变更时说明迁移影响.

### 测试与组织

- **[强制] 依赖方向单向**: 模块依赖应单向无环, 不出现循环引用; 跨层调用通过明确接口而非具体实现.
- **[默认] 配置外置**: 环境差异, 密钥, 阈值等通过配置注入, 不硬编码进业务逻辑.
- **[默认] 测试贴近行为**: 测试覆盖关键业务路径与错误分支, 优先验证行为而非实现细节.
