### 格式与工具链

- **[强制] 类型边界**: 新增公共函数, 服务边界和复杂数据结构应提供类型标注; 数据模型优先使用项目既有 schema/model 机制.
- **[默认] 格式与 lint**: 遵循项目既有 `ruff`, `black`, `mypy`, `pytest` 等工具配置.
- **[默认] 入口 guard**: 可执行脚本用 `if __name__ == "__main__":` 保护副作用入口, 不在模块顶层执行.

### 错误处理

- **[强制] 异常语义清晰**: 不使用裸 `except`; 捕获具体异常类型, 不把错误静默降级为默认值.
- **[强制] 异常链保留**: 重新抛出或包装异常时用 `raise ... from original` 保留原始上下文, 不丢失根因.

### 并发与资源

- **[强制] 资源用 with**: 文件, 连接, 锁等资源用 `with` 语句或上下文管理器管理, 不依赖手动 close.
- **[强制] 可变默认参数**: 函数默认参数不用可变对象 (list, dict, set), 用 `None` + 内部构造替代.
- **[默认] 模块边界简洁**: 避免在模块 import 阶段执行网络, 文件写入或重型初始化.

### 安全与边界

- **[强制] 参数化查询**: SQL 必须用参数化绑定, 不用字符串拼接或 f-string 组装查询.
- **[默认] f-string 不泄露敏感**: 日志与错误信息中的 f-string 不拼接密码, token, 连接串等敏感字段.

### 测试与组织

- **[强制] 依赖注入优先**: 外部服务, 文件系统, 时间和随机数等副作用应便于测试替换.
- **[默认] 协议与模型边界**: 抽象行为用 `typing.Protocol`, 数据边界用 `dataclass` 或项目既有 Pydantic / ORM 模型, 不混用.
- **[默认] async 边界**: async 函数不与同步阻塞 I/O 混用; 长耗时同步操作移到 executor 或改为 async 实现.
