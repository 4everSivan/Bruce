### API 安全与契约红线

- **[红线] 禁止未审计暴露面**: 未确认认证方式, 匿名访问边界和权限模型前, 不得新增或放宽公开 API.
- **[红线] 禁止响应泄密**: API 响应不得泄露敏感字段, token, 内部错误栈, 连接信息或实现细节; 错误响应必须可定位但不暴露内部实现, 调试信息只允许进入受控日志.
- **[红线] 禁止无迁移策略的破坏性变更**: 未提供版本策略, 迁移说明, 兼容层或用户确认的 breaking-change 方案前, 不得发布破坏性 API 契约变更.
- **[红线] 禁止不安全重试**: 非幂等写接口不得在缺少幂等键, 事务保护或重复提交防护时支持自动重试.
- **[红线] 禁止已知契约漂移发布**: 已知 API 契约与实现不一致且影响安全或兼容性时, 不得发布.
- **[强制] 输入边界校验**: 所有外部输入必须经过 schema, 类型, 范围或业务约束校验.
- **[强制] API 变更须补充测试并说明约束**: 新增或修改 API 时必须补充或更新请求/响应, 权限, 错误路径或契约测试, 并说明认证方式, 权限模型, 错误码, 限流或请求大小约束.
- **[默认] 契约源优先**: 优先使用 OpenAPI, GraphQL schema, proto 或项目既有契约源维护 API 兼容边界; 当契约文件与实现漂移时, 不得默认以任一方为准, 必须在变更中显式标注漂移并由用户确认修正方向.
- **[默认] Handler 保持薄层**: API handler/controller 只做协议转换, 鉴权上下文和参数校验; 业务逻辑应下沉到 service/domain 层.
