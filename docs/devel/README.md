# 开发文档入口 (devel/)

> **created**: 2026-09-23 ｜ **last-change**: 2026-10-20 ｜ **status**: active

## 1. 简介

`docs/devel/` 组织设计、开发和维护工作。先确认事项属于哪条轨道，再读取对应设计、模板和总账；日常无需再次调用 `$ad-flow`。

共同元数据、路径、授权和校验规则见 [文档中心](../README.md)，项目协作规则见 [AGENTS.md](../../AGENTS.md)。

## 2. 索引

| 文件或目录 | 入口 | 维护内容 | 使用时机 |
|---|---|---|---|
| `../standards/coding.json` | [代码编写规范](../standards/coding.json) | 通用规则、所选语言规则及官方来源 | 编码与代码审查前 |
| `design/` | [设计中心](design/README.md) | 总体与模块设计、主题锚、演进记录 | 理解规则、设计新能力或评估规则变动 |

| `task/` | [任务卡池](task/README.md) / [总账](task/index.json) | 阶段目标、能力交付及依赖 | 新功能、里程碑、模块建设 |

## 3. 研发规则

- **编码规范**：读取 `../standards/coding.json` 的通用规则及当前语言规则；项目约定和已有工具配置优先。只检查本次变动，不为套用规范批量格式化历史代码。
- **按事项分轨**：C 卡记录具体修复及前后差异，T 卡记录阶段能力和依赖。按目标选择轨道，不为同一执行事项重复建卡。
- **设计先行**：建卡挂接具体设计正文及匹配的 `@topic`；设计缺失时先补齐相关正文。README 仅用于导航和操作说明。
- **批准与实现分开记录**：设计基线描述已批准规则，尚未实现的能力由 T 卡体现；代码存在、测试通过与人工验收分别取证。
- **先登记再执行**：从 `../standards/change-template.json` 或 `../standards/task-template.json` 建卡，填写发布批次、执行分支、目标及验收条件，在总账登记。若事项来自 todo，建卡登记后同步删除原行；尚未建卡的事项继续留在待办。
- **状态保持一致**：卡片状态与总账同步更新；合入和归档前核对编号冲突、依赖与路由，不覆盖其他事项的记录。

## 4. 日常执行顺序

| 阶段 | C 变更轨 | T 任务轨 |
|---|---|---|
| 明确目标 | 定位现象、原因与规则差异，挂接所属设计 | 明确阶段能力、设计与完成定义 |
| 建卡登记 | 建 C 卡，预先定义 `verification.checks` | 建 T 卡，定义 `tasks[]`、`depends_on` 与 `acceptance.checks` |
| 实现与取证 | 运行预检和授权回调，修复并补针对性回归 | 依赖完成后开工，交付能力并逐项验收 |
| 验收收口 | 人工确认后预检 `verified`；合入及必要回写后预检 `closed` | 实测及项目要求的验收完成后预检 `completed` |
| 发布归档 | 仅本次发布批次的 `closed` 卡 | 仅本次发布批次的 `completed` 卡 |

收口命令、证据字段和异常处理见 [变更操作](change/README.md) 与 [任务操作](task/README.md)。Exit 0 后再同步状态并普通复核；卡片完成不自动授权推送、部署或发布。

归档按 [归档操作](../archive/README.md) 执行，现行总账保留历史卡号并更新路径。后续任务可以引用归档的已完成依赖，归档卡保持只读。

### 卡片发布批次归属（C074）

> 📌 **卡片发布批次归属**：变更卡的发布批次**不写入 `Cxxx.json` 卡片文件本体**，统一由总账 [change/index.json](change/index.json) 的卡条目 `version` 字段承载（如 `"0.12.2+"`）；设计文档与 Markdown 头部均不标注 `version`，不设独立小版本号。
