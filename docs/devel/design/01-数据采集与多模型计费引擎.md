## 1. 简介 (Introduction)

本方案定义 `Bruce` 的核心数据引擎 —— **Core Collector**。
Core Collector 独立运行于 `core/collector/`，由纯 Rust 打造，作为高吞吐、零内存泄漏的守护采集进程。

- **业务动因**：现代开发者通常在本机多 Agent 并行开发（如使用 Claude Code 自动化重构、Codex 审查代码、Kimi Code 分析仓库、OpenCode 执行终端操作等）。每个 Agent 拥有独立的会话目录、专有的日志格式（JSONL、SQLite、增量转储）及不同的模型标记。开发者迫切需要一个统一、轻量、近实时的引擎，快速扫描本地日志并折算为统一的 Token 与美元费用指标。
- **系统定位**：作为底层数据生产引擎，向下只读扫描用户家目录下的 Agent 会话日志与云端额度接口，向上通过标准 IPC（JSON over stdio）为应用层（macOS App / Web Widget）提供强类型标准工件（Artifact）。

---

## 2. 目标与非目标 (Goals & Non-Goals)

### 2.1 目标 (Goals)
1. **多源异构会话即时扫描**：原生支持 Claude Code, Codex, Kimi Code, OpenCode, CodeBuddy, Grok, Pi, ZCode 等 8+ 主流 Agent 的日志解析；
2. **增量指纹与零冗余 I/O**：基于 `64KB Segment Fingerprint` + `mtime/size` 双重缓存策略，冷启动后二次扫描延迟低于 50ms；
3. **多模型精密计费**：内置主流大模型基准价卡（输入、输出、Cache Read 单价与缓存写入 TTL 倍率，唯一事实源 `pricing-catalog.json`，C108），支持模型别名归一化与用户自定义覆盖（Overrides）；
4. **强健的系统安全性**：对符号链接提供防环保护（Cycle Prevention），读取外部应用 SQLite 时强制 `mode=ro` 只读连接，绝不破坏宿主会话。

### 2.2 非目标 (Non-Goals)
1. **不拦截或代理模型网络流量**：不充当本地反向代理或网关，纯旁路离线审计；
2. **不修改或清理第三方 Agent 会话文件**：严禁向扫描目录执行写入、删除或格式化操作；
3. **不提供跨机器数据同步服务**：所有采集和聚合逻辑均在单机闭环。

## 3. 需求分析 (Requirements)

### 3.1 功能需求清单
- **FR-1 多源扫描**：自动探测本机 `~/.claude/`、`~/.codex/`、`~/.kimi/` 等标准路径，兼容单文件 JSONL、分片目录与 SQLite 状态库；
- **FR-2 时间窗口切片**：支持今天（Today）、过去7天（7d）、过去30天（30d）与全量（All-time）四维时间窗口聚合；
- **FR-3 维度多维交叉**：支持 `Agent × Model × Month`、`Agent × Project` 等多维聚合，生成模型分布占比与趋势数据；
- **FR-4 成本换算**：按各模型具体输入 Token、输出 Token、缓存读取 Token（Prompt Cache Read）分别乘以单价并折算为 `costUsd`。

### 3.2 非功能需求 (NFR)
- **性能指标**：冷启动扫描 10,000+ 条会话日志总耗时 < 1.5 秒；增量缓存命中时总耗时 < 80 毫秒；
- **内存开销**：单次完整采集峰值内存占用 < 35 MB，任务完成后瞬时释放；
- **架构兼容**：支持 Universal 2 二进制（`arm64-apple-darwin` 与 `x86_64-apple-darwin`）。

##### 2. 费用核算计算式
对于任意用量切片，总费用计算严格遵循以下纯函数公式：
$\text{Cost} = \frac{\text{input} \times P_{\text{in}} + \text{output} \times P_{\text{out}} + \text{cacheRead} \times P_{\text{cache}} + (\text{write}_{5m} \times m_{5m} + \text{write}_{1h} \times m_{1h}) \times P_{\text{in}}}{1,000,000}$
- **缓存写入按 TTL 拆分（C107）**：`write_1h` 取 Claude Code 日志 `usage.cache_creation.ephemeral_1h_input_tokens`（贯穿 `TokenBucket.cache_creation_1h`，上限为 `cache_creation`），其余缓存写入计为 `write_5m`；未区分 TTL 的来源全部计为 5 分钟写入。倍率 `m_5m` / `m_1h` 由价卡行声明（`cache_write_multiplier` / `cache_write_1h_multiplier`），Anthropic 行为 1.25 / 2.0，未声明时 `m_5m = 1.0`、`m_1h = m_5m`（即按输入单价计，与 C107 前一致）；
- 当模型命中用户在设置中配置的自定义覆盖项（`ModelPricingOverride`）时，优先采用覆盖单价；缓存写入倍率沿用内置行（覆盖输入单价时写入成本随之等比变化）；
- 未匹配到任何价卡行（含覆盖项）的模型**不估算费用**：对应桶 `costUsd` 为 `null`，工作台计入「未定价 tokens」。

##### 3. 增量缓存机制与文件防环
- **分段哈希**：扫描器仅对会话文件头部及末尾 64KB 执行 SHA-256 计算，避免对数百兆历史日志全量重哈希；
- **源级缓存 (C021 起)**：JSONL 与 SQLite 源在未变更（按身份/指纹判定）时直接复用上次解析结果（`jsonl_cache.rs` / `sqlite_cache.rs`），避免重复解析整棵源树；缓存启用与失效路径需与冷扫结果逐字段一致（`cached_*_sources_match_cold_and_warm_results` 系列用例锁定）；SQLite 缓存签名含**库文件头 change counter**（偏移 24 大端 u32）与（Windows）**创建时间身份**，使「替换 vs 追加」判定不依赖文件时间戳粒度（C022：Windows 时间戳粒度约 15ms，仅凭 size/mtime 会把替换误判为追加并静默返回陈旧用量）；
- **增量追加身份红线 (C040)**：SQLite 游标增量追加必须以**缓存身份全匹配**（窗口长度/时区/今日，`cache_identity_matches`）为前置——身份错位（如以不同 `days`/时区参数直跑 collector）时旧条目的天索引在新窗口 `day_list` 下会错位或越界，此时严禁增量合并，必须整体回退全量重建；base 解码失败（`to_domain` = None）同样回退重建，**严禁以空 base 合并后推进游标**（该路径曾把历史整体清空且无自愈，回归用例 `zcode_sqlite_cache_window_mismatch_rebuilds_instead_of_empty_append` 锁定）；
- **聚合格式版本红线 (C072)**：SQLite 缓存条目身份必须包含**聚合格式版本**（`aggregation_version`，与 JSONL 缓存条目同一防线）——任何影响缓存贡献形状的聚合演进（如 C070 的 `day_models`/`hour_models` 明细桶）都必须同步提升 `AGGREGATION_VERSION`，令全部旧条目身份失配回退全量重建。C070 曾只以 serde 可缺省字段兼容旧条目而漏设此门禁：升级后无明细的 v2 条目被当合法 base 增量追加，历史逐日/逐小时模型明细永久缺失而月明细幸存（月/日视图口径分裂），回归用例 `zcode_sqlite_cache_aggregation_version_mismatch_rebuilds_detail` 锁定；
- **行数截断严重度 (C041)**：SQLite 源扫描上限 `MAX_SOURCE_ROWS = 30,000`（覆盖 ZCode 自身修剪后的存量天花板，常态不触发），触顶语义为「保留最新、丢最旧」的**计划内信息级降级**：`SourceScan.capped` 结构化标记贯穿缓存条目，对外用独立诊断码 `LOCAL_SOURCE_ROWS_CAPPED`，agent 状态保持 ok 仅记 note，**不参与 envelope Partial 判定**（否则菜单栏把常态降级误报为红色故障环）；`LOCAL_SOURCE_SCHEMA_INCOMPATIBLE` 仅用于真实 schema/读取故障；
- **取消语义 (C021 起)**：本地扫描在源循环与目录遍历层均检查 `CancellationToken`，取消时停止扫描并以 `LOCAL_SOURCE_CANCELLED` 拒绝发布半成品 artifact（发布前设终态栅栏）；单 root 的 I/O 错误按 `io_errors` 计数并保留已得贡献，不整次失败；
- **防环保护**：维护 `visited_inodes: HashSet<(u64, u64)>`（针对 Unix 文件系统 `(dev, ino)`）与目录 canonical 路径集合，当检测到重复节点或深度超过 16 层（`MAX_DIRECTORY_SCAN_DEPTH`）时立即切断，防止符号链接循环导致的死循环或栈溢出。
- **生产路径不得以 panic 表达数据不匹配 (C043)**：缓存条目构造中 `from_domain` 返回 None（某天不在当前窗口 `day_list`）一律「放弃写该缓存条目 + 计 `cache_corruptions`」，严禁 `expect`；worker 线程失败（local/quota/aggregation）一律降级为 `COLLECTOR_WORKER_PANICKED` 诊断而非 `join().expect`；采集入口 `run_bytes_panic_safe` 以 `catch_unwind` 兜底输出 `BRIDGE_INTERNAL_PANIC` error envelope，保证 stdout 恒有可解释 JSON（此前 panic 会让宿主只看到非零退出码）；
- **目录递归双护栏 (C045)**：全部会话目录遍历（未缓存 walker、JSONL 缓存适配器、Codex 文件收集、Kimi 树缓存）共用 `MAX_DIRECTORY_SCAN_DEPTH` 与 canonical 已访问集合双重护栏，任一实现缺一即视为缺陷（用例 `jsonl_cache_adapter_survives_symlink_cycle` 以 `files_visited` 计数锁定护栏有效性）；
- **降级必须可见 (C046)**：聚合合并失败 → agent 降级 `partial` 且 note 说明数据不完整（不再静默丢用量）；次要源 I/O 错误 → 信息级诊断 `LOCAL_SOURCE_IO_DEGRADED`（区分「源不存在」与「读取失败」）；Codex 树缓存解码异常 → 计 `cache_corruptions` 并在 note 说明；
- **缓存写盘权限口径 (C047)**：一切缓存写盘统一 `create_new + 0600 (unix) + 失败清理 + rename`，不留 umask 窗口；
- **provider 专属语义边界 (C048)**：provider 的失败语义（`failureKind` / 失败文案）、新鲜度（`freshness`）、鉴权挑战（`credential_challenges`）及凭据轮换（`credential_updates`）统一由 `collector-provider` 的 `QuotaProvider::finalize_outcome` 产出的 `ProviderOutcome` 标准化输出；官方凭据缺失提示与嵌套 OAuth 解包规则统一在 `CATALOG_SPECS` 声明；账户计划专属参数校验归属 `collector-application::account`；编排层（`execution.rs`）与协议层（`collector-bridge`）**严禁按 provider 名字硬编码分支**；
- **provider 目录单一事实源 (C049)**：provider 的 prefix / app / 凭据字段统一定义在 `collector-provider` 目录表（由 `catalog_entries()` 投影），其他 crate 一律派生，**禁止复写字符串**；一致性由 `catalog_entries_are_complete_and_unique` 锁定；
- **截断文案不得硬编码上限 (C050)**：诊断文案必须引用 `MAX_SOURCE_ROWS` 等常量，防止上限调整后文案失真；
- **出站台账缓存（C038 引入，C039 回收）**：`LedgerCache` 端口曾是 Cline `/usages` 逐单台账的跨运行增量管线（端口在 `collector-runtime`、`FileLedgerCache` 在 `collector-local`）；C039 将 Cline 三窗口切换为服务端权威端点直读（design/02 规则 5）后，该管线失去唯一消费者并整体删除（git 历史保留 C038 实现，台账端点在 design/02 备案为回退路径）。**现行约定：provider 一律无状态**，quota 类数据优先直读服务端权威聚合端点，不为窗口建模引入跨运行本地状态。

## 7. 扩展设计 (Additional Technical Design)

### 7.1 缓存持久化
- **位置（单一事实源）**：缓存根恒由 `collector-local::default_cache_root` 解析，App 侧不透传 `cache_root`（Windows 壳注入的也是同一函数结果）——macOS / Linux 为 `~/Library/Application Support/Bruce/collector-cache-v1`（**不是** macOS 惯例的 `~/Library/Caches`），Windows 为 `%LOCALAPPDATA%\Bruce\collector-cache-v1`（`LOCALAPPDATA` 优先，空白值视为未设置并回退 `~/AppData/Local`），使机器本地缓存不落 roaming profile。
- **分层结构（按源类型分四层，C021 起源级缓存）**：

| 缓存层 | 实现位置 | schema 常量 | 覆盖源 | 形态 |
|---|---|---|---|---|
| Kimi Code CLI 专用 | `collector-local/src/lib.rs` | `CACHE_SCHEMA_VERSION = 1`（另有 `PARSER_VERSION = 2` / `AGGREGATION_VERSION = 2`） | kimi-code-cli（`~/.kimi-code/sessions`） | `manifest-<源根摘要>.json` + 每文件一条增量条目（身份 `source_kind` / `source_path_digest` / `window`，文件 `file` 签名与 `safe_offset` · `head_length` · `prefix_tail_length` · `head_fingerprint` · `prefix_tail_fingerprint`，载荷 `delta`） |
| JSONL 源级 | `jsonl_cache.rs` | `JSONL_CACHE_SCHEMA_VERSION = 1` | kimi-work、claude-code、codebuddy、grok、pi | 每文件一条 `JsonlCacheEntry`（身份 `schema_version` / `source_id` / `source_path_digest` / `parser_version` / `aggregation_version` / `window`，文件签名与 `safe_offset` · `head_length` · `prefix_tail_length` · `head_fingerprint` · `prefix_tail_fingerprint`，载荷 `payload`）+ 一份 `JsonlCacheManifest`（源内已见路径摘要集合） |
| SQLite 源级 | `sqlite_cache.rs` | `SQLITE_CACHE_SCHEMA_VERSION = 2` | opencode、zcode | 每库一条 `SqliteCacheEntry`（`schema_fingerprint` / `signature` / `cursor`(rowid · timestamp_millis) / 身份三元组 `window_days` · `timezone` · `today` / `append_safe` / `capped` / `diagnostic` / `contribution`） |
| Codex 树缓存 | `sources.rs` | — | codex | 单文件 `codex-tree-v1.json` |

  字段全集与逐字段语义以对应实现文件为准；本节只声明层级与身份判定口径，不做逐字段镜像，以免文档先行腐化。
- **复用与版本迁移**：条目参与复用以身份全项相等为前置（三层各有一个 `cache_identity_matches`，比对 schema / `source_id` / 路径摘要 / parser / aggregation / 窗口 `days` · `timezone` · `today`）；任一项失配即**忽略该条目并重新解析**（无损重算，不删除文件）。缓存文件删除只发生在源文件从源路径集合中消失时（按各自 manifest 差集清理，计入 `cache_deletions`）。版本常量升级即令旧条目全部失配：Kimi 层配 `PARSER_VERSION = 2` / `AGGREGATION_VERSION = 2`（v2 引入自然月 × 模型聚合 `modelMonths`，旧条目按版本不匹配全量重建一次）。

### 7.2 IPC 错误与降级
- 遇到个别日志行损坏或 JSON 截断：递增 `ScanStats.malformed_lines` 并平滑跳过，绝不中断整次采集；
- 遇到权限不足或外部 SQLite 独占锁冲突：产出 `ScanStats.conflict_session_groups` 诊断，保障其他正常源完整出库。
