## 1. 简介 (Introduction)

本方案定义 `Bruce` 的订阅额度监控（Subscription Quota）及应用内安全凭据管理体系。

- **业务动因**：与本地日志采集离线统计不同，各大大模型服务商（Anthropic Claude, OpenAI Codex, Kimi, 火山引擎, 智谱 GLM, DeepSeek, Grok, OpenCode Go 等）提供了基于云端实时计费窗口的订阅套餐（例如 Claude 的 5 小时滑动窗口、Codex 的 5 小时/周度周期、Kimi 编程套餐等）。开发者需要实时知晓各 Provider 的额度剩余百分比、重置倒计时与当前使用速率，以便合理调度编码任务。
- **系统定位**：位于 `apps/macos/Sources/BruceOnboardingCore/` 与 `core/collector/crates/collector-provider/`，构建端到端的安全凭据存储、外部 CLI 登录态无感探测与云端出站额度查询闭环。

---

## 2. 目标与非目标 (Goals & Non-Goals)

### 2.1 目标 (Goals)
1. **10 家 Provider 额度统一纳管**：覆盖 Kimi, DeepSeek, 火山引擎, 智谱 GLM, Codex, Claude, Grok, OpenCode Go, StepFun, Cline/ClinePass（Jev 适配保留但于 UI 屏蔽）；
2. **零钥匙串弹窗骚扰 (Zero-Prompt Security)**：构建基于 POSIX `0600` 的本地原子凭据持久化存储（`credentials.json`），根治 Ad-hoc 本地构建因签名变动触发的系统 SecurityAgent 密码弹窗；
3. **外部 CLI 静默只读探测**：探测 Claude CLI 等外部第三方凭据时，强制附加 `kSecUseAuthenticationUISkip`，遇到鉴权未就绪静默跳过并降级至本地文件；
4. **凭据安全隔离与脱敏**：凭据仅在运行时通过 Bridge stdin 传输，绝不进入命令行参数、日志或公开工件；UI 交互统一采用 `前4...后4` 脱敏遮罩。

### 2.2 非目标 (Non-Goals)
1. **不伪造或截获第三方 OAuth Client Secret**：Codex 登录通过 OpenAI 官方设备授权码（Device Flow）轮询，不硬编码任何泄漏密钥；
2. **不回写或篡改外部凭据**：外部 CLI 配置文件（如 `~/.claude/.credentials.json`、`~/.grok/auth.json`）仅作只读嗅探，绝不反向回写或清理；
3. **不代理第三方账号登录页面**：实际账号密码仅在服务商官方浏览器页面或官方 CLI 终端输入，App 内仅做状态轮询与结果接收。
4. **不读取 Cline 官方客户端 OAuth 账号令牌**：Cline 额度纳管仅接受用户手动粘贴的 Cline API Key（Bearer 直连 `api.cline.bot/api/v1`），不引入 VS Code secrets / 系统钥匙串等新增凭据读取面。
5. **不硬编码 ClinePass 限额阈值**：5h/7d/30d 三窗口限额一律从 `/users/me/plan` 的 `entitlements` 动态读取，代码内不得写入 `$10/$25/$50` 等常量（账户级计划如 `[Internal]` 与公开计划阈值可能不同）。

## 3. 需求分析 (Requirements)

### 3.1 功能需求清单
- **FR-1 凭据安全存取**：提供增、删、改、查 API Key、Access Key/Secret Key、Session Cookie 与 OAuth Token 的安全接口；
- **FR-2 Provider 状态研判**：支持 `未配置 (Unconfigured)`、`有效 (Valid)`、`已过期 (Expired)`、`需重新授权 (NeedsReauthorization)` 等状态转换；
- **FR-3 额度标准化输出**：将各厂商完全不同的 JSON 响应统一归一化为标准化模型：已用量、总限额、剩余百分比、重置时间戳（ISO 8601）与滑动窗口描述；
- **FR-4 凭据一键导入与发现**：自动发现本机 CC Switch 数据库与各 Agent CLI 的本地登录态，支持用户一键安全导入。

### 3.2 非功能需求 (NFR)
- **文件权限底线**：凭据存储文件强制要求权限为 `0600`（所有者读写，其他用户 0 权限），父目录为 `0700`；
- **原子替换写入**：采用临时文件生成 + `replaceItemAt` 原子替换，防止写入中断导致凭据文件损坏；
- **防锁死保护**：云端额度出站查询超时严格限制为 5 秒，单 Provider 失败不阻塞其他 Provider。

## 5. 总体设计 (High-Level Architecture)

```mermaid
graph TD
    UI[设置中心 / Onboarding 向导] --> Coordinator[CredentialUpdateCoordinator]
    Probe[LocalCredentialProbe] --> ExtReader[SystemExternalCredentialReader]
    ExtReader -- kSecUseAuthenticationUISkip --> Keychain[系统钥匙串 (只读跳过UI)]
    ExtReader -- 只读嗅探 --> LocalAuthFiles[~/.claude, ~/.grok, CC Switch]
    
    Coordinator --> Store[ProtectedFileCredentialStore]
    Store -- POSIX 0600 原子写入 --> CredFile["~/Library/Application Support/Bruce/credentials.json"]
    
    AppModel[AppModel 调度器] --> Store
    Store --> BridgeReq[BridgeRequest Credentials]
    BridgeReq -- Stdio stdin --> RustCollector[Rust Collector-Provider]
    RustCollector -- HTTPS --> Providers[云端 Provider APIs]
```

#### 现行设计规则

##### 1. POSIX 0600 本地凭据存储规范
凭据存储位于用户 Application Support 专用沙箱：
- **目标路径**：`~/Library/Application Support/Bruce/credentials.json`；
- **目录权限**：`0700` (`rwx------`)；
- **文件权限**：`0600` (`rw-------`)；
- **防损坏写入流程**：
  1. 编码 JSON 数据到内存缓冲区；
  2. 写入同目录下的临时文件 `credentials.json.tmp.<UUID>`，并立即调用 `fchmod(fd, 0600)`；
  3. 执行 `FileManager.replaceItemAt` 原子置换原文件；
  4. 清理旧临时文件。

##### 2. 外部 CLI 探测防弹窗策略 (`kSecUseAuthenticationUISkip`)
在探测 Claude Code CLI 本机登录态时，系统通过 `SystemExternalCredentialReader` 执行只读查询（C059 修订读取序）：
```swift
var query: [String: Any] = [
    kSecClass as String: kSecClassGenericPassword,
    kSecAttrService as String: "Claude Code-credentials",
    kSecReturnData as String: true,
    kSecMatchLimit as String: kSecMatchLimitOne,
]
let context = LAContext()
context.interactionNotAllowed = true
query[kSecUseAuthenticationContext as String] = context
query[kSecUseAuthenticationUI as String] = kSecUseAuthenticationUISkip
```
- **Claude 登录态读取序 (C059/C060, 对照 cc-switch)**：①外部 Keychain 项**无条件静默尝试**（C060 起不再受 `externalSources` 白名单/`state` 门禁；被锁定/ACL 拦截时仅返回 nil 降级、**不 markBlocked**，不污染 Bruce 自有存储策略，任何意图都不上抛、绝不唤起 SecurityAgent 弹窗）；②`~/.claude/.credentials.json` 家目录凭证文件回退（只读用户自己的文件，不经钥匙串授权仪式门禁）。探测把 `valid/refreshPending/expired` 均计为「检测到登录态」（过期也照常试一把查询，实查 401 才落 needsRelogin）；collector 装配层的零配置回退 (`externalOAuthAccount`) 同序同门禁。
- **凭据规范化 (C060)**：`ClaudePasteParser` 完整保留原 OAuth 条目全部字段（`refreshTokenExpiresAt` / `subscriptionType` / `rateLimitTier` / `scopes` 等），仅规范化包装键与 accessToken —— 与 cc-switch 保留原始凭证一致，refreshPending 判定可依据刷新令牌到期时间。
- 设置区提供显式「从本机导入」（读取即入库验证）作为账号信息的可核验入口；「重新验证」仅在存在已存账号时出现。Keychain 被系统拦截且两路皆无登录态时，导入提示需先登录 CLI 或改用粘贴；Grok 维持 `externalSources` 白名单前置门禁的文件单源行为。

##### 3. Bridge 凭据注入与字段白名单
Rust Collector 边界建立严格的白名单校验（`ALLOWED_CREDENTIAL_FIELDS`）：
- 仅允许经协议批准的凭据字段（如 `kimiQuotaAccounts`, `claudeQuotaAccounts`, `codexQuotaAccounts` 等）通过 stdin 注入；
- 未登记字段一律在 Bridge 校验阶段直接拒绝并报警；
- 采集完成后，Rust 进程内内存即刻覆盖清空，响应 stdout 中仅返回脱敏后的额度指标，严禁包含任何 Token 明文。

##### 4. 余额型订阅双槽对称展示规范 (方案 B)
针对以账户余额计费的 Provider（如 DeepSeek，无周期重置窗口，仅有可用金额）：

##### 5. Cline / ClinePass 三窗口订阅计量与展示规范
针对 Cline 包月订阅（ClinePass，$9.99/月）的额度纳管：

- **数据源（C039 定稿：服务端权威直读）**：`GET /api/v1/users/me/plan`（ClinePass 门槛 + 计划名）+ `GET /api/v1/users/me/plan/usage-limits`（三窗口数值），恒定 2 次 Bearer GET（实测约 1.4s，远低于 `moduleSeconds=90`）。usage-limits 是**网页控制台 USAGE LIMITS 的同源数据端点**（扫描 app.cline.bot 前端 bundle 发现；Bearer API key 直连 200），响应真实形态：
  `{data:{limits:[{type:"five_hour"|"weekly"|"monthly", percentUsed:<整数>, resetsAt:<RFC3339 9位纳秒>}]}, success:true}`；
  `percentUsed` 与 `resetsAt` 由服务端算好返回，与网页逐字一致，映射进既有窗口契约（label/windowMinutes/resetsAt），渲染层零改动。`reset_epoch`（chrono rfc3339）原生解析纳秒小数。
- **服务端窗口语义（备查，仅作理解，严禁据此在客户端复刻建模）**：5h 为「上一块到期后首单开块 `[t, t+5h)`」的活动块（纳秒级实证：resetsAt `05:51:46.262166334Z` − 5h = 台账 `00:51:46.262166Z` 那一单）；weekly/monthly 为「窗口内最早一单 + 7d/30d」的滚动窗口。Cline 调整口径时 Bruce 自动跟随。
- **红线（C039 起）**：**严禁在客户端复刻服务端窗口建模**（翻页聚合/槽网格/滚动窗口推算一律不再引入）。历史教训：台账翻页上限截断（C025 前 500 单 → 7d/30d 欠计约 40%；2400 单上限在本机 3319 单时再次偏差 30%）；纪元网格固定槽模型被两天跨边界对账证伪（C025 被 06:00Z 巧合落网误导，单日单点对账会把巧合当规律）；客户端建模永远差一个未观测边界态，直读权威端点让这类缺陷失去存在条件。
- **无状态与故障恢复**：端点失败（网络/5xx/形状变更）→ 显式报错（`status=error` + 查询失败注记），保留上次 artifact，**不得静默渲染陈旧或空窗口**（fail-visible）；恢复后下一轮刷新即精确，无任何需修复/回填的本地状态。C038 的增量台账缓存（`LedgerCache` 端口 + `FileLedgerCache`）随本卡回收（git 历史保留）；`GET /users/{id}/usages`（逐单台账，`nextToken` 游标分页，单页硬上限 200，不支持时间过滤）与 `GET /users/{id}/usages/daily?startdate=&enddate=`（按天聚合，参数必填）备案为「usage-limits 端点若对 API key 关闭」时的既定回退路径（届时按 C038 方案恢复台账管线），也供将来 Cline 模型级用量明细特性使用。
- **分母（限额，仅作门槛）**：`GET /api/v1/users/me/plan` → `data.plan.entitlements.cline_pass.inferenceCapThreshold.{last5Hours/last7days/last30daysUsageCostUSDPerUser}`（单位 1e-8 USD，实测个人档 $10 / $25 / $50）。C039 起百分比直读服务端，该字段仅用于 ClinePass 账户门槛判定（存在、未停用、三阈值均为正），**仍严禁硬编码阈值**；
- **展示规范**：三窗口订阅流（5h / 7d / 30d 三层进度条，各自百分比与倒计时，倒计时取服务端 `resetsAt`），由既有双窗口订阅模式（Codex）扩展为三层；plan 状态徽标展示 生效中 / 已取消（到期日） / 周期区间（`currentPeriodStart~End`）；
- **降级与容错**：`entitlements.cline_pass` 缺失或 `enabled=false`（非 Pass 账户）→ 返回空态（`status=empty` + “未取到额度数据”），不渲染三窗口（绝对值展示留待后续评估）；401/403 → `needsReauthorization`；429 → `rateLimited` 并拉长重试；**不注入订阅生命周期注记**（C020 起：`canceledAt`/`cancelAt` 一律不在卡片展示，卡片仅呈现计划名与三窗口）；
- **凭据边界**：仅接受用户在设置中心粘贴的 Cline API Key（`cline:api-key`，Bearer 直连），不读取 Cline 官方客户端 OAuth 令牌（详见 2.2 非目标第 4 条）。

##### 6. 订阅 Provider 列表管理门禁规范
订阅额度设置中心的 Provider 行管理遵循以下门禁规则（统一事实源：`SubscriptionPresentationPolicy.showsProviderRemoval`）：

- **移除入口门禁**：只要 Provider 已添加进列表（配置条目 `subscriptionProviders[id]` 存在）即可移除，**凭证是否已保存不作为移除前提**；凭证存在而列表无条目时同样允许移除（防御性清理）；两者皆无才隐藏入口；
- **重新验证门禁**：仅当凭证已保存（`subscriptionCredentialConfigured[id]`）时提供「重新验证」，其语义依赖已存凭证，不得因本次放宽移除门禁而一并放宽；
- **半添加状态可退出**：添加后未保存凭证的行必须保留合法退出通道（移除），严禁出现「启用开关随未配置禁用 + 无移除入口」的死锁态（C019 缺陷回归红线）；
- **后端契约**：移除流程先删凭证再清配置条目；Keychain 删除对不存在项返回 `errSecItemNotFound` 且视为成功，无凭证场景无需特殊分支。

##### 7. 订阅变更与仪表盘联动规范
订阅配置的变更与仪表盘展示按以下规则联动（C020 起）：

- **即时生效**：用户在设置中心保存凭证并通过验证（`verificationStatus == .ok`）后，立即请求该 Provider 的定向刷新（`scheduler.refreshSubscription`），无需等待下一次定时刷新或手动刷新即可出现在仪表盘；验证失败 / 需重新登录 / 未验证一律不触发刷新；
- **仅展示验证通过项**：仪表盘订阅段只渲染验证状态为 `ok` 的 Provider 服务；`none`（已添加未配置的半添加态）/ `failed` / `needsRelogin` 的服务一律不进入订阅段（门禁判定以纯函数 `SubscriptionPresentationPolicy.isVerifiedForDashboard` 收纳，过滤发生在 AppModel 组装面板 VM 前的服务层；Agent 用量卡不受该门禁影响）；
- **缓存联动**：订阅配置发布（`setSubscriptionProviders`）必须失效面板缓存，确保验证状态变化即时反映到下一次面板渲染；
- **套餐名展示位置 (C024)**：订阅套餐名（Codex `plus`、智谱 `lite`、Cline `Cline Pass (Monthly)` 等）**不在仪表盘展示**（标头胶囊、多账号行、双槽右槽一律不呈现），统一在设置中心「订阅额度」的 Provider 行内以标签呈现，数据取最近一次采集 artifact 的 `service.plan`；
- **Cline 生命周期注记**：订阅卡不展示 `canceledAt`/`cancelAt` 等订阅生命周期注记，仅呈现额度窗口。

##### 10. 凭据存储的损坏语义与写入校验套件 (C042)

- **读路径三态**：`credentials.json` 不存在 → 空 payload（正常首次使用）；存在但读/解码失败 → **保留损坏现场副本后抛 `ProtectedFileCredentialStoreError.corrupted`**，严禁折叠为空 payload。理由：空 payload 被 `saveCredential` 的整体覆盖写回会抹除其余全部凭据（原实现路径，无备份无回滚）；
- **写路径套件**：`createFile(attributes: 0600)` → write → `synchronize`（fsync）→ **重读解码校验** → 复制上一版为 `.bak` → `replaceItemAt` → `setAttributes 0600` 且失败即抛错。目录存在时也校正为 0700；
- **账号索引同理 (C046)**：`ProviderAccountStore.loadIndex/loadRecord` 解码失败必须抛 `ProviderAccountStoreError`，不得返回空索引/`nil` —— 空索引会被后续 `saveIndex` 覆盖写回，使遗留记录成为不可达孤儿；`removeAllAccounts` 删除失败必须上抛，不得吞错后仍清空索引。

##### 9. 窗口边界刷新与过期窗口展示规范 (C037)

订阅窗口的**刷新时机**与**过期展示**统一如下（mac `RefreshScheduler` + `SubscriptionBoundaryWakePolicy`，Windows `scheduler.rs` + `runtime_core::boundary_wake`，两端同构实现）：

- **边界唤醒**：下次定时唤醒 = min(间隔剩余, 最近一个**未来**窗口重置时刻 + slack)，slack = 20s（边界是预测值，留出刷新耗时）。边界取自 artifact `services[].windows[].resetsAt`（与卡片展示同源），且只在采集成功时参与调度；失败/退避路径保持原语义（退避优先）。
- **防风暴三道防线**：①只认严格在未来的 `resetsAt`（滚动窗口的滑出时刻随刷新前移时天然不触发）；②同一「边界值」只消费一次（按 epoch 秒精确去重，集合随边界过期自动收敛）；③未命中边界、或边界比间隔更远时回落原间隔。**严禁**用无条件 `min(间隔, 边界)` 替代 —— 滚动窗口倒计时恒贴近当前时刻会触发刷新风暴（C025 历史教训）。
- **过期窗口文案**：`resetsAt <= now`（窗口已重置但卡片数据仍属上一窗口、刷新在途）统一显示「**刷新中**」，mac 与 Windows 同文案（`PanelModels.resetText` / `viewmodel::reset_text`）。此前写作「已到期」，与「窗口过期」混淆，观感上像到点不刷新；配合边界唤醒，该中间态通常只持续数十秒。

##### 11. Claude 用量响应解析口径 (C058)

`api.anthropic.com/api/oauth/usage` 响应解析对照 cc-switch（farion1231/cc-switch `services/subscription.rs`，2026-10-18 校准）统一口径：

- **顶层旧版窗口**（`five_hour` / `seven_day` / `seven_day_fable` / `seven_day_opus` / `seven_day_sonnet` 及未知键）：取 `utilization`（百分比）与 `resets_at`（ISO 字符串）；`utilization` 缺失或非数值的窗口**逐条跳过**，严禁让单条脏数据把整卡打成解析失败；
- **`limits[]` 模型专属周限额**：仅收 `kind=weekly_scoped` + `group=weekly` 且 `scope.surface` 为空的行，模型归一自 `scope.model.display_name`（trim + 小写 → fable/opus/sonnet 三档，其余跳过）；取 `percent`（须为非负 JSON 数值）与 `resets_at`（仅字符串或 null）。**与 Claude Code 一致不按 `is_active` 过滤**（0% / null 重置时间也可能是有效额度）；同名档位**首条优先去重**并**覆盖同名旧版顶层窗口**；行内任一字段形态非法则整行跳过（跳过判定先于去重插入，防止废行占掉首条名额）；
- **输出排序**：按已知档位序（five_hour → seven_day → fable → opus → sonnet），未知窗口稳定排后；`extra_usage`（`is_enabled=true` 且 `utilization` 为数值时）独立成行追加末尾；
- **展示标签**：模型专属周窗口 collector 标签为「每周 Fable / 每周 Opus / 每周 Sonnet」；双端 `windowLabel`/`window_label` 的 windowMinutes 优先归一中，**带空格后缀的「每周 X」形态原样保留**（避免总量 + 三模型多行被归一成同一文案），无后缀形态（「每周窗口」/裸「每周」）仍归一为「每周」。

##### 12. 订阅额度查询周期联动与 429 冷却 (C062, C065)

本地采集周期与订阅额度查询周期保持联动，用户在设置中心选择的刷新间隔（5/15/30/60 分钟，C125 按实现 `allowedRefreshIntervalMinutes` / `REFRESH_PRESETS` 更正，原 5/10/15/30/60 为文档漂移）同时决定本地采集与云端额度查询周期，解除原硬编码 30 分钟门禁：

- **额度周期**：C065 起，用户「刷新间隔」同时决定本地会话扫描周期与订阅额度查询周期（`quotaRefreshInterval` 与 `refreshInterval` 联动更新）。service 在 artifact 中携带 `quotaAttemptedAt`（本轮真实查询时间）与 `rateLimitedAt`（429 时间）；距 `quotaAttemptedAt` 不足用户配置周期的 provider 跳过外部查询（避免同一周期内频繁重复查询）。全部 provider 均未到期时执行 `localUsageOnly` run：collector 返回空 `services`，不输出 denied 占位、不产生 `COLLECTOR_PARTIAL_RESULT`（C124 起未授予 `externalQuotas` —— 无订阅凭证或未同意授权 —— 同样返回空 `services`，纯本机统计的 envelope 为 success；两端映射层对旧 artifact 中的占位形状仍跳过不渲染）；App 用 `QuotaCarryOverMerger` 回填旧 services。
- **429 冷却**：当 Provider 遭遇真实 HTTP 429 限流时，依然进入 30 分钟冷却期保护，冷却期内自动 run 不再请求该 provider。查询失败（含 429）且旧数据合格时，复制旧 `windows`/`plan`/`extra`/`kind`/`capturedAt` 并标 `freshness=stale`，不得清空上次窗口；查询成功（`ok`/`empty`）清除 `rateLimitedAt`。
- **限流与 provider 判定（C118）**：collector 为每条 service 显式下发 `provider`（`SubscriptionProviderID` rawValue，经 `subscription_provider_id(app)` 归一，如 `opencode-go` → `opencodeGo`）与 `failureKind`（成功为 `null`；失败按诊断码由 `failure_kind_for_code` 归类为 `auth` / `permission` / `rateLimit` / `server` / `invalidResponse` / `credential` / `network`，Codex 与其余 provider 同表）。两端的 `rateLimitedAt` 记账与本轮限流集合只认 `failureKind == "rateLimit"`，provider 归属只认 `provider`；仅当字段**缺省**（C118 前落盘的旧 artifact）时才回退按 service id 前缀推断与匹配 note 限流文案（429 / 限流 / RATE_LIMIT），显式 `null` 视为未限流。note 只承担展示，不再承担判定语义。
- **按启用集合判定与双端对拍（C120）**：门禁逐个判定**本轮启用**的 provider（mac 取 `subscriptionProviders[id].enabled == true`，与凭证装配同一判据；Windows 取 `enabled_providers`），而非上一份 artifact 中出现的 provider：启用但无历史 service 的（新启用 / 首次采集）必须首查；已停用 provider 的残留 service 不参与判定；无任何启用 provider 时不发起额度查询；全部新鲜时 `skipProviders` = 全部启用 provider。尝试时间 `quotaAttemptedAt` → `capturedAt` → 失败（`error` / `partial` / `unavailable`）回退 `rateLimitedAt`。双端判定以 `tests/fixtures/quota-policy-parity/cases.json` 共享用例对拍（mac RefreshSchedulerHarness / Windows `quota_policy_coverage`），任一端改动门禁须先改 fixture。已知限制：启用但 collector 不返回任何 service 的 provider（凭证在采集前丢失）会在每轮被判为到期，双端相同。
- **强制查询**：手动全量刷新与单 Provider 定向刷新强制查询并绕过 429 冷却；窗口边界唤醒强制查询但尊重 429 冷却。此外，若上次快照中的某个 `resetsAt` 已过去（说明数据属于上一窗口），即使未满配置周期也在下一次本地 run 强制重查，保证 C037 的边界刷新不被额度门禁降级。
- **Codex 例外**：Codex 永不进入 `skipProviders`，其四源合并/定向重试需要完整首轮结果；Codex 是否查询仍由 freshness 决定。
- **启动/激活去重**：模块 `running` 或距上次尝试不足 60 秒时，`wake`/`didBecomeActive` 直接跳过，禁止首轮 run 与激活补偿形成 4 秒内两次全量请求。

##### 13. Claude OAuth 自动续期与凭据轮换写回 (C063)

对齐 Claude Code CLI (cc 2.1.302) 与 cc-switch 官方 OAuth 刷新协议，实现静默无感自动续期：

- **官方刷新端点与凭据要素**：
  - 端点：`POST https://api.anthropic.com/v1/oauth/token`；
  - 授权体：`grant_type=refresh_token`、`client_id=9d1c250a-e61b-44d9-88ed-5944d1962f5e`、`refresh_token=<token>`，User-Agent 声明 `claude-code/2.1.302`；
  - 动态刷新触发条件：若 `expires_at_epoch_ms` 到期时间剩余 $\le 60\text{s}$ 或 API 请求遭遇 401 鉴权拒绝，且存在有效 `refresh_token`，主动请求端点换取新 access_token 与轮换后的 refresh_token；
  - 401 自愈：换取成功后立即使用全新 access_token 重试 usage 查询；
- **凭据写回与隔离存储持久化**：
  - Collector 返回的 payload 中附加 `credential_update`（包含 `access_token`、`refresh_token` 与 `expiry`）；
  - `collector-credential` 增加 `claude` 字段白名单校验；
  - Swift 宿主由 `CredentialRotationMerge` 将新令牌安全合并写入 `claudeAiOauth` 与 `claude.ai_oauth` 内部嵌套字典中，转换 `expiry`（秒）为 `expiresAt`（毫秒）；
  - 对于零配置（`claude-cli`）账号，`CredentialUpdateCoordinator` 自动建立并更新至 `ProviderAccountStore`（POSIX `0600`，`~/Library/Application Support/Bruce/credentials.json`），保证新 token 持久化且不触发 macOS 钥匙串安全弹窗。
- **测试与安全红线**：
  - 所有单元测试与 Harness 必须使用 `FixtureHttp` 内存 Mock 或沙箱临时文件，严禁发起真实的 `claude.ai` / `api.anthropic.com` 外网连接，严禁使用用户本地真实 CLI 凭据测试。

## 7. 扩展设计 (Additional Technical Design)

### 7.1 外部 SQLite 数据库只读防御
对于从 CC Switch（`~/.cc-switch/cc-switch.db`）导入多账号的场景：
- 连接串严格限定：`file://.../cc-switch.db?mode=ro&immutable=1`；
- 严禁向外部数据库执行 `CREATE`, `INSERT`, `UPDATE`, `VACUUM` 或 `PRAGMA` 写入指令；
- 若检测到外部数据库锁冲突，立即记录诊断并跳过，绝不阻塞 UI 线程。

### 7.2 异常流与容灾
- **Provider API 速率受限 (429 HTTP)**：返回降级指标并携带 `rateLimited = true`；C062 起按 provider 进入 30 分钟冷却（`rateLimitedAt`），partial 路径同样遵守，冷却期内自动 run 不再查询该 provider。失败时保留上次窗口并标 `freshness=stale`，不把卡片清空；无 artifact 的 error 路径仍按 `rateLimitBackoffSeconds`（300 秒）退避；
- **Provider 凭据失效 (401/403 HTTP)**：标记对应 Provider 状态为 `needsReauthorization`，在 UI 面板高亮提示用户重新录入，不影响其他 Provider 正常刷新；
- **本机断网（C061）**：所有订阅共用 `agentUsage` 刷新链路，调度器以 `NWPathMonitor` 可达性为统一闸门。无网络时定时刷新、唤醒补偿与退避重试一律不启动 Collector、不排任何重试，保留上次 artifact 并展示「网络不可用, 已暂停自动刷新」；手动刷新（含单 Provider 定向刷新）仍可执行一次，但失败后同样不进入自动重试。网络恢复后，对离线期间被抑制或已陈旧的模块补偿一次刷新，成功后恢复正常间隔调度，避免断网期间积压的重试在恢复瞬间形成请求风暴、叠加触发 Provider 限流。
- **电脑锁屏订阅抑制（C064）**：在设置中心新增「锁屏暂停订阅刷新」开关（持久化至 `OnboardingConfiguration.pauseSubscriptionRefreshOnScreenLock`，默认开启）。当开关开启且系统处于锁屏状态（通过 `DistributedNotificationCenter` 的 `com.apple.screenIsLocked` / `com.apple.screenIsUnlocked` 及 `CGSessionCopyCurrentDictionary` 实时判定）时，定时刷新自动降级为纯本地扫描（`localUsageOnly`，`includeExternalQuotas=false`），杜绝人不在电脑前时的无意义云端订阅配额消耗与 429 风险；当屏幕解锁后，若订阅额度已陈旧或已到期，立即补偿触发一次全量刷新，实现无缝衔接。锁屏抑制运行本身**必须原样回填上一份 services**（C071：`suppressExternalQuotas` 分支返回的本地专用策略携带 `skipProviders` = 上一份 artifact 的全部 provider，与「全部 provider 仍新鲜」路径同构），仅按新鲜期标注 `fresh`/`stale`——否则抑制运行会发布零 `services` 的 artifact，仪表盘订阅卡在解锁后被清空且因发布时间戳刷新而无法立即补偿，只能手动刷新恢复。
