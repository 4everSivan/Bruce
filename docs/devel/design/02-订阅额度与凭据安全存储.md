## 1. 简介 (Introduction)

本方案定义 `Bruce` 的订阅额度监控（Subscription Quota）及应用内安全凭据管理体系。

- **业务动因**：与本地日志采集离线统计不同，各大大模型服务商（Anthropic Claude, OpenAI Codex, Kimi, 火山引擎, 智谱 GLM, DeepSeek, Grok, OpenCode Go 等）提供了基于云端实时计费窗口的订阅套餐（例如 Claude 的 5 小时滑动窗口、Codex 的 5 小时/周度周期、Kimi 编程套餐等）。开发者需要实时知晓各 Provider 的额度剩余百分比、重置倒计时与当前使用速率，以便合理调度编码任务。
- **系统定位**：位于 `apps/macos/Sources/BruceOnboardingCore/` 与 `core/collector/crates/collector-provider/`，构建端到端的安全凭据存储、外部 CLI 登录态无感探测与云端出站额度查询闭环。

---

## 2. 目标与非目标 (Goals & Non-Goals)

### 2.1 目标 (Goals)
1. **11 大 Provider 额度统一纳管**：覆盖 Kimi, DeepSeek, 火山引擎, 智谱 GLM, Codex, Claude, Grok, OpenCode Go, StepFun, Jev, Cline/ClinePass；
2. **零钥匙串弹窗骚扰 (Zero-Prompt Security)**：构建基于 POSIX `0600` 的本地原子凭据持久化存储（`credentials.json`），根治 Ad-hoc 本地构建因签名变动触发的系统 SecurityAgent 密码弹窗；
3. **外部 CLI 静默只读探测**：探测 Claude CLI 等外部第三方凭据时，强制附加 `kSecUseAuthenticationUISkip`，遇到鉴权未就绪静默跳过并降级至本地文件；
4. **凭据安全隔离与脱敏**：凭据仅在运行时通过 Bridge stdin 传输，绝不进入命令行参数、日志或公开工件；UI 交互统一采用 `前4...后4` 脱敏遮罩。

### 2.2 非目标 (Non-Goals)
1. **不伪造或截获第三方 OAuth Client Secret**：Codex 登录通过 OpenAI 官方设备授权码（Device Flow）轮询，不硬编码任何泄漏密钥；
2. **不回写或篡改外部凭据**：外部 CLI 配置文件（如 `~/.claude/.credentials.json`、`~/.grok/auth.json`）仅作只读嗅探，绝不反向回写或清理；
3. **不代理第三方账号登录页面**：实际账号密码仅在服务商官方浏览器页面或官方 CLI 终端输入，App 内仅做状态轮询与结果接收。
4. **不读取 Cline 官方客户端 OAuth 账号令牌**：Cline 额度纳管仅接受用户手动粘贴的 Cline API Key（Bearer 直连 `api.cline.bot/api/v1`），不引入 VS Code secrets / 系统钥匙串等新增凭据读取面。
5. **不硬编码 ClinePass 限额阈值**：5h/7d/30d 三窗口限额一律从 `/users/me/plan` 的 `entitlements` 动态读取，代码内不得写入 `$10/$25/$50` 等常量（账户级计划如 `[Internal]` 与公开计划阈值可能不同）。

## 3. 需求分析 (Requirements)

### 3.1 功能需求清单
- **FR-1 凭据安全存取**：提供增、删、改、查 API Key、Access Key/Secret Key、Session Cookie 与 OAuth Token 的安全接口；
- **FR-2 Provider 状态研判**：支持 `未配置 (Unconfigured)`、`有效 (Valid)`、`已过期 (Expired)`、`需重新授权 (NeedsReauthorization)` 等状态转换；
- **FR-3 额度标准化输出**：将各厂商完全不同的 JSON 响应统一归一化为标准化模型：已用量、总限额、剩余百分比、重置时间戳（ISO 8601）与滑动窗口描述；
- **FR-4 凭据一键导入与发现**：自动发现本机 CC Switch 数据库与各 Agent CLI 的本地登录态，支持用户一键安全导入。

### 3.2 非功能需求 (NFR)
- **文件权限底线**：凭据存储文件强制要求权限为 `0600`（所有者读写，其他用户 0 权限），父目录为 `0700`；
- **原子替换写入**：采用临时文件生成 + `replaceItemAt` 原子替换，防止写入中断导致凭据文件损坏；
- **防锁死保护**：云端额度出站查询超时严格限制为 5 秒，单 Provider 失败不阻塞其他 Provider。

#### 现行设计规则

##### 1. POSIX 0600 本地凭据存储规范
凭据存储位于用户 Application Support 专用沙箱：
- **目标路径**：`~/Library/Application Support/Bruce/credentials.json`；
- **目录权限**：`0700` (`rwx------`)；
- **文件权限**：`0600` (`rw-------`)；
- **防损坏写入流程**：
  1. 编码 JSON 数据到内存缓冲区；
  2. 写入同目录下的临时文件 `credentials.json.tmp.<UUID>`，并立即调用 `fchmod(fd, 0600)`；
  3. 执行 `FileManager.replaceItemAt` 原子置换原文件；
  4. 清理旧临时文件。

##### 2. 外部 CLI 探测防弹窗策略 (`kSecUseAuthenticationUISkip`)
在探测 Claude Code CLI 本机登录态时，系统通过 `SystemExternalCredentialReader` 执行只读查询：
```swift
var query: [String: Any] = [
    kSecClass as String: kSecClassGenericPassword,
    kSecAttrService as String: "Claude Code-credentials",
    kSecReturnData as String: true,
    kSecMatchLimit as String: kSecMatchLimitOne,
]
let context = LAContext()
context.interactionNotAllowed = true
query[kSecUseAuthenticationContext as String] = context
query[kSecUseAuthenticationUI as String] = kSecUseAuthenticationUISkip
```
- 当 Keychain 处于锁定态或需要用户输入系统密码时，立即返回 `errSecInteractionNotAllowed`；
- 读取器捕获该状态后静默标记 `accessController.markBlocked()`，直接返回 `nil` 并静默降级为读取 `~/.claude/.credentials.json` 本地明文文件，绝不唤起 SecurityAgent 系统弹窗。

##### 3. Bridge 凭据注入与字段白名单
Rust Collector 边界建立严格的白名单校验（`ALLOWED_CREDENTIAL_FIELDS`）：
- 仅允许经协议批准的凭据字段（如 `kimiQuotaAccounts`, `claudeQuotaAccounts`, `codexQuotaAccounts` 等）通过 stdin 注入；
- 未登记字段一律在 Bridge 校验阶段直接拒绝并报警；
- 采集完成后，Rust 进程内内存即刻覆盖清空，响应 stdout 中仅返回脱敏后的额度指标，严禁包含任何 Token 明文。

##### 4. 余额型订阅双槽对称展示规范 (方案 B)
针对以账户余额计费的 Provider（如 DeepSeek，无周期重置窗口，仅有可用金额）：
- **标头去冗余**：标头移出 `BalanceChip`，仅保留品牌 Logo、服务名与尾部定向刷新按钮，消除头部拥挤；
- **正文双槽对称流 (`BalanceDualSlotView`)**：
  - **左槽（资产槽）**：固定显示微标「可用余额」+ 大号等宽粗体数值（如 `¥ 38.21`）；
  - **右槽（状态槽）**：显示「订阅状态」+ 圆点指示器与状态文案（「正常」或接口返回状态）；套餐名自 C024 起不再进入仪表盘（见规则 7）；
  - **主题自适应**：Classic/LiquidGlass 下采用平滑圆角微透磨砂槽；Nothing 主题下采用 3pt 方角、透明底加强边框与 Space Mono 字体；
- **Jev 暂时屏蔽**：因 TypeSafe 官方当前未开放免计费查余额公开 API，在 `SettingsView` 与 `SubscriptionPresentationPolicy` 中暂时隐藏 Jev 显示，底层已实现的解析器与数据契约 100% 保留。

##### 5. Cline / ClinePass 三窗口订阅计量与展示规范
针对 Cline 包月订阅（ClinePass，$9.99/月，限额采用滚动窗口而非日历周期）的额度纳管：

- **分子（已用量）**：`GET /api/v1/users/{id}/usages` 逐单台账（`nextToken` 游标分页，`total` 字段不可信恒为 0，必须按游标翻页），每单含 `aiModelName` / `promptTokens` / `completionTokens` / `cachedTokens` / `costUsd` / `createdAt`；按各滚动窗口对 `costUsd` 求和（单位 1e-8 USD，即 `× 1e-8` 折算美元）得窗口已用量；
- **分母（限额）**：`GET /api/v1/users/me/plan` → `data.plan.entitlements.cline_pass.inferenceCapThreshold.{last5HoursUsageCostUSDPerUser, last7daysUsageCostUSDPerUser, last30daysUsageCostUSDPerUser}`（单位同为 1e-8 USD，实测个人档 $10 / $25 / $50）；**严禁硬编码阈值**，一律以响应为准；
- **窗口语义**：采用 API 滚动语义（5h 滚动 / 近 7 天 / 近 30 天），与官方文档“日历周 / 日历月”表述不一致处以 API 为准；窗口倒计时 = 窗口内最早一单时间 + 窗口长度（即“下一单滑出时刻”），无台账时不展示倒计时；
- **展示规范**：三窗口订阅流（5h / 7d / 30d 三层进度条，各自百分比与滑出倒计时），由既有双窗口订阅模式（Codex）扩展为三层；plan 状态徽标展示 生效中 / 已取消（到期日） / 周期区间（`currentPeriodStart~End`）；
- **降级与容错**：`entitlements.cline_pass` 缺失或 `enabled=false`（非 Pass 账户）→ 返回空态（`status=empty` + “未取到额度数据”），不渲染三窗口（绝对值展示留待后续评估）；401/403 → `needsReauthorization`；429 → `rateLimited` 并拉长重试；**不注入订阅生命周期注记**（C020 起：`canceledAt`/`cancelAt` 一律不在卡片展示，卡片仅呈现计划名与三窗口）；
- **凭据边界**：仅接受用户在设置中心粘贴的 Cline API Key（`cline:api-key`，Bearer 直连），不读取 Cline 官方客户端 OAuth 令牌（详见 2.2 非目标第 4 条）。

##### 6. 订阅 Provider 列表管理门禁规范
订阅额度设置中心的 Provider 行管理遵循以下门禁规则（统一事实源：`SubscriptionPresentationPolicy.showsProviderRemoval`）：

- **移除入口门禁**：只要 Provider 已添加进列表（配置条目 `subscriptionProviders[id]` 存在）即可移除，**凭证是否已保存不作为移除前提**；凭证存在而列表无条目时同样允许移除（防御性清理）；两者皆无才隐藏入口；
- **重新验证门禁**：仅当凭证已保存（`subscriptionCredentialConfigured[id]`）时提供「重新验证」，其语义依赖已存凭证，不得因本次放宽移除门禁而一并放宽；
- **半添加状态可退出**：添加后未保存凭证的行必须保留合法退出通道（移除），严禁出现「启用开关随未配置禁用 + 无移除入口」的死锁态（C019 缺陷回归红线）；
- **后端契约**：移除流程先删凭证再清配置条目；Keychain 删除对不存在项返回 `errSecItemNotFound` 且视为成功，无凭证场景无需特殊分支。

##### 7. 订阅变更与仪表盘联动规范
订阅配置的变更与仪表盘展示按以下规则联动（C020 起）：

- **即时生效**：用户在设置中心保存凭证并通过验证（`verificationStatus == .ok`）后，立即请求该 Provider 的定向刷新（`scheduler.refreshSubscription`），无需等待下一次定时刷新或手动刷新即可出现在仪表盘；验证失败 / 需重新登录 / 未验证一律不触发刷新；
- **仅展示验证通过项**：仪表盘订阅段只渲染验证状态为 `ok` 的 Provider 服务；`none`（已添加未配置的半添加态）/ `failed` / `needsRelogin` 的服务一律不进入订阅段（门禁判定以纯函数 `SubscriptionPresentationPolicy.isVerifiedForDashboard` 收纳，过滤发生在 AppModel 组装面板 VM 前的服务层；Agent 用量卡不受该门禁影响）；
- **缓存联动**：订阅配置发布（`setSubscriptionProviders`）必须失效面板缓存，确保验证状态变化即时反映到下一次面板渲染；
- **套餐名展示位置 (C024)**：订阅套餐名（Codex `plus`、智谱 `lite`、Cline `Cline Pass (Monthly)` 等）**不在仪表盘展示**（标头胶囊、多账号行、双槽右槽一律不呈现），统一在设置中心「订阅额度」的 Provider 行内以标签呈现，数据取最近一次采集 artifact 的 `service.plan`；
- **Cline 生命周期注记**：订阅卡不展示 `canceledAt`/`cancelAt` 等订阅生命周期注记，仅呈现额度窗口。

## 7. 扩展设计 (Additional Technical Design)

### 7.1 外部 SQLite 数据库只读防御
对于从 CC Switch（`~/.cc-switch/cc-switch.db`）导入多账号的场景：
- 连接串严格限定：`file://.../cc-switch.db?mode=ro&immutable=1`；
- 严禁向外部数据库执行 `CREATE`, `INSERT`, `UPDATE`, `VACUUM` 或 `PRAGMA` 写入指令；
- 若检测到外部数据库锁冲突，立即记录诊断并跳过，绝不阻塞 UI 线程。

### 7.2 异常流与容灾
- **Provider API 速率受限 (429 HTTP)**：返回降级指标并携带 `rateLimited = true`，自动拉长该 Provider 的下一次重试间隔至 15 分钟；
- **Provider 凭据失效 (401/403 HTTP)**：标记对应 Provider 状态为 `needsReauthorization`，在 UI 面板高亮提示用户重新录入，不影响其他 Provider 正常刷新。
