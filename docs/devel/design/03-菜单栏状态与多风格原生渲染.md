## 1. 简介 (Introduction)

本方案定义 `Bruce` 的菜单栏状态指示系统（Menu Bar Status Item）与原生下拉仪表盘（Dashboard Panel）渲染架构。

- **业务动因**：macOS 菜单栏是用户与常驻工具交互频次最高的“一等公民”入口。然而不同用户的桌面环境差异巨大（高对比度壁纸、暗黑/明亮主题、MacBook 刘海屏空间极其拥挤等），单一维度的文字或死板图标无法满足需求。此外，下拉控制台需要承载密集的 Agent 用量折线图、多模型费用对比与订阅额度卡片，对视觉质感与渲染性能提出了苛刻要求。
- **系统定位**：位于 `apps/macos/Sources/BruceApp/Views/` 与 `apps/macos/Sources/BruceGlassSurfaceCore/`，向下消费 `BruceAppCore` 提供的聚合快照，向上驱动 AppKit 原生 NSStatusItem 与无边框 NSPanel 玻璃面板。

## 2. 目标与非目标 (Goals & Non-Goals)

### 2.1 目标 (Goals)
1. **赛博精密环形仪表 (Precision Cyber Ring Gauge)**：在 22pt 标准菜单栏高度内，提供像素级精度的多段彩色用量环、刻度线、中心核心图标/剩余量指示；
2. **多模式自适应布局**：支持 `纯图标模式 (Icon-Only)`、`紧凑数值模式 (Compact Value)` 与 `宽屏组合模式 (Expanded Trend)`，适配刘海屏空间挤压；
3. **双重先锋主题引擎**：
   - **原生液态玻璃 (Liquid Glass)**：基于系统材质的连续窗口级背景模糊（macOS 26+ `NSGlassEffectView` 与 macOS 14-25 `NSVisualEffectView` 兼容层）；
   - **Nothing 极客点阵风格 (NDot Minimalist)**：硬核红/白/黑极简点阵字型、LCD 晶体迷你仪表与 Emerald Glow 微光走势折线；
4. **低功耗与零帧率抖动**：空闲态 0% CPU 占用，菜单栏重绘仅在快照更新或分钟级心跳时触发，下拉面板动画保持 120Hz ProMotion 流畅。

### 2.2 非目标 (Non-Goals)
1. **不修改系统状态栏核心行为**：不注入私有 Dock/WindowServer 进程，严格遵循 Apple 官方 `NSStatusItem` 规范；
2. **不改变数据核心协议**：UI 层纯单向数据流渲染，严禁在 View 渲染树中触发隐式网络请求或磁盘扫描；
3. **不强占全局焦点**：面板设计为非激活式（Non-activating Panel），点击面板外部或切换至其他 App 时自动轻量淡出关闭。

## 3. 需求分析 (Requirements)

### 3.1 功能需求清单
- **FR-1 菜单栏指标自由配置**：支持选择展示当日 Token 消耗、当日费用（USD）、或最紧张 Provider 额度剩余百分比；
- **FR-2 警示色彩动力学**：额度正常时为极客白/青绿（Emerald），接近阈值（>75%）时呈现警戒琥珀黄（Amber），耗尽（>95%）或断配时呈现科技红（Neon Red）；
- **FR-3 模块化卡片流**：下拉面板按业务卡片解耦：
  - Agent 活跃概览卡（Claude, Codex, Kimi 等当前活跃状态）
  - 核心 Provider 额度卡（滑动窗口进度条、重置倒计时）
  - 24 小时 Token / 费用走势折线图
- **FR-4 折叠态交互与图表动画隔离 (Collapsible Cards & Animation Discipline)**：
  - 支持卡片一键折叠与状态记忆，收起态呈现标题与高保真迷你可视化；
  - **动画事务与图表隔离契约**：收起态迷你图表（如 `HourlyLineCard` 中的 24 点迷你折线图）必须通过 `.transaction { $0.animation = nil }` 显式阻断继承父级的折叠动画事务，杜绝 Swift Charts 在 0.25 秒高度坍缩期间触发 Mark 内部数据插值形变或拉扯；
  - **展开区裁切与转场约束**：展开内容必须附加 `.clipped()` 与 `.transition(.opacity)`，确保卡片高度折叠时由下至上整齐裁切，杜绝内部柱状图、多行折线图或进度条因提议高度变矮发生垂直挤压重绘；
  - **标题栏状态件平滑渐隐**：`CollapsibleCardHeader` 中收起态 `mini` 与展开态 `status` 统一应用 `.transition(.opacity)`，杜绝两态交替时的元素横向飞动或晃动；
  - **订阅卡底栏刷新时间对齐 (C182)**：订阅用量卡片标题行不再承载最后刷新时间（展开态状态件置空），移至展开态底栏右侧，与左侧三档阈值图例（`<50` / `50–79` / `≥80`）经 `Spacer` 水平撑开并平齐对齐；非 Nothing 主题下同样在底部分隔线下右对齐展示，双端 1:1 保持对齐。
- **FR-5 顶栏单卡 Tab 切换与角标融合布局 (Top-Right Tab Switcher & Badge Fusion)**：
  - **双模式并存与设置开关**：支持「纵向级联 (滚动瀑布流)」与「顶栏 Tab (单卡极简)」双模式，在设置中心「通用」面板中提供分段开关切换，持久化落盘至 `dashboard.layoutMode`（`stack` / `tabbed`）；
  - **顶栏三图标导航**：在 HUD Header 右侧提供三个等宽紧凑分段按钮（`Token 用量 chart.bar.xaxis`、`订阅配额 creditcard`、`Agent 活跃 waveform.path.ecg`）；C214 起容器为 1px 发丝描边、无填充、无滑动药丸/滑块，选中态仅图标变色（经典主文本色 / Nothing accent：浅 `#D4A843`、深 `#4A9E5C`），未选中 secondary；
  - **固定卡片快捷键 (C211)**：⌘1/⌘2/⌘3 固定映射 Token 用量 / 订阅 / Agent 用量，与卡片拖拽顺序无关；顶栏 Tab 模式切换页签，纵向级联模式先 `scrollTo` 到该卡再切换折叠/展开；仅响应 key down（长按不连发），缺卡 no-op；裸 `1/2/3` 退役。设置中心「全局快捷键」分组在唤出看板录制器下方以只读键帽展示该映射，不提供录制/修改。Windows 以 `Ctrl+1/2/3` 等价实现；
  - **角标融合 (Badge Fusion)**：活跃 Agent 数量不再以视觉圆点呈现（C208 双端退役呼吸绿点角标），仅保留悬停提示展示活跃 Agent 数量；顶栏不额外堆砌文本，维持极简；
  - **状态记忆 (Tab Persistence)**：持久化记录 `dashboard.activeCardID`，重新呼出面板时自动记忆并恢复最后浏览的卡片；
  - **方案 1 方向感知水平滑动动效 (Directional Slide)**：切卡时根据索引前后关系自动感知滑动方向（向右切卡自右向左推入，向左切卡自左向右推入），配合容器高度以系统 Spring 阻尼曲线弹性伸缩；内部既有三张卡片结构与指标样式 100% 保持原样；
  - **跨端等价性**：Windows 端在 `apps/win/src/` 同步镜像本特性，保持 SVG 几何、CSS 硬件加速水平滑动与 `%APPDATA%\Bruce\settings.json` 的完全等价。
- **FR-6 面板底栏外观切换入口 (Footer Appearance Toggle)**：
  - **位置与形态**：在底栏「刷新」按钮右侧新增一个仅图标按钮（紧随刷新、位于左半区，与右半区的「设置 / 退出」以 Spacer 分隔），图标即当前外观态（跟随系统 `circle.lefthalf.filled` / 浅色 `sun.max` / 深色 `moon`）；
  - **单击循环语义**：单击在「跟随系统 → 浅色 → 深色 → 跟随系统」间循环，循环顺序与设置中心「配色模式」分段选择器**逐字一致**，由 `AppearancePreference.next` 单一纯函数给出（以 `allCases` 声明顺序为准，避免两处顺序漂移）；
  - **单一真源与即时生效**：复用既有持久化偏好 `OnboardingConfiguration.appearanceMode`，点击即调 `OnboardingCoordinator.setAppearanceMode`（先存后生效，保存失败不变更运行态），面板与设置窗口的 `preferredColorScheme` 随之同步；
  - **可达性**：提供 `accessibilityLabel`（含当前态中文名）与 `.help` 悬停提示，并纳入底栏整体提示文案；面板隐藏期间不得引入任何持续动画或定时器（沿用 FR-4 / C044 门控契约）；
  - **跨端分歧（有意）**：外观切换为 **mac 独有能力** —— Windows 恒深色且无配色模式偏好，故 `apps/win/src/index.html` 底栏不镜像该按钮，仅在注释中登记该分歧（与「配色模式 / 钥匙串 / 外部 CLI 来源为 mac 独有能力」同口径）。
- **FR-7 顶部四色状态灯 (HUD Status Light)**：**实现状态：已实现（C100，待双端真机验收）**。
  - **形态收敛**：删除 HUD 头左侧的 `SYS.OK` 文字牌（mac `MenuBarViews.swift` Nothing/Classic 两处、Windows `index.html` 的 `#runtime-status`），顶部只保留「状态灯 + 品牌字」；品牌字在**所有主题**统一为 `Bruce`（删除 `// HUD` 后缀，Nothing 主题同时去掉 `.hud-brand` 的 `uppercase` transform，确保字面即 `Bruce`）；灯与品牌间距保持 6，右侧 Tab 切换器 / Agent 计数靠 `Spacer` 自动右对齐。
  - **四色语义与统一判定源**：状态灯为绿 / 黄 / 红 / 中性灰四色，加「刷新中」呼吸脉冲态，由单一判定源 `resolve(moduleState:subscriptions:hasData:detail:) -> (tone, reason)` 给出（`subscriptions` 为 `{status, name}` 列表）（mac 落在 `BruceAppCore`，Windows 在 `app.js` 内实现同一张映射表，双端共用一份 fixture 对拍）。映射：绿 = `fresh` / `ready`（mac）、`ok` / `fresh` / `idle`（有数据，win）；黄 = `partial` / `stale` / `authRequired`（两端同）；红 = `failed`（mac）、`failed` / `error` / `unavailable`（win）；中性灰 = `notConfigured`（mac）、`empty` 与无 artifact 首次启动（win）；刷新中 = 呼吸脉冲且底色取当前态色。`stale`（数据过期）归黄，红只留给「采集失败且无可用数据」。
  - **聚合口径（两端逐字一致）**：灯表达「数据可用性总览」，聚合「采集健康度」（mac `moduleStatuses[.agentUsage]` / win `runtime.phase`）与「订阅服务健康度」（两端 `panel.subscription.sections[].status`，同构取值 `ok` / `partial` / `error` / `empty`）两个来源，按最严重态优先 `error > warn > ok` 取并；中性灰仅在两者均无数据时出现。
  - **触碰显示原因**：状态灯挂 hover 提示 —— mac `.help(reason)` + `.accessibilityLabel(reason)`，Windows `title` + `aria-label`（迁移原 `#runtime-status` 的 `role="status"` 语义）；文案为「态名 · 具体原因」，原因按决定灯色的一侧取：采集侧决定（含与订阅侧同级）时取采集详情 —— mac `ModuleStatus.detail`（partial 时取 envelope 诊断中**第一条非信息级**诊断的文案，全部为信息级时才取第一条；信息级码清单 `BridgeDiagnostic.informationalCodes` 与 collector-domain `INFORMATIONAL_DIAGNOSTIC_CODES` 由共享 fixture `tests/fixtures/bridge/informational-diagnostics.json` 双端锁定 —— collector 按来源顺序输出诊断、宿主追加的 `CREDENTIAL_PERSIST_FAILED` 排在最后，信息级说明不得盖住真实故障，C200），win `runtime.error` 机器码经 `RUNTIME_ERROR_TEXT` 转成的中文释义（未登记的码不外露，只显示态名）；订阅侧更严重时点名该级别的服务名（去重，以「、」连接），不挂采集侧详情。健康态显示「运行正常」、刷新中显示「正在刷新…」。
  - **边界**：卡内 LIVE 徽标已于 C210 双端退役，顶部状态灯仍以 `isLive` 表达数据新鲜度；订阅卡内 section / account note 保持不变，**不与顶部灯联动**；面板隐藏期间不得引入任何持续动画或定时器（沿用 FR-4 / C044 门控契约）。
- **FR-8 经典风格升级高斯模糊（方案A 柔光云母高斯）与全风格紧凑圆角统一体系 (Gaussian Frosted Glass & Unified Compact Corner Geometry)**：**实现状态：已实现（C102）**。
  - **紧凑圆角 1:1 统一 (macOS & Windows)**：
    - 主面板外框圆角全风格（Classic / Liquid Glass / Nothing）统一收敛至 `10pt`（旧 Classic 为 22pt，消除大面积无用边角占用）；
    - 主卡片容器（`PanelCardContainer` / `.card`）统一收敛至 `4pt`（旧 Classic 为 16pt，消除由于大圆角导致卡片内部数据与图表边缘被挤压收窄的问题）；
    - 卡片内细分子槽、分段统计格、操作按钮（`DashboardPanelGlassButtonStyle`）、状态指示芯片（`.chip`）、品牌徽章（`.pbadge`）、多账号子卡统一收敛至 `3pt`（旧 Classic 为 8~10pt）；
    - 顶栏 Tab 切换器外框为 `3pt` + 1px 发丝描边，无填充、无滑动胶囊（C214）；
    - 几何体系在 macOS 与 Windows 两端 100% 保持等价，彻底消灭原 Classic 大圆角与 Nothing 极客精密美学的割裂。
  - **方案 A 柔光云母高斯光学质感 (Scheme A: Soft Mica Gaussian Blur)**：
    - **深色外观 (Dark Mode)**：采用高透高斯底板（macOS `.hudWindow`，Windows `rgba(18, 20, 26, 0.48)` + `backdrop-filter: blur(36px) saturate(185%)`），搭配面板顶部 1px 高光发线（内缩 8pt）；卡片采用 `rgba(255, 255, 255, 0.085)` 浮岛、`0.18` 描边与顶部 1px 晶体折光边（内缩 4pt）；
    - **浅色外观 (Light Mode)**：摒弃易受暗色壁纸污染的发灰纯白透明层，重构为 macOS `.popover` 系统材质 + 暖瓷云母底板（`rgba(243, 245, 250, 0.72)`）托底；卡片采用纯白浮岛（`rgba(255, 255, 255, 0.62)`）显著拔高明度层级；外轮廓叠加 `0.085` 冷灰暗界与内侧 `0.88` 纯白高光，构筑清晰晶体折光感；语义文字与图表适配森林绿（`#0E6245`）与深海蓝（`#184E77`），大幅提高浅色强光下的可读性；
    - **风格隔离红线**：设置中心窗口保持 Fluent 平面风格（遵循 `C067` 契约），不引入毛玻璃或圆角覆盖。
- **FR-10 双端订阅额度图标锚定预警气泡 (Anchored Quota Alert Bubble)**：
  - **替代系统通知**：完全移除系统的通知中心横幅与 Windows Toast，改由在状态项/托盘图标正下方/正上方弹出的轻量悬浮气泡呈现；
  - **精巧胶囊微卡规格（方案 A · 280pt）**：固定宽度 `280pt`，高度约 `54pt`（多服务并发时 `76pt`）；左侧 `24pt` 品牌图形瓷砖徽章，中部上行「服务名 · 5h + 百分比」、下行「5pt 迷你量条 + HH:MM:SS 电子表读秒」，右侧纯净 `✕` 关闭按钮；
  - **无焦点非激活与显隐门控**：采用 `NSPanel` 的 `.nonactivatingPanel` 与 Windows `focusable: false`，弹出时绝不打断当前 IDE/终端的打字焦点；6 秒后静默平滑淡出，悬停时保持常亮；主看板已展开时静默不弹。
- **面板规格基准**：面板宽度固定为 `440pt`，自适应高度动态计算（最大高度不超过当前屏幕高度的 80%），超出区域启用平滑弹性滚动；
- **冷启动渲染延迟**：点击菜单栏图标至面板完全展开渲染时间 < 16 毫秒（首帧即见最新快照）；
- **内存安全**：AppKit 窗口与 SwiftUI Hosting Controller 之间杜绝强引用循环。

## 4. 总体架构与渲染拓扑 (Architecture)

```text
NSStatusBar (系统菜单栏)
└── NSStatusItem (Bruce 状态项)
    └── PrecisionRingGaugeView (CoreGraphics / SwiftUI 仪表)
        ├── 刻度底环 (Track Ring)
        └── 动态进度弧 (Dynamic Usage Arc, 纯净通透无中心点)

DashboardPanel (无边框浮动 NSPanel)
└── DashboardGlassPanelController (AppKit 宿主)
    ├── NativeSurfaceView (系统材质承载层: NSGlassEffectView / NSVisualEffectView)
    └── NSHostingView<MenuBarDashboardView> (SwiftUI 业务渲染层)
        ├── PanelHeaderView (时间、总消耗概览)
        ├── QuotaCardsStack (Provider 额度进度条)
        ├── AgentUsageStack (各 Agent 用量与模型分布)
        ├── TrendChartSection (折线趋势图)
        └── PanelFooterBar (刷新 / 外观切换 / 设置 / 退出入口)
```

#### 现行设计规则

##### 1. 德系包豪斯整体订阅单轨星规与主题自适应排版 (`PrecisionSingleOrbitGauge` / `MenuBarStatusItemController` · C183) 规格契约
- **包豪斯单轨星规 (The Orbit & Satellite) 几何规范**：
  - **单轨圆规 (Orbit Track)**：外径半径 `r = 6.4pt`，线宽 `1.4pt`；完整映射整体订阅剩余额度 `summary.averageRemainingQuota ?? summary.minimumRemainingQuota`（`subscriptionQuotaRatio`）；
  - **卫星刻度点 (The Satellite)**：外径半径 `r = 1.8pt`，精准锚定于剩余额度当前弧端（起始角 90° 顺时针旋转），内核点缀 `0.75pt` 微高光核，赋予精密机械腕表小秒针级微观质感；
  - **三档动态预警色阶动力学**（单轨与卫星点严格联动）：
    ```swift
    // 深色模式：高发光度 Apple 系统色；浅色模式：高对比度深调 WCAG 适配
    // 剩余额度 > 50%：翡翠绿 (深色 #30D158 / 浅色 #15803D, 健康态)
    // 剩余额度 20%...50%：警示琥珀橙 (深色 #FFB800 / 浅色 #D97706, 预警态)
    // 剩余额度 < 20% 或 failed：科技红 (深色 #FF453A / 浅色 #DC2626, 濒危态)
    ```
  - **零额度与未配置态**：额度 `<=0` 时在 12 点钟顶端呈现微型警示红点；模块未配置时底轨呈现 `[2.2, 2.2]` 虚线；
  - **刷新动态**：卫星定位点在 `refreshPhase` 驱动下沿单轨顺时针 60fps 平滑自旋，呈现陀飞轮秒针滑过的精密质感，消除双环差速撕裂感。
- **主题自适应字体与排版契约**：
  - **经典与液态玻璃主题 (T-0)**：`NSFont.monospacedDigitSystemFont(ofSize: 12, weight: .regular)`，指标间以双空格 `"  "` 分隔；
  - **Nothing 极客点阵主题 (T-4 自动联动)**：当 `coordinator.resolvedTheme == .nothing` 时，自动切换为 `NSFont.monospacedSystemFont(ofSize: 12.5, weight: .semibold)`，单位格式化为硬朗大写（`K` / `M`），指标间以 `35% alpha` 的斜杠 `" / "` 分隔，与下拉控制台 Nothing 点阵风格达成 100% 视觉统一度；
  - **光学居中与防抖**：采用 `capHeight` 结合 `descender` 的光学几何中心公式垂直对齐；状态项宽度采用 `4pt` 步进量化，杜绝数字跳动时左侧状态栏发生高频抖动；
  - **渲染稳定性红线 (C203)**：`NSImage(drawingHandler:)` 绘制闭包内**严禁调用任何文本测量 API**（`NSAttributedString.size()` / `boundingRect` 等）——该测量走 NSStringDrawingEngine 的 CoreText 排版路径，在 `NSCustomImageRep` 离屏上下文中偶发属性字典插 nil（`NSInvalidArgumentException` → SIGABRT，安装版每天多次自退，C180 引入当天首崩）；排版尺寸一律经闭包外主线程测量（`targetStatusItemLength`）或字体度量推导（行高 = `ceil(ascender + |descender|)`），属性串闭包内构建后**只执行 `draw(in:)`**；指标字体（T-0 / T-4 两个实例）为控制器级缓存，避免 50ms 刷新动画高频重绘时反复构造；
  - **设置页预览条对齐**：`SettingsView.menuBarPreviewStrip` 同步升级为德系包豪斯单轨星规并根据当前设置主题动态应用 T-0 / T-4 字体与格式，保持所见即所得。

##### 2. 窗口级材质承载层架构 (`DashboardGlassPanelController`)
彻底摒弃在单个卡片上叠加多层仿玻璃塑料背景的做法，将系统级材质作为统一底板：
```swift
final class DashboardGlassPanelController: NSViewController {
    private let surfaceView = NativeSurfaceView()
    private var hostingView: NSHostingView<MenuBarDashboardView>?

    override func loadView() {
        let root = NSView()
        root.wantsLayer = true
        surfaceView.autoresizingMask = [.width, .height]
        root.addSubview(surfaceView)
        self.view = root
    }
}
```
- **macOS 26+**：采用 `NSGlassEffectContainerView` 搭配流体高光与系统光感；
- **macOS 14-25**：回退至 `NSVisualEffectView(material: .popover, blendingMode: .behindWindow)`；
- 内部 SwiftUI 卡片背景全部设置为 `Color.white.opacity(0.04)`（暗黑）或 `Color.black.opacity(0.02)`（明亮），配合 `0.5pt` 细微半透明描边，实现晶莹通透的呼吸感。

##### 3. Nothing 风格点阵引擎
针对追求极简硬核科技的用户，内建 Nothing 风格主题：
- **字体契约**：数字与标题采用 `NDot 57` 点阵等宽字型，辅助信息采用 `Space Mono`；
- **点阵 LCD 仪表**：将连续圆环离散化为 16 段矩阵点，每段代表 6.25% 刻度；
- **Emerald Glow 微光走势**：折线图采用无填充的 1pt 纤细线段，并在折点处绘制 2pt 发光微粒。

##### 4. 底栏外观切换入口 (`actionFooter` 外观按钮) 契约
- **唯一真源**：外观偏好只存于 `OnboardingConfiguration.appearanceMode`（`AppearancePreference`）；底栏按钮与设置中心「配色模式」是同一偏好的两个入口，禁止引入第二份状态或独立持久化键；
- **循环顺序**：`AppearancePreference.next` 是唯一的循环定义（跟随系统 → 浅色 → 深色 → 跟随系统），以 `allCases` 声明顺序实现；设置中心分段选择器的选项顺序必须与之一致，变更任一处必须同步另一处；
- **先存后生效**：点击经 `OnboardingCoordinator.setAppearanceMode`，持久化失败时不改变运行态外观（与设置中心同一失败语义）；
- **图标即状态**：按钮图标必须反映当前外观态（`circle.lefthalf.filled` / `sun.max` / `moon`），不得使用与当前态无关的固定图标；图标为 SF Symbols，随底栏既有 `.labelStyle(.iconOnly)` 渲染；
- **面板显隐门控**：该按钮为无状态瞬时控件，不得引入持续动画、定时器或后台任务（沿用 FR-4 / C044 契约）；
- **跨端口径**：Windows 恒深色、无配色模式偏好，底栏有意不镜像该按钮；该分歧在 `apps/win/src/index.html` 底栏注释中登记，不得静默扩散为「未对齐缺陷」。

##### 5. 经典风格高斯模糊光学质感与全风格 1:1 紧凑圆角体系 (C102)
- **紧凑圆角阶梯矩阵契约 (Corner Radius Hierarchy)**：
  - 为消灭不同主题间的几何割裂，并杜绝原 Classic 风格大圆角对卡片内部小图表与指标的挤压，macOS 与 Windows 统一实行紧凑型圆角分层：
    1. **面板外壳 (Panel Shell)**：`10pt`（旧 Classic 22pt，与 Nothing 10pt 统一）；顶部 1px 晶体高光发线内缩收敛为 `8pt`；
    2. **主业务卡片 (Main Cards)**：`4pt`（旧 Classic 16pt，与 Nothing 4pt 统一）；卡片顶部 1px 折光边内缩收敛为 `4pt`；
    3. **细分子槽 / 按钮 / 徽章 / 芯片**：`3pt`（旧 Classic 8~10pt，涵盖 `UsageHeroCard` 月度细分格与四槽、`SubscriptionCard` 额度双槽与账号卡、`ProviderBrandBadge` 品牌徽章、底栏按钮 `DashboardPanelGlassButtonStyle` 以及 Windows 对应元素）；
    4. **顶栏 Tab 切换器**：外框 `3pt` + 1px 发丝描边，无填充、无滑动胶囊（C214）。
- **方案 A 柔光云母高斯光学质感契约 (Scheme A Token Matrix)**：
  - **深色外观 (Dark Mode)**：
    - 面板底板：macOS 系统 `.hudWindow` 搭配 `panelTint = Color.black.opacity(0.48)`；Windows `#panel` 使用 `rgba(18, 20, 26, 0.48)` 叠加 `backdrop-filter: blur(36px) saturate(185%)`；
    - 卡片浮岛：`cardFill = Color.white.opacity(0.085)`，边框 `cardBorder = Color.white.opacity(0.18)`，折光发线 `cardHighlight = Color.white.opacity(0.14)`；
  - **浅色外观 (Light Mode)**：
    - 暖瓷云母底板：macOS 系统 `.popover` 搭配 `panelTint = Color(red: 243/255, green: 245/255, blue: 250/255).opacity(0.72)`，抵抗暗色壁纸透光发脏；
    - 纯白浮岛卡片：`cardFill = Color.white.opacity(0.62)`，将卡片视觉层级与明度显著抬升；
    - 双层复合轮廓：外层冷灰暗界 `cardBorder = Color.black.opacity(0.085)`（杜绝纯白背景边缘发虚），内层纯白折射边 `cardHighlight = Color.white.opacity(0.88)`；

##### 7. 额度摘要门禁与滚动条压制 (C133 / C132)
- **菜单栏额度门禁 (TD-009 / C133)**：菜单栏「最低剩余额度」「平均剩余额度」与仪表盘订阅段共用同一验证门禁 —— 只统计 `subscriptionProviders[id].verificationStatus == ok` 的 Provider；`none` / `failed` / `needsRelogin` 一律不参与。Token 与费用摘要不受此门禁影响。验证状态变化须经面板缓存失效让菜单栏摘要立即重算，不得保留旧口径。
- **滚动条事件驱动 (TD-012 / C132)**：`ScrollIndicatorSuppressor` 不再使用 0.3s 周期 Timer。面板可见且视图已入窗时，向上定位目标 `NSScrollView` 并通过 KVO 观察 `hasVerticalScroller` / `hasHorizontalScroller` / `scrollerStyle`，同时监听 `NSScroller.preferredScrollerStyleDidChangeNotification`；命中后把 `scrollerStyle` 置为 `.overlay` 并关闭两侧 scroller。面板隐藏或视图离窗时解除观察，空转开销为零。
- **观察回调的隔离边界 (C143)**：KVO changeHandler 与通知 block 都是 nonisolated，必须经 `nonisolated` 入口显式建立主线程语义 —— 主线程用 `MainActor.assumeIsolated` 同步压制，其他线程交主队列异步执行，不得直接调用 MainActor 隔离方法；`deinit` 只释放自身观察资源（KVO 观察与通知 token），不调用隔离方法。

##### 8. 双端仪表盘物理卷轴抽屉开合机制 (流派 B · C137)
- **设计定位与视觉质感**：
  - 彻底摒弃瞬时弹出的生硬体验，双端统一引入「流派 B：物理卷轴抽屉下拉 / 帘幕展开 (Curtain Drop & Roller Blind Reveal)」动效；
  - 面板如同一幅自菜单栏图标顶边（Windows 端为任务栏托盘侧）顺滑垂下的丝质卷轴，外壳平滑伸展，内部复杂卡片、图表与数据保持真实固有高度被自顶向下自然裁切露显（而非挤压变形），带有物理世界的质量感与精致感。
- **macOS 端物理阻尼展开与逆向回卷契约 (`DashboardGlassPanelController` / `MenuBarStatusItemController`)**：
  - **时序与阻尼曲线**：展开动画时长 240ms（0.24s），采用 `CAMediaTimingFunction(controlPoints: 0.22, 0.61, 0.36, 1.0)`（C145 修正：原 `(0.16, 1.0, 0.3, 1.0)` 前 45ms 即走完 74.5% 行程，视觉上等同瞬移）；收起动画时长 140ms（0.14s），采用干净利落的 `kCAMediaTimingFunctionEaseIn` 快速回卷；
  - **顶边绝对锚定 (Top Anchor Lock)**：展开时以菜单栏状态图标中心为 X 锚点，面板顶部 Y 固定不变，起始高度设为 `curtainCollapsedHeight = 20pt`、透明度 `0`（C145 由 `0.25` 下调，避免首帧半透明鬼影），目标窗口 frame 沿 Y 轴向下延展至自适应目标高度，透明度同步插值至 `1.0`；
  - **防垂直挤压架构 (Anti-squash Content Constraint)**：`hostingController.view` 以 top/leading/trailing 必需约束贴住窗口顶边，并以显式内容高度约束承载 SwiftUI 内容高度（C147 起不再使用低优先级底约束，见规则 10）；同时根容器设置 `masksToBounds = true` 与 `isFlipped = true`。这使得面板内部 SwiftUI 业务卡片在窗口高度从 20pt 展开的过程中始终以固有高度完整布局，绝不发生柱状图挤压或字体重排，由 AppKit 视口作为物理遮罩自然揭露；
  - **逆向平滑回卷与焦点归还**：点击外部、快捷键或再次点击图标关闭时，先锁定状态并在 140ms 内逆向平滑卷回至 20pt / alpha 0，动画完成后再调用 `panel.orderOut(nil)` 并将焦点安全归还至前台宿主 App；
  - **连击打断保护与 SwiftUI 布局重入防御**：引入 `isTransitioning` 状态锁，在展开与收起动画执行期间，`resizePanel` 跳过非用户驱动的突变重绘，避免首帧动态高度计算与动画插值产生画面跳跃或撕裂。
- **Windows 端 CSS 硬件加速卷轴展开契约 (`styles.css` / `app.js` / `lib.rs`)**：
  - **硬件加速渲染**：利用 CSS `@keyframes winCurtainEnter` 与 `winCurtainExit`，结合 `clip-path: polygon(...)` 与轻量 `transform: translateY(...)` / `scaleY(...)`，保持满帧率渲染，避免修改 DOM 尺寸导致的强制重排（Reflow）；
  - **开合时序**：进入 260ms `cubic-bezier(0.22, 0.61, 0.36, 1)` 揭开，收起 140ms `ease-in` 卷回；在 `requestHideDashboard()` 中播放退出动画并在 `animationend` / 超时后通知 Tauri 后端 `hide_dashboard`。

##### 9. 全局界面动效总开关 (`MotionPreference` · C145)
- **单一裁决源**：应用配置项 `MotionPreference` 取 `system` / `always` / `never`（默认 `system`），解析规则唯一：`suppressed = (preference == never) ‖ (preference == system ∧ 系统减弱动态效果)`。系统值在 macOS 读 `NSWorkspace.accessibilityDisplayShouldReduceMotion`、在 Windows 读 `prefers-reduced-motion`，且系统设置在运行中变更时必须重新解析（mac 监听 `accessibilityDisplayOptionsDidChangeNotification`，Windows 监听 `matchMedia(...).change`），不得只在启动时读取一次。
- **作用域为整个 app 的显式动效**：macOS 覆盖 SwiftUI `withAnimation` / `.animation(...)`、AppKit 卷轴开合过渡、菜单栏刷新指示环；Windows 覆盖全部 CSS `animation` / `transition`。`never` 下所有无限循环动效（呼吸、流动、热力、转圈）不挂载，一次性过渡直接落定终值。
- **与面板显隐门禁是逻辑与**：`DashboardPanelAnimationPolicy` 的 `panelVisible` 判定保持原样，`motionSuppressed` 只能追加约束，禁止替代（回退 C044 / TD-012 的性能修复）。
- **实现形态**：SwiftUI 的 `\.accessibilityReduceMotion` 是只读环境值，无法覆盖，因此自建可写环境键 `EnvironmentValues.motionSuppressed`，在两个 SwiftUI 宿主根（仪表盘面板、设置窗口）注入；Windows 以 `<html data-motion>` 作为唯一真源，CSS 侧 `html[data-motion="never"] *` 全量闸门，删除原 `prefers-reduced-motion` 与 JS 判据的双重裁决，避免设置值与系统值相互覆盖。
- **默认值取向**：默认 `system`，保证升级用户行为零变化；`always` 为显式 opt-in，用于用户本机已开启系统减弱动态效果但仍希望看到应用内动效的场景。

##### 10. 面板高度单一真源与失配兜底 (`DashboardPanelSizingPolicy` · C147/C148)
- **单一真源**：面板窗口高度只接受 SwiftUI 上报的目标内容高度（`MenuBarDashboardView.reportedContentSize` = 顶栏 + 卡片栈理想高度 + 底栏，三段实测齐全后才上报 → `MenuBarStatusItemController.resizePanel`），控制器是唯一写入点；打开面板时优先使用最近一次上报值，`fittingSize` 只在从未收到上报时兜底。
- **失配必补应用**：卷轴展开/收起动画期间（`isTransitioning`）与面板隐藏期间收到的上报不得直接丢弃，必须写入待应用槽，并在动画结束、面板重新可见时补应用一次；禁止只依赖「值变化才回调」的几何回调节奏，被吞掉的上报必须可重放。
- **应用时机不得重入布局**：上报在 SwiftUI 布局回调中到达，应用端必须把同一拍内的多条上报合并（30ms 窗口）后再改窗口；禁止在布局回调内同步 `setFrame` + `layoutSubtreeIfNeeded`。
- **内容填满窗口**：AppKit 宿主视图四边贴合窗口（top/leading/trailing/bottom 均必需），SwiftUI 根视图不再 `fixedSize`，视口按窗口高度弹性伸缩。这样窗口高度动画的每一帧，底栏都贴在下边缘同步移动，杜绝「底栏先跳到位、窗口边缘随后追赶」的错位；卷轴开合期间窗口从 20pt 长起时，顶栏留在顶部、底栏直到窗口容得下顶栏+底栏才出现，中间视口逐步展开，内容向下溢出由根视图裁切（不存在内容被强制整体上移把 Header 顶出）。
- **屏幕夹取**：任何尺寸应用都要经 `BruceAppCore.DashboardPanelSizingPolicy` 顶边锚定 + 屏幕夹取：顶部不高于 `visibleFrame.maxY - 8`，底部不低于 `visibleFrame.minY + 8`，内容高于可用高度时压缩窗口高度（视口随之收窄并转为滚动），杜绝 Header 或底栏被推出屏幕。屏幕参数变化（`didChangeScreenParametersNotification`）后按已记录尺寸重新夹取一次。

##### 11. 卡片过渡身份稳定与单一高度动画源 (`MenuBarViews` / `SubscriptionCard` · C148)
- **几何上报只给终值**：`onGeometryChange` 在 SwiftUI 动画期间只回调布局终值，不会逐帧给出插值。因此**禁止**用「测量内容高度 → 逐帧跟随窗口 frame」的方案追求窗口与内容的逐帧同步：那样只能得到一次跳变，窗口和内容必然错位。
- **窗口是唯一高度动画源**：内容高度变化一律转成**一次**窗口高度动画（`NSAnimationContext` + `panel.animator().setFrame`，0.24s `easeInEaseOut`，与卡片内容动画同长）。拍内多条上报先经 30ms 窗口合并成一个目标，严禁每条上报各起一条动画 —— 反复重新起步的缓动就是肉眼看到的"弹簧回弹"。动效开关（`motionSuppressed`）关闭时直接 `setFrame`。
- **卡片栈视图身份恒定**：卡片在 `cardStack` 中遍历渲染时，严禁使用 `if isCollapsed { card.draggable... } else { card }` 等外层条件修饰符粉碎其结构性身份（Structural Identity）；卡片必须始终保持一致的 View 类型，展开/折叠仅通过内部状态驱动。
- **交换态容器高度必须是显式可动画值**：折叠/展开（三张卡片的 `expandedContent`）、多账号局部开合（`multiAccountContent`）与 Tab 单卡切换都必须用 `ZStack(alignment: .top)` 承载互斥内容，内容经 `readingNaturalHeight(into:)` 上报**自然高度**（内部 `fixedSize(vertical: true)`，保证被外层裁切时测量值不随容器收放而失真），再由外层显式 `.frame(height:)` + `.clipped()` 按目标高度插值。目标高度统一取自 `BruceAppCore.DashboardSwapHeight`：已测量取实测值，未测量返回 `nil` 退回自然高度，**严禁用 0 表示未测量**（会把刚插入的内容永久裁死）；折叠态是显式的 `DashboardSwapHeight.collapsed`（=0），与「未测量」区分。禁止依赖 `if`/`else` 增删布局空间的隐式插值 —— 那会让新旧内容先并存占位再回落，面板先冲高再缩回。
- **禁忌曲线**：卡片高度相关的切换禁用过冲曲线（`spring(dampingFraction < 1)`、`.bouncy`）；卡片折叠/展开、多账号开合、Tab 单卡切换与窗口高度过渡共用 `DashboardMotionTiming.contentResize`（0.30s `easeInOut`），时长与曲线必须同源，各自为政的时长会让外框与正文互相追尾。
- **标题行不得有瞬移元素**：拖拽手柄必须常驻、占位宽度随折叠态插值（展开态 0 宽），严禁用 `if isCollapsed` 增删节点导致标题横向跳位；收起摘要（mini）与展开态状态件（更新时间）常驻同一占位盒，但必须**接力淡入**（先让退场方快速淡出、再让入场方淡入），严禁同时交叉淡入 —— 两者都贴右缘，同时半透明会让状态文字压在最后一条量条上，读作糊成一团。正文淡出时长短于外框收拢时长，避免半透明文字拖成残影。
- **局部动效边界**：多账号开合只经 `value: expanded` 的局部 `.animation` 驱动，严禁在交互按钮里用全局 `withAnimation` 污染外层事务；展开时动态挂载的账号子卡内部量条（`MeterBar`）必须抑制 0.45s 延迟装载动画（`animateEntrance: false`），直接以当前占比呈现；展开箭头采用单图标 `rotationEffect` 连续旋转，不做字符替换。

##### 12. 订阅卡空状态与 Tab 回退门禁 (`SubscriptionEmptyStatePolicy` · C157)
- **只做两态**：A「未配置」与 C「已配置但无数据」；**明确不引入** B「待验证 / 已停用」状态。判定输入只有面板视图模型与 provider 配置快照：`subscription == nil` 且 artifact 已存在；`dashboard-eligible provider` = 已添加 ∧ `enabled` ∧ `verificationStatus == .ok` ∧ 非临时屏蔽（`SubscriptionPresentationPolicy.isProviderTemporarilyDisabled`，当前为 `jev`）。
  - **A 未配置**：eligible 数为 0（含从未添加、仅添加未验证、全部停用）→ 标题「尚未添加订阅」、说明「添加并验证账号后，显示 5 小时与每周额度。」、按钮「添加订阅」。
  - **C 无数据**：eligible > 0 但 `makeSubscription` 仍返回 nil → 标题「暂未获取到额度」、说明「这次采集没有返回订阅额度，可手动刷新重试。」、按钮「刷新额度」；刷新触发一次 `agentUsage` 全量刷新。
  - artifact 缺失（`panel.usage == nil`）时不进入本规则，继续走既有「未配置模块」全局兜底。
- **不得静默消失**：栈模式必须占据订阅卡槽位并参与排序 / 拖拽 / 折叠；Tab 模式订阅页签必须渲染空态卡。`hasCards` 必须计入 `subscriptionEmpty`；订阅页签不再调用 `fallbackTabCard`，artifact 缺失时直接走全局兜底 `emptyPanelState`，任何情况下都不得把 Token 用量卡顶到订阅页签。
- **结构**：复用 `PanelCardContainer` + `CollapsibleCardHeader`（标题「订阅用量」），右槽状态词「未配置 / 无数据」；正文为 36pt 虚线空位框 + 图标（A `creditcard` / C `arrow.clockwise`，16pt，必须是可解析的 SF Symbol 名，`Image(systemName:)` 对无效名静默渲染为空）、标题 12.5pt（Nothing 11.5pt）、说明 10.5pt（Nothing 10pt）、按钮 11pt（Nothing 10pt mono）。展开高度走 `readingNaturalHeight`；折叠态沿用 `collapsedCards` 持久化，**不新增「隐藏卡片」概念**。
- **入口深链**：按钮直达设置「订阅额度」页；`SettingsWindowController.present(category:)` 与 `SettingsView` 对 `requestedSettingsCategory` 的消费属于本规则实现范围，禁止只打开通用页。
- **可访问性**：标题行沿用 `CollapsibleCardHeader` 的标题与展开 / 收起提示；正文图标 + 标题 + 说明合并为一个无障碍元素（`children: .ignore`），标签为「订阅用量，<状态词>。<标题>，<说明>」；状态词是文本而非仅颜色；按钮保持独立元素与独立 label，不并入正文。
- **缓存与动效边界**：provider 配置 / 验证状态变化必须失效面板缓存（`setSubscriptionProviders` 已具备）；空态出现或消失不新增动画，走既有卡片栈高度链路与面板高度单一动画源（规则 10 / 11）。
- **测试**：`PanelViewModelHarness` 表驱动覆盖 A / C、artifact 缺失、已有订阅不出空态，并用 `NSImage(systemSymbolName:)` 断言两态图标均为有效 SF Symbol；`AppModelCacheHarness` 覆盖 provider 变更后缓存失效，以及 `jev` 临时屏蔽、未验证、验证失败、需重新登录、全停用一律归 A。

##### 13. 额度条与余额数字的更新动效 (`MeterBar` / `WindowRowView` / `BalanceRow` · C158)
- **触发边界**：只在 artifact 刷新导致 `usedPercent` / `percentText` / `amount` 变化时播放；首次出现、卡片展开、Tab 切换、设置变更不播放。动画只挂叶子视图，**严禁**用全局 `withAnimation` 包整卡或整面板（会与规则 10 / 11 的高度动画互相打架）。
- **单一裁决源 `MeterMotionPolicy`**（BruceAppCore）：按 `fill` / `percent` / `balance` / `levelCrossfade` / `thresholdColor` / `highlight` / `sheen` 返回曲线；`panelVisible == false` 或 `motionSuppressed` 时一律返回 nil。视图只读 `MeterMotionPolicy.animation(for:panelVisible:motionSuppressed:)`，**不得**内联 `motionSuppressed ? nil : …`；档位交叉淡入、阈值色、高光与扫光同样受门控，不得只门控宽度。高光 / 扫光是否启动由 `shouldPlayUpdate` 判定（分数差 ≤ 0.0005 视为同值，不空转）。
- **量条（classic / glass）**：增量增长，从旧值过渡到新值；`.spring(duration: 0.85, bounce: 0)` 或等价临界阻尼曲线，**零过冲**（数值是真值，不允许短暂显示更大的百分比）。`MeterBar` 与 `MiniMeterBar` 同曲线；宽度变化用 `.animation(MeterMotionPolicy.animation(for: .fill, …), value: usedFraction)`，`panelVisible == false` 或 `motionSuppressed` 时为 nil 直接落值。
- **档位渐变**：绿 / 橙 / 红三层 `LinearGradient` 叠放，按 `level` 做 0.34s 交叉淡入；禁止直接替换单个 gradient（不可插值，必然硬切）。
- **增长提示**：填充右缘 2px 高光（仅动画期可见）+ 一次 0.85s 的 46px 扫光（仅增长、不循环、不改变几何）。真实 30 分钟刷新常只有 1–3pp，小增量靠高光、扫光与数字滚动传达「刚更新」，不得伪造量条距离。
- **Nothing 分段**：24 段由可动画 `Shape`（`animatableData` 为插值分数）逐帧驱动点亮段数（仅对 `usedFraction` 挂 `.animation` 会让段数一次性跳到终值）；动画期前沿段（最后点亮的一段）叠白色提亮层，随同一插值分数逐段前移，高光以 `highlight` 曲线淡入淡出；不做放大，避免改变分段几何。小于 4.17pp 的变化可能不动段，由百分比数字承担。
- **百分比数字**：`.contentTransition(.numericText(value: usedPercent))` 与量条同一 0.85s 事务；Nothing 的阈值色同步 0.25s 过渡。
- **余额数字**：`BalanceRow` / `BalanceChip` 增加 `amount: Double`（`amountText` 仍是展示与 VoiceOver 的唯一文案源）；`.contentTransition(.numericText(value: amount))` + `.animation(.spring(duration: 0.6, bounce: 0), value: amountText)`。`--` 占位不滚动（占位与数值之间以 `.id` 切换视图身份）、首次出现不滚动、位数 / 千分位骨架变化交给 numericText 原生处理。
- **行身份**：`ForEach` 的窗口行按 `label`（多账号再加 `account.id`）标识，禁止用数组下标；否则窗口增删时动画会作用到错误行。
- **测试**：`PanelViewModelHarness` 表驱动断言 `MeterMotionPolicy` 每种动效的曲线（弹簧 bounce 恒为 0）、隐藏 / 减弱 / 两者同时时为 nil、百分比与量条同曲线、高光保持覆盖量条时长，以及 `shouldPlayUpdate` 的不空转与门控；并断言 `BalanceRow.amount` 取自 artifact、`amountText` 由 amount 格式化（货币与 Credits 两路）。动效本身靠真机截图 / 录屏核验，不把 UI 动画写进单测。
- **双端契约**：0.85s / 0.6s、零过冲、增量语义与「小增量靠数字 / 扫光」同步写入 design/05 规则 34；Windows 用渲染后 WAAPI 补间复现同一语义，不得用 CSS transition 全量重建冒充。

##### 21. 14 日柱顶部标注与图例徽章尺寸 (`HourlyLineCard` / `dailyLegend` · C218)

- **悬停显示（C222）**：经典 / 液态玻璃的 14 日柱总量默认 `opacity 0`，鼠标悬停该日期列（含柱顶）才淡入，移出淡出；Windows fluent 同语义（`.day-total` 默认 `opacity: 0` + `.day:hover`）。标注仍参与布局（Windows 保留 10px 标注行、mac 保留 20% y 域），显隐不得改变柱高、日期轴或图例位置。Nothing 点阵柱的悬停语义不变。
- **Windows 等价**：14 日柱继续以 `calc((100% - 10px) × ratio)` 预留顶部标注行，不改柱高公式。
- **图例徽章**：双端 14 日图例厂商徽章由 14pt 收敛到 **12pt**，并通过 mac `usesBrandChrome` / Windows `forceBrand` 保留品牌真彩/位图与系列色环（不得退回系列色瓷砖）；行首 agent 徽章保持 14pt，C217 的 3pt leading 内缩保留。
- **验证**：实机截图最高柱总量完整可见、柱顶不顶满；图例徽章 12pt 仍带品牌图形与色环；日期轴/图例位置不变。

##### 22. 主题强调色对齐 Nothing 杏 / 绿 (`UsageHeroCard` / `AccountTagChip` · C220)
- **统一 accent**：经典 / 液态玻璃 / Nothing 共用同一强调色 token —— 浅色 `#D4A843`（杏）、深色 `#4A9E5C`（Nothing 绿）。hero 数字渐变为 accent 深阶 → 浅阶（浅色 `#B8860B → #E3BE6B`，深色 `#2A6B3C → #8CCB98`），成本文字、月度 chip 当前 / 选中标签与描边、背景代码流 tint、订阅账号标签均取该 token。C220 起 `UsageTier` 不再驱动 hero / 热力图的五档彩色，仅保留语义分档。
- **热力图档位**：level 1-5 统一为 accent 的 `20/40/60/80/100%` 透明度档（与 Nothing 原口径一致），level 0 与空槽按 §15 取主题空槽色。**禁止**恢复 sage..forest 五档彩色或蓝色 accent。
- **Windows 等价（恒深色）**：仪表盘新增 `--panel-accent #4A9E5C` / `--panel-accent-deep #2A6B3C` / `--panel-accent-soft #8CCB98`；hero 渐变固定为深阶 → 浅阶，`.hero-cost`、`.chip.current/.selected`、`.card.drop-target`、代码流 tint 取面板 accent；热力图 l1-l5 为 `rgba(74,158,92,.2/.4/.6/.8/1)`。设置页继续使用全局 `--accent` 蓝色，两者不得混用。
- **不变项**：面板 / 卡片底色、玻璃材质、文字层级、厂商品牌色、订阅阈值三色（good / warn / crit）与 Agent 品牌徽章不随本规则改动。
- **验证**：mac 浅色 / 深色与 Windows 真实渲染截图逐项核对 accent、渐变、热力图档位与 chip；Windows 用例断言面板 accent 与设置页 `--accent` 分离。

##### 23. Nothing 浅色 Agent 系列色 (C221)
- **浅色杏阶**：Nothing 浅色下 Agent 系列色取杏色五档 `#946A08 / #B8860B / #D4A843 / #E3BE6B / #F0D69A`（深→浅），与 hero / 热力图同源；14 日点阵柱分段、图例徽章、agent 行首色点、逐小时走势线（`#D4A843`）与模型 / 项目明细条（`#B8860B / #D4A843 / #E3BE6B`）统一取该色阶。
- **深色不变**：Nothing 深色仍为绿阶 `#8CCB98 / #5FAF6E / #4A9E5C / #35854A / #2A6B3C`、走势线 `#30D158`、明细条 `#30D158 / #4A9E5C / #2B7A42`。
- **禁止**：浅色仍出现绿色分段、柱体 / 图例 / 行首色点不同源，或把 Windows 深色侧改成杏色（Windows 恒深色，只取绿色档）。
- **验证**：`PanelViewModelHarness` 断言 `nothingRampHex` 浅色落在杏阶、深色落在绿阶；实机 Nothing 浅色展开 Agent 卡目视确认柱状图为杏色。

##### 24. 单账号订阅段的旧快照标注 (`SubscriptionProviderSection.lastSuccessText` · C224)
- **契约**：`SubscriptionProviderSection` 携带 section 级 `lastSuccessText`（Rust `last_success_text`，对拍协议同名 camelCase）。单账号段取该服务的「上次成功 HH:mm」（仅 `freshness == "stale"` 且 `capturedAt` 可解析，口径与账号级 `lastSuccessText` 完全相同）；多账号段恒为 `nil` / `None`，由各账号子卡自行呈现。
- **渲染**：单账号段（窗口型与纯余额型）在窗口行 / 余额双槽与 error/empty 说明之后追加一行，与账号子卡同款（9pt secondary，无障碍标签「这是上次成功的数据」）；出口阻断态同样显示，标明受保护快照的时间。多账号段**不得**在段级重复呈现。单账号段仍**不得**为取该文案而读取 `section.accounts`（design/05 订阅段分支规则）。
- **禁止**：查额失败或被跳过（冷却 / 过期回填）而沿用旧窗口时，单账号段以与实时数据相同的外观呈现、无任何时间标注。
- **验证**：`PanelViewModelHarness.singleAccountStaleSectionCarriesLastSuccess`、Rust `single_account_stale_section_carries_last_success_like_mac`、Windows 前端单账号 / 多账号用例；viewmodel-parity golden 含该字段。

##### 25. 纯余额型「订阅状态」槽的态名与点色 (`BalanceDualSlotView.rightSlot` / `balanceSlots` · C225)
- **同一判定源**：右槽态名取 `DashboardStatusToneResolver.statusLabel(for:)`（Windows `statusLabel`），点色按 `sectionTone(for:)`（Windows `sectionTone`）取订阅阈值三色：`ok` `#4A9E5C`、`warn` `#D4A843`、`error` `#D71921`；`neutral` 取 disabled 灰（mac `NothingTokens.disabled`，Windows `#666666`）。与顶部状态灯共用同一张映射表，不另立词表。
- **禁止**：点色恒绿、直出 `error` / `partial` 等英文状态码。
- **验证**：`PanelViewModelHarness.balanceSlotStatusUsesSharedToneTable`；Windows 前端断言 error / partial / empty 三态的态名、点色类名且不含状态码原文。

### 6.1 Web Widget 嵌入式组件契约 (`apps/widget/`)

- **失焦关闭**：监听 `NSEvent.addGlobalMonitorForEvents(matching: [.leftMouseDown, .rightMouseDown])`，点击面板以外区域即刻触发平滑动画关闭；
- **Esc 快捷键响应**：面板作为第一响应者时，按下 Esc 键立即收起。
