## 1. 简介

`Bruce` 是一款专为开发者设计的 macOS 原生菜单栏常驻应用，核心用于统一监控和分析本机各类 AI Agent（如 Claude Code, Codex, OpenCode 等）的 Token 用量、费用估算和多模型订阅额度。作为菜单栏常驻辅助工具，具备系统登录时自动随系统启动（Launch at Login）并静默常驻在顶部菜单栏的能力，是保障用量连续统计与实时额度预警的关键基础体验。

在历史版本中：
1. `docs/devel/design/04-设置中心与价格校准交互.md` §2.2 与 §3.1 已明确将开机自启动纳入通用设置（General）规划并约定采用 macOS 标准 `SMAppService` API，但代码层尚未落地具体服务实现与开关绑定；
2. 新用户在完成 `T22` 首次启动欢迎向导（Welcome Wizard）后，缺少在初始向导中一键开启自启动的便捷通道；
3. 非应用捆绑包（开发调试 `swift run` 或受管单元测试环境）调用系统服务时可能触发异常或无感失败，缺少协议抽象与测试 Double 隔离机制。

本方案确立 macOS 端基于 `ServiceManagement.SMAppService.mainApp` 原生机制的开机自启动架构，提供协议化服务抽象 `LaunchAtLoginServiceProtocol`，在「设置中心 - 通用设置」与「首次启动欢迎向导 - 第三步（外观与快捷唤出）」两处核心入口落地交互开关，并完备处理 `.requiresApproval` 权限拦截与降级跳转系统偏好设置。

**批准情况**：2026-11-03 维护者明确三项核心决策：
- **A1**：优先实现 macOS 原生开机自启动（基于 macOS 14+ `SMAppService.mainApp` API），Windows 端仅在设计基线中对齐技术规划；
- **A2**：设置中心「通用」面板增设「开机自启动」开关（默认关闭，由用户主动开启），并在首次启动欢迎向导（Welcome Wizard）第三步提供可选联动配置；
- **A3**：按 `AGENTS.md` 规范创建专属特性分支 `feat/T25-launch-at-login` 独立推进。
据此本文转为现行基线，执行拆解为 `T25`。

## 3. 规范

### 3.1 目标

1. **macOS 原生合规与无侵入性**：
   - 严格遵循 Apple 官方推荐标准，使用 macOS 13.0+ 引入且在 macOS 14/26 上原生完备的 `ServiceManagement.SMAppService.mainApp` API；
   - 坚决杜绝安装隐式 `LaunchDaemons`、`LaunchAgents` plist 或修改不可控的系统隐藏启动脚本，100% 保持在用户空间合规运行。
2. **双入口一致性与配置同步**：
   - **入口 1（设置中心通用面板）**：在「通用 (General)」分类中提供标准 Switch 风格行；
   - **入口 2（首次启动欢迎向导 Step 3）**：在外观与快捷偏好区提供开机自启动卡片，便于新用户在初始引导中直接设定；
   - 两个入口的双向状态实时同步，配置通过 `OnboardingConfiguration`（`launchAtLogin: Bool?`）与系统 `SMAppService.mainApp.status` 双向对齐。
3. **系统拦截感知与友好降级引导**：
   - 当用户曾在 macOS「系统设置 → 通用 → 登录项与扩展」中禁用了 Bruce 时，系统状态呈现为 `.requiresApproval`；
   - 界面精准检测该状态，行内提示「需在系统设置中允许」，并提供一键跳转系统设置（`SMAppService.openSystemSettingsLoginItems()`）的操作按钮。
4. **架构解耦与测试友好**：
   - 定义纯 Swift 协议 `LaunchAtLoginServiceProtocol`，解耦真实系统调用与业务协调器；
   - 提供 `MockLaunchAtLoginService` 用于单元测试与 Preview，杜绝自动化测试污染宿主机登录项。

### 3.2 非目标

1. **不修改系统管理员级别的后台守护进程**：不开设全局 Root 服务，不接管系统底层调度。
2. **macOS 端不采用已废弃的旧 API**：不使用过时的 `SMLoginItemSetEnabled` 或已废弃的 AppleScript / Login Items 列表操作。
3. **本期不落地 Windows 端代码实现**：Windows 端自启动（基于 Tauri autostart 插件或注册表 `Run` 键）留待 Windows 专属里程碑推进，本设计仅预留配置契约兼容性。

### 4.2 核心业务规则

<!-- @topic: LaunchAtLogin -->

#### R1 状态映射与协议抽象

1. **状态枚举定义**：
   ```swift
   public enum LaunchAtLoginStatus: Equatable, Sendable {
       case enabled            // 已在系统登录项中启用
       case notRegistered      // 未注册自启动
       case requiresApproval   // 系统设置中被用户或策略禁用，需人工批准
       case unavailable(String)// 开发环境/非 Bundle 模式下不可用
   }
   ```
2. **协议契约**：
   ```swift
   public protocol LaunchAtLoginServiceProtocol: Sendable {
       var status: LaunchAtLoginStatus { get }
       func register() throws
       func unregister() throws
       func openSystemSettings()
   }
   ```
3. **真实系统实现 (`SystemLaunchAtLoginService`)**：
   - 映射 `SMAppService.mainApp.status`：
     - `.enabled` $\rightarrow$ `.enabled`
     - `.notRegistered` $\rightarrow$ `.notRegistered`
     - `.requiresApproval` $\rightarrow$ `.requiresApproval`
     - `.notFound` $\rightarrow$ `.unavailable("未找到可注册的应用包")`
     - 其余情况回落 `.notRegistered`；
   - 注册：`try SMAppService.mainApp.register()`；
   - 注销：`try SMAppService.mainApp.unregister()`；
   - 打开系统设置：`SMAppService.openSystemSettingsLoginItems()`。

#### R2 配置持久化与平滑迁移

1. **`OnboardingConfiguration` 扩展**：
   - 新增可选字段 `public var launchAtLogin: Bool?`；
   - 默认值：`nil`（表示未显式配置，由系统真实状态为准，新安装时默认关闭）；
   - 自定义 `init(from decoder:)`：使用 `decodeIfPresent(Bool.self, forKey: .launchAtLogin)`，旧版本配置缺失该键时平滑保持 `nil`，绝不因新增字段拒绝加载；
   - `CodingKeys` 明确包含 `case launchAtLogin`。
2. **协调器状态同步策略**：
   - 初始化时优先读取 `launchAtLoginService.status`；
   - 当调用 `coordinator.setLaunchAtLogin(enabled: Bool)` 时：
     1. 若 `enabled == true`，调用 `service.register()`；若成功，更新本地 `config.launchAtLogin = true`；
     2. 若 `enabled == false`，调用 `service.unregister()`；若成功，更新本地 `config.launchAtLogin = false`；
     3. 若抛出异常或状态为 `.requiresApproval`，捕获并更新 `launchAtLoginStatus`，向界面回显友好提示，不破坏其它配置持久化。

#### R3 界面呈现与交互契约

1. **设置中心「通用」面板**：
   - 位于「界面动效」与「仪表盘卡片布局」之间，或者紧邻系统级行为区；
   - 标题：“开机自启动”，副标题：“开机时自动启动 Bruce 并在后台驻留菜单栏”；
   - 右侧渲染标准 `.toggleStyle(.switch)`；
   - 若状态为 `.requiresApproval`，在开关旁呈现黄色预警提示「需在系统设置中允许」，附中性次按钮「打开系统设置」调用 `service.openSystemSettings()`。
2. **首次启动欢迎向导 Step 3**：
   - 位于「快捷偏好行」区，与「仅显示双环图标」及「全局唤出热键」形成协调的三偏好卡片组；
   - 标题：“开机自动运行”，副标题：“随系统启动常驻菜单栏”；
   - 采用与其他 Step 3 偏好卡一致的卡片风格（`SettingsDemoTokens.surface` + 8pt 圆角 + 描边），右侧放置 Switch。
