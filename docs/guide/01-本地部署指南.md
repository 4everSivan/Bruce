## 一、环境准备

### 1. 系统与运行时依赖
- 操作系统支持：macOS / Linux
- 运行环境与版本要求（根据具体技术栈配置）：
  - Node.js / Python / Go / Rust 等版本说明

### 1.1 Windows 平台 (apps/win)

- 依赖: Rust (MSVC)、WebView2；前端为静态资源，无 Node 构建步骤，执行前端回归测试时需要 Node。
- 构建: `powershell -ExecutionPolicy Bypass -File scripts/build-win-app.ps1`, 产物 (NSIS 安装包/裸 exe + SHA256) 收拢 `local/dist`。
- 数据位置: 凭证 `%APPDATA%\Bruce\credentials.json`、设置 `%APPDATA%\Bruce\config\settings.json`、快照 `%APPDATA%\Bruce\snapshot.json`、月度账本 `%APPDATA%\Bruce\usage-ledger\`、缓存 `%LOCALAPPDATA%\Bruce\collector-cache-v1`。macOS 上调试 Windows 壳使用 `~/Library/Application Support/Bruce-Windows-Dev`，不读取原生 mac App 凭证。
- 配置入口: 看板「设置」与托盘「设置」使用同一配置。默认全局热键为空；录制或输入组合键后保存，系统注册失败会返回错误并保留旧配置。设置窗口关闭时隐藏，可从托盘再次打开。
- 首次授权: 在「授权与隐私」勾选订阅查询同意并保存，再启用需要的 Provider、录入账号或明确选择 Codex `auth.json` 导入。凭证存在不等于允许出站；关闭同意后停止订阅查询。
- 本地验证（不启动应用、不读取真实凭证）：

```powershell
$env:CARGO_TARGET_DIR = Join-Path (Get-Location) 'local\c009\target'
$env:TEMP = Join-Path (Get-Location) 'local\c009\tmp'
$env:TMP = $env:TEMP
New-Item -ItemType Directory -Force $env:TEMP | Out-Null
node scripts/check-win-frontend.mjs
cargo test --manifest-path apps/win/src-tauri/Cargo.toml --no-default-features --locked
```

预期各命令退出码为 0、Node 与 Cargo 输出测试通过。该验证覆盖控制 DOM 与 Rust 逻辑；系统窗口焦点、热键冲突、Toast、实际 SID ACL 及真实 Agent 路径须在 Win10/11 验收并记录到 C009/T02/T03，不能用 mac 编译结果代替。

### 2. 端口规划与隔离约定
- 本地调试默认端口：`8080`（或按项目自定义）
- 隔离目录：所有本地数据、运行时日志、临时文件全量写入 `local/` 目录

---

## 二、配置与环境变量

创建本地环境配置文件 `.env`（严禁提交至 Git）：

```bash
# 本地服务端口
PORT=8080

# 数据与日志路径（收拢于 local/）
DB_PATH=local/data/app.db
LOG_PATH=local/logs/app.log
```

---

## 三、启动与部署步骤

### 1. 安装依赖
```bash
# 安装项目依赖
npm install # 或 pip install / go mod download / cargo build
```

### 2. 服务启动
```bash
# 启动本地服务
npm run dev # 或 python -m app.main
```

---

## 四、部署报告产出规范（必填）

部署成功后，**必须在 `local/` 目录下生成 `local/deploy_report.md`**：

```markdown
# 本地部署验收报告 (deploy_report.md)

| 监控项 | 采集值 |
|---|---|
| 生成时间 | 2026-09-23 HH:MM:SS |
| Git 分支 / 提交 | main / <commit_hash> |
| 实际监听端口 | 8080 |
| 实际数据库路径 | local/data/app.db |
| 日志文件 | local/logs/app.log |
| 健康检查端点 | http://127.0.0.1:8080/health |
```

> ⚠️ **红线提醒**：后续所有自动化测试与重新部署均参考 `local/deploy_report.md` 实际运行数据执行，严禁抛开报告重新翻阅本指南！
