# 订阅额度查询设计

订阅额度模块将宿主注入的账号凭据转换为账号服务计划，通过服务商接口查询窗口或余额，再装配为 `artifact.services`。它处理服务端额度，不使用本地会话费用复刻订阅消耗；凭据保存、账号登录和定时重试由宿主承担。

## 1. 目标与职责

本模块把账号计划变成服务端窗口或余额，返回单账号状态及诊断。宿主负责决定是否查询、凭据保存与跨轮历史保留；Provider 内只执行有限的协议兼容和续期尝试。


<a id="chapter-2"></a>
## 2. 对外契约

<a id="quota-contract"></a>
### 2.1 责任与外部契约

应用编排由 `collect_quota_usage()` 进入，先调用 `build_account_plan()`，再执行 `execute_quota_accounts()`。服务商适配器实现统一接口：

```rust
fn query(
    &self,
    request: &ProviderRequest,
    http: &dyn HttpClient,
    cancellation: &CancellationToken,
) -> Result<Option<Value>, ProviderError>;
```

`ProviderRequest` 包含原账号 ID、采集时间、HTTP 超时、响应体上限和可选凭据。返回 `Ok(Some(...))` 表示有可归一化数据，`Ok(None)` 表示合法空态，`Err(...)` 表示查询失败。`HttpClient` 是可注入边界，生产实现 `UreqHttpClient` 仅接受 HTTPS；测试可以替换请求结果。

服务条目先由 `service_template()` 创建，包含 `id`、`name`、`app`、`isCurrent`、`status`、`kind`、`plan`、`windows`、`balance`、`currency`、`capturedAt` 和 `note`。`finalize_service()` 将解析结果合入模板：`kind=windows` 但无窗口时设为 `empty`，无数据也为 `empty`，请求失败为 `error`。窗口使用 `label`、`usedPercent`、`windowMinutes`、`resetsAt`，其中重置时刻通常归一为 Unix 秒；Codex 解析器直接保留接口 `reset_at` 的值。

依据：[`collector-provider/src/lib.rs`](../../core/collector/crates/collector-provider/src/lib.rs) 的 `QuotaProvider`、`ProviderRequest`、`HttpClient`、`service_template()`、`finalize_service()`、`window()`；[`collector-application/src/lib.rs`](../../core/collector/crates/collector-application/src/lib.rs) 的 `collect_quota_usage()`。

## 3. 内部结构

<a id="account-plan"></a>
### 3.1 账号目录与顺序

`CATALOG_SPECS` 是服务商 app ID、服务 ID 前缀与凭据字段的共同来源。普通服务商先按目录定义顺序遍历，再按账号 ID 排序；服务 ID 由前缀加原账号 ID 组成。显示名来自 `display_name`，缺失时使用品牌名和账号 ID 前八个字符。Claude 与 Grok 在没有多账号条目且 `providerMeta.<app>.enabled=true` 时，可生成直接服务条目，使用 `claudeOAuth` 或 `grokOAuth`。

| app ID | 多账号凭据字段 | 服务 ID 前缀 |
|---|---|---|
| `opencode-go` | `opencodeGoQuotaAccounts` | `opencode_go_` |
| `kimi` | `kimiQuotaAccounts` | `kimi_coding_` |
| `deepseek` | `deepseekQuotaAccounts` | `deepseek_` |
| `zhipu` | `zhipuQuotaAccounts` | `zhipu_` |
| `volcengine` | `volcengineQuotaAccounts` | `volcengine_` |
| `claude` | `claudeQuotaAccounts` | `claude_` |
| `grok` | `grokQuotaAccounts` | `grok_` |
| `stepfun` | `stepfunQuotaAccounts` | `stepfun_` |
| `jev` | `jevQuotaAccounts` | `jev_` |
| `cline` | `clineQuotaAccounts` | `cline_` |

Codex 通过独立计划加入上述目录结果末尾。`codexQuotaAccounts` 必须同时携带 `context.codexQuotaAccountOrder`，两者账号集合必须相同、顺序数组不得重复，账号数量为 1 至 64。每个账号只接受非空 `access_token` 和 `display_name`；原账号 ID 用于请求头 `chatgpt-account-id`，服务 ID 为 `codex_` 加 SHA-256 十六进制摘要的前 16 位。Codex 结果保留宿主注入顺序。

依据：[`collector-provider/src/lib.rs`](../../core/collector/crates/collector-provider/src/lib.rs) 的 `CATALOG_SPECS`、`resolve_service_catalog()`、`codex_service_id()`；[`collector-application/src/account.rs`](../../core/collector/crates/collector-application/src/account.rs) 的 `build_account_plan()`、`build_codex_account_plans()`、`credential_for_service()`；[`collector-bridge/src/lib.rs`](../../core/collector/crates/collector-bridge/src/lib.rs) 的 `validate_codex_request()`。

## 4. 详细设计

<a id="provider-adapters"></a>
### 4.1 服务商适配口径

| 服务商 | 凭据与查询入口 | 归一结果与边界 |
|---|---|---|
| Kimi | Bearer API Key；`api.kimi.com/coding/v1/usages` | `limits[].detail` 形成 5 小时窗口，`usage` 形成 7 天窗口 |
| DeepSeek | Bearer API Key；`api.deepseek.com/user/balance` | 取 `balance_infos` 第一项余额，缺少列表为空态，币种缺失默认 `CNY` |
| Z.ai | API Key 与 `base_url`；BigModel 或 Z.ai 额度路径 | 根据 `base_url` 是否包含 `bigmodel.cn` 选择固定主机，解析额度窗口 |
| 火山引擎 | `accessKeyId`、`secretAccessKey`；签名 OpenAPI | 尝试 `GetCodingPlanUsage` 与 `GetAFPUsage`，兼容不同额度响应形态 |
| Claude | `claudeAiOauth` 或 `claude.ai_oauth` 下的 `accessToken`；OAuth usage 接口 | 顶层窗口与模型专属周窗口，支持额外用量独立行 |
| Grok | OAuth `key`，兼容当前 OIDC scope 与旧 sign-in scope；gRPC-web POST | 从二进制账单响应解析窗口，不能按普通 JSON 接口替换 |
| OpenCode GO | `auth` Cookie、`workspaceId`；`opencode.ai/_server` | 解析服务端序列化响应，有限重试两次 |
| Codex | `access_token` 与原账号 ID；`wham/usage` | 主、次窗口、计划与 Credits；不在 Collector 内刷新 Codex OAuth |
| StepFun | Token；国内或国际站额度与刷新端点 | 解析 Credits 与时间窗口，双段 Oasis Token 可刷新并回传凭据更新 |
| Jev | Bearer API Key；模型列表接口 | 验证模型响应并输出 `kind=balance`；余额只取注入凭据的 `balance`，接口本身不提供该余额 |
| Cline | Bearer API Key；plan 与 usage-limits | 直接读取服务端 5 小时、周、月窗口，不在客户端翻页建模 |

Jev 适配器的存在不表示客户端会展示它；原订阅设计明确保留底层适配、在界面隐藏。该模型列表接口不提供真实余额。

依据：[`collector-provider/src/lib.rs`](../../core/collector/crates/collector-provider/src/lib.rs) 的 `provider_for_app()`、各 Provider 的 `query()` 与 `parse_*` 函数；[原订阅设计](../devel/design/02-订阅额度与凭据安全存储.md) 的 Jev 展示范围。

<a id="claude-windows"></a>
### 4.2 Claude 模型窗口

`parse_claude_usage()` 先处理顶层窗口：只接受包含可解析 `utilization` 的对象，逐项跳过坏数据；已知窗口按 5 小时、总周额度、Fable、Opus、Sonnet 排序，未知窗口稳定排在后面。百分比限制在 0 至 100。

`limits[]` 仅接受 `kind=weekly_scoped`、`group=weekly`、`scope.surface` 缺失或为 null 的模型周额度。模型 `display_name` 去首尾空格并转小写后，仅识别 fable、opus、sonnet；`percent` 须为非负 JSON 数值，`resets_at` 只接受字符串、null 或缺失。有效的同模型第一项优先，覆盖同名顶层旧窗口；不使用 `is_active` 过滤。`extra_usage.is_enabled=true` 且利用率可解析时追加“额外用量”独立行。

依据：[`collector-provider/src/lib.rs`](../../core/collector/crates/collector-provider/src/lib.rs) 的 `CLAUDE_TIERS`、`parse_claude_usage()`；[原订阅设计](../devel/design/02-订阅额度与凭据安全存储.md) 的 Claude 用量响应解析口径。

<a id="cline-windows"></a>
### 4.3 Cline 服务端窗口

`ClineProvider` 先请求 `/users/me/plan`。只有 `cline_pass_entitled()` 返回真才请求 `/users/me/plan/usage-limits`，正常 Pass 查询因此是两次 GET，非 Pass 路径在第一步返回空态。三类窗口直接读取 `percentUsed` 和 `resetsAt`，`five_hour`、`weekly`、`monthly` 分别标记 300、10080、43200 分钟；未知类型跳过。缺少 `data.limits` 或已知窗口的百分比无法解析时返回错误，不从旧台账重建数值。

原设计要求三个动态阈值均为正。当前 `cline_pass_entitled()` 对三个阈值使用 `filter_map(...).all(...)`：会跳过缺失或不可解析的值，只检验实际解析出的值是否为正；因此不能把它当作三字段完整性校验。它同时要求存在 `entitlements.cline_pass` 和 `inferenceCapThreshold`，且没有显式 `enabled=false`。

额度解析不注入 `canceledAt`、`cancelAt` 生命周期注记。过去的逐单台账缓存和客户端窗口推算不属于当前查询路径；服务端窗口端点失败会显式产生服务错误，后续刷新重新直读。

依据：[`collector-provider/src/lib.rs`](../../core/collector/crates/collector-provider/src/lib.rs) 的 `ClineProvider::query()`、`cline_pass_entitled()`、`parse_cline_usage_limits()`；[原订阅设计](../devel/design/02-订阅额度与凭据安全存储.md) 的 Cline 三窗口规则。源码测试 `cline_provider_reads_server_usage_limits` 定义两次 GET、服务端百分比与时间转换的预期。

<a id="host-quota-policy"></a>
### 4.4 宿主额度策略与跳过行为

macOS 的刷新流水线先读取历史工件，通过 `QuotaRefreshPolicy` 决定本轮是否包含额度查询及跳过哪些 Provider。`localUsageOnly=true` 时 Collector 不产生额度服务或未授权占位；`quotaSkipProviders` 则在 `build_account_plan()` 中过滤账号计划，未查询服务由宿主按策略回填。普通未授权请求仍沿用其占位语义，不能与主动本地专用请求混淆。

查询尝试时间、429 冷却和旧服务新鲜度由 `QuotaCarryOverMerger` 管理。账号被查询但结果中缺席时不会因为存在旧快照就自动复活。具体手动、窗口边界和多账号优先级见[刷新生命周期设计](刷新生命周期设计.md)，这些 macOS 调度策略不能直接推定已接入 Windows。

依据：[`QuotaRefreshPolicy.swift`](../../apps/macos/Sources/BruceAppCore/QuotaRefreshPolicy.swift)；[`collector-application/src/account.rs`](../../core/collector/crates/collector-application/src/account.rs) 的 `build_account_plan()`、`quota_skip_apps()`；[`collector-application/src/lib.rs`](../../core/collector/crates/collector-application/src/lib.rs) 的本地专用分支。


<a id="claude-refresh"></a>
### 4.5 Claude OAuth 续期与重试

`parse_claude_oauth_credentials` 从嵌套 OAuth 条目读取 accessToken、refreshToken、expiresAt、scopes。到期值大于 100000000000 时按毫秒转秒，否则按秒处理；没有到期值时不主动刷新。若存在 refreshToken，且采集时刻距到期不超过 60 秒，先 POST `/v1/oauth/token`，再使用有效 Token GET `/api/oauth/usage`。

刷新使用 refresh_token 授权类型、固定客户端 ID 与 User-Agent；scopes 非空时空格连接，否则使用实现中的默认 scope。成功响应必须含非空 access_token；缺少 refresh_token 时保留旧值，缺少整数 expires_in 时默认 28800 秒。到期时间以本轮 capturedAt 的 epoch 加 expires_in 计算。

主动刷新失败被忽略，仍用旧 Token 查询。仅当尚未成功刷新、查询返回 `PROVIDER_AUTH_REJECTED` 且存在 refreshToken 时，再尝试一次刷新；成功后重查 usage。已经主动刷新成功后，即使查询再遇 401 也不循环刷新。401 续期失败时保留原查询错误，403、429 和传输失败不走此鉴权重试分支。

控制路径如下，出口“返回查询结果”还须经过原有服务归一与诊断处理。

![Claude到期预刷新、401补救和查询结果返回的条件分支](../assets/km/claude-oauth-refresh.svg)

图：Claude 查询内的有限续期。主动刷新和 401 补救可能都被尝试，但首次成功刷新后不再触发第二次成功刷新。

成功刷新且 usage 是对象时才附加内部 `credential_update`，随后被应用层提取到封套。刷新成功但 usage 查询失败或返回 None 时，不会输出轮换更新。按源码推演，50 秒后到期且刷新成功会执行 POST→GET；未到期但 GET 返回 401 时执行 GET→POST→GET。缺 refreshToken 的同一 401 直接作为服务失败返回，其他账号仍可完成。

依据：[`collector-provider/src/lib.rs`](../../core/collector/crates/collector-provider/src/lib.rs) 的 `ClaudeProvider::query`、`is_claude_token_expired`、`refresh_claude_token`、`query_claude_usage`；其中 `claude_provider_proactively_refreshes_expired_token`、`claude_provider_refreshes_token_on_401_and_retries` 定义 Mock 预期。

## 5. 流程与状态

<a id="account-execution"></a>
### 5.1 请求执行与故障隔离

账号请求和归一结果按计划槽位汇总，关系如下。

![账号计划经受限工作线程与Provider适配后按原序汇总](../assets/km/quota-account-flow.svg)

图：多账号额度执行。单个服务错误仍进入其结果槽位，不覆盖其他账号结果。

额度任务最多启动 4 个账号工作线程；每个账号先经同账号请求合并器（`AccountSingleFlight`）处理，再获取凭据与网络许可。同一运行中重叠执行的同一账号共享一次结果；执行完成后移除该合并项，后续调用可重新执行。跨次 Collector 运行不共享这份状态。结果按计划索引写入槽位，最后按计划顺序汇总，因此完成先后不改变服务顺序。

凭据来自 `AccountPlan.credential`。当前应用路径不调用宿主钥匙串或外部文件回退；Claude、Grok 缺少注入凭据时产生 `CREDENTIAL_MISSING`。`collector-credential` 中保留的兼容读取函数不能据此当作生产额度链路的调用行为。

每次 HTTP 请求使用请求中的 `externalRequestSeconds`，响应体上限默认 4 MiB；模块共享 `moduleSeconds` 截止时间。401 在携带鉴权错误文案的请求中映射为 `PROVIDER_AUTH_REJECTED`，403 为 `PROVIDER_PERMISSION_DENIED`，429 为 `PROVIDER_RATE_LIMIT`，5xx 为 `PROVIDER_SERVER_ERROR`。传输、非法 JSON、形状不兼容与超大响应有各自错误码，诊断不回显凭据内容。

单个服务失败通常保留其他成功服务及本地数据；服务级 `partial/error` 会附加 `COLLECTOR_PARTIAL_RESULT`。Collector 不提供统一的持续退避循环；重试与刷新时间需要宿主处理。适配器内部存在有限兼容尝试，例如 OpenCode GO 最多两次请求、火山引擎尝试接口与密钥候选、StepFun 刷新后重试，不能把所有服务描述成“一账号一次 HTTP”。

依据：[`collector-application/src/execution.rs`](../../core/collector/crates/collector-application/src/execution.rs) 的 `execute_quota_accounts()`、`execute_one()`、`execute_one_uncached()`、`resolve_credential()`；[`collector-provider/src/lib.rs`](../../core/collector/crates/collector-provider/src/lib.rs) 的 `send_response()`、`bounded_http_body()` 与各 Provider 的 `query()`；[`collector-runtime/src/lib.rs`](../../core/collector/crates/collector-runtime/src/lib.rs) 的 `RuntimeLimits` 和 `AccountSingleFlight`。

## 6. 异常与恢复

<a id="credential-updates"></a>
### 6.1 凭据更新、挑战与安全边界

StepFun 双段 Token 使用 `...` 分隔。访问段的 `exp` 距采集时刻不超过 30 秒时，适配器先尝试刷新；未成功刷新且查询返回鉴权拒绝或远端拒绝时，再尝试刷新并重查。刷新成功且查询返回可用结果时，内部结果附加 `credential_update`，应用层将其从服务数据中移除，转为封套中的 `credentialUpdates`。

更新对象固定包含 `provider`、`accountId`、`kind=oauthTokens`、`operation=replace`、`credentials`；当前输出校验只接受 `kimi`、`stepfun` 与 `claude`，凭据子字段只接受 `access_token`、`expiry`、`id_token`、`refresh_token` 的字符串值。校验失败时 Bridge 返回错误封套，不发布该轮 artifact。当前 StepFun 查询会产生更新；接受 Kimi 更新并不表示 Kimi API Key 查询实现了 OAuth 刷新。

Codex 只有遇到 `PROVIDER_AUTH_REJECTED` 且账号 ID 存在时才发出 `credentialChallenges`，内容为 `provider=codex`、`accountId`、`reason=accessRejected`。403 权限拒绝、429 或网络失败不发重新授权挑战。Codex 服务失败时移除 `capturedAt`，并设置 `freshness=unavailable` 和 `failureKind`；成功则为 `fresh`。这些字段用于宿主区分新鲜结果与失败，不在 Collector 内保存上一轮服务快照。

stdin 和 stdout 是宿主与子进程间的私有凭据通道。`artifact` 与诊断不应承载 Token，但合法的 `credentialUpdates` 确实含新 Token，不能把整个 Bridge 响应作为公开报表或无差别日志。原订阅设计中“stdout 仅返回脱敏指标”的表述没有涵盖当前更新通道。

依据：[`collector-provider/src/lib.rs`](../../core/collector/crates/collector-provider/src/lib.rs) 的 `StepFunProvider::query()`、`is_stepfun_token_expired()`、`refresh_stepfun_token()`；[`collector-application/src/execution.rs`](../../core/collector/crates/collector-application/src/execution.rs) 的 `credential_update` 提取、`codex_challenge()`、`finalize_codex_service()`；[`collector-credential/src/lib.rs`](../../core/collector/crates/collector-credential/src/lib.rs) 的 `validate_credential_updates()`、`validate_credential_challenges()`；[`collector-bridge/src/lib.rs`](../../core/collector/crates/collector-bridge/src/lib.rs) 的 `validate_response_credentials()`。
