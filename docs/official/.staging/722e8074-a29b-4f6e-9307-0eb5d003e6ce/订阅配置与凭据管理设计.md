# 订阅配置与凭据管理设计

订阅配置模块管理 Provider 的非敏感设置、账号发现、凭据录入与刷新输入。生产装配以受权限保护的本地文件保存 Bruce 自有凭据，保留 Keychain 兼容读取；外部 CLI 凭据另走只读边界，实际额度查询由 Collector 执行。

## 配置、凭据与账号的边界

`OnboardingCoordinator` 接收设置页动作，把凭据保存、导入和验证委托给 `SubscriptionService`。`ProviderRegistry` 为每个 `SubscriptionProviderID` 登记凭据键、Bridge 注入类型和“已配置”判定规则。Provider 已列入配置、凭据可用、验证通过和允许刷新分别有自己的判据。

| 数据 | 存储或接口 | 含义 |
|---|---|---|
| 用户偏好、统一同意、Provider 状态 | `config/onboarding-v1.json` | 非敏感配置，包含刷新周期、主题、价格覆盖和访问配置 |
| Bruce 自有凭据 | `credentials.json` | `ProtectedFileCredentialStore` 的账户键到字符串映射 |
| 多账号索引与记录 | `CodexCredentialStore`、`ProviderAccountStore` | 在凭据存储抽象上组织账号元数据和完整记录 |
| 外部 Claude/Grok 登录态 | `ExternalCredentialReader.read(source:intent:)` | 只读外部来源，不回写 CLI 凭据 |
| 单次运行输入 | `CollectorRunInput` 的 `context`、`credentials` | 注入 Collector 的瞬时输入，不作为 UI 数据模型 |

`CredentialStore` 提供 `saveCredential(_:forAccount:)`、`loadCredential(forAccount:)` 和 `deleteCredential(forAccount:)`；意图感知接口区分后台自动操作和用户主动操作。UI 发布账号摘要、验证状态和存储健康，不以原始凭据 JSON 驱动呈现。

依据：[`OnboardingCoordinator.swift`](../../apps/macos/Sources/BruceApp/OnboardingCoordinator.swift) 的凭据操作委托；[`ProviderRegistry.swift`](../../apps/macos/Sources/BruceOnboardingCore/ProviderRegistry.swift) 的 `ProviderDescriptor`、`ConfiguredRuleEvaluator`；[`OnboardingConfiguration.swift`](../../apps/macos/Sources/BruceOnboardingCore/OnboardingConfiguration.swift) 的存储协议与实现；[`AppModel.swift`](../../apps/macos/Sources/BruceAppCore/AppModel.swift) 的账号摘要与状态字段。

## 文件存储与兼容读取

配置默认位于 `~/Library/Application Support/Bruce/config/onboarding-v1.json`，由 `OnboardingConfigurationStore` 串行读取和原子保存。保存使用 `AtomicJSONStore`，文件权限为 `0600`，目录权限为 `0700`，写入后重读验证并保留上一版本备份。新版本 schema 保守拒绝；损坏配置尝试备份回滚，不可读或无法恢复时返回默认配置。

`ProtectedFileCredentialStore` 默认写入 `~/Library/Application Support/Bruce/credentials.json`。写入创建权限为 `0600` 的临时文件，写入并同步后重读解码，备份旧文件，再替换或移动到目标并复位权限。父目录创建为 `0700`；已有目录的权限校正是尽力执行。该文件保存凭据字符串，保护依赖本机文件权限，并未实现文件内容加密。

读取区分不存在和损坏：不存在返回空 payload；读入或解码失败时尽力将原文件移动为带时间戳的损坏副本并抛错，避免空数据覆盖现场。文件中没有某个账户键时，可以从装配的 Keychain fallback 读取并迁移到文件；迁移写盘失败上抛。类名和配置字段保留了 Keychain 字样；生产装配的主存储是受保护文件。

依据：[`BruceApp.swift`](../../apps/macos/Sources/BruceApp/BruceApp.swift) 的 `ProtectedFileCredentialStore` 装配；[`OnboardingConfiguration.swift`](../../apps/macos/Sources/BruceOnboardingCore/OnboardingConfiguration.swift) 的 `OnboardingConfigurationStore`、`ProtectedFileCredentialStore.loadPayloadLocked()`、`writePayloadLocked()`、`loadCredential`。

## 统一同意与调度门控

`CollectorActivationGate.canActivate(module:readiness:isModuleSelected:appIsAcceptingNewTasks:keychainAccessConfigured:)` 默认拒绝。当前 `agentUsage` 模块需要同意版本匹配、用户选中、Bruce 存储允许自动访问、应用接受任务，以及就绪度为 `ready` 或 `partial`。撤销同意清除已确认版本并重新协调，模块转为禁用。

输入提供器还有第二道检查：`agentUsageInput()` 要求 Bruce 自有存储允许 `.automatic`，否则返回 `missingAuthorization`，进程不启动。通过后先授予本地会话和本地价格能力，按已启用 Provider 装配凭据；配置已有同意版本且装配结果非空时，才加入 `externalQuotas`。版本的精确匹配由前面的激活门控负责。

`KeychainAccessPolicy` 中，Bruce 自有存储的自动访问要求状态为 `allowed` 且存储版本就绪，用户主动配置可以进入准备流程。外部来源策略要求状态允许且来源在白名单；当前 Claude 读取器有专门例外，见下节。访问策略、Provider 启用状态和面板验证过滤分别作用于存储、运行输入和展示层。

依据：[`CollectorActivationGate.swift`](../../apps/macos/Sources/BruceOnboardingCore/CollectorActivationGate.swift)；[`OnboardingCoordinator.swift`](../../apps/macos/Sources/BruceApp/OnboardingCoordinator.swift) 的 `confirmConsent`、`revokeAllConsent`、`reconcileScheduler`；[`CollectorRunInput.swift`](../../apps/macos/Sources/BruceAppCore/CollectorRunInput.swift) 的 `agentUsageInput`、`requireAutomaticKeychainAccess`；[`KeychainAccessPolicy.swift`](../../apps/macos/Sources/BruceOnboardingCore/KeychainAccessPolicy.swift)。

## Claude 与 Grok 的外部读取

Claude 每次读取都先静默查询 `Claude Code-credentials` Keychain 条目。查询同时设置 `LAContext.interactionNotAllowed = true` 和 `kSecUseAuthenticationUISkip`，不受外部来源白名单或共享策略状态的前置阻断。条目不存在或系统要求交互时返回空并回退 `~/.claude/.credentials.json`；其他 Keychain 错误抛出读取失败。外部条目被阻断不会调用 `markBlocked()` 污染 Bruce 自有存储策略。

Grok 自动读取仍要求外部来源白名单和允许状态，然后读取 `~/.grok/auth.json`。`LocalCredentialProbe` 只读探测本机登录态，`SubscriptionService` 发布可用标记。Claude 的本机“检测到”包含 `valid`、`refreshPending` 和 `expired`，因此该标记不等于联网认证成功。

运行输入优先使用已存多账号记录；没有记录时才尝试 CLI 跟随。Claude 显式“从本机导入”走同一静默读取顺序，再经 `ClaudePasteParser` 规范化并保存到 Bruce。解析器保留 OAuth 条目全部字段，仅规范包装形式并修剪 `accessToken`；兼容 `claudeAiOauth`、`claude.ai_oauth`、条目本体及纯 token 输入。`saveClaudeOAuthJSON` 依据本地有效期分类处理，`valid` 或 `refreshPending` 可以入库，`expired` 提示重新登录。这一路径的 `.ok` 是本地判定，不是实际远端查询结果。

## Codex 账号发现、登录与 token 决议

Codex 从 CLI `~/.codex/auth.json` 或 CC Switch 账号库导入时只保存发现的账号元数据，标为需要重新授权，不导入外部 token。已配置判定要求存在完整凭据记录，只有索引或账号名称不够。

用户发起设备码登录后，`SubscriptionService` 启动授权、打开验证页、轮询并交换结果，成功时由 `CodexTokenManager.storeLoginResult` 保存 Bruce 自有 token 链。该管理器对外提供 `validAccessToken(for:now:)` 和 `refreshAfterAccessRejected(for:now:)`，把存储及刷新决议委托给 resolver。输入只向 Collector 提供可用账号的短期 access token；refresh token 留在 Swift 凭据管理边界。

启动时，仅已启用 Codex 才执行旧库迁移。损坏 JSON、schema 不兼容或迁移失败会暂停 Codex 外部额度，不阻断本地统计。查询遇到符合条件的账号挑战时，刷新流水线可经 token manager 做定向恢复，随后合并账号状态和上一份额度，详见[刷新生命周期](刷新生命周期设计.md)。

依据：[`SubscriptionService.swift`](../../apps/macos/Sources/BruceApp/SubscriptionService.swift) 的 `importCodexFromLocalCLI`、`importCodexFromCCSwitch`、`loginCodexNewAccount`；[`CodexTokenManager.swift`](../../apps/macos/Sources/BruceOnboardingCore/CodexTokenManager.swift)；[`CollectorRunInput.swift`](../../apps/macos/Sources/BruceAppCore/CollectorRunInput.swift) 的 `setCodexMigrationResult`、`resolveCodexQuotaAccounts`；[`ApplicationBootstrap.swift`](../../apps/macos/Sources/BruceApp/ApplicationBootstrap.swift) 的 `prepareKeychainBackedStartup`。

## 失败与安全边界

凭据解析失败、存储失败和需要重新登录分别写入所属 Provider 的错误状态；UI 的保存/导入 busy 集合与额度定向刷新集合分开维护。Collector 返回的凭据轮换由 `CredentialUpdateCoordinator` 在发布工件之前应用，写回失败追加 `CREDENTIAL_PERSIST_FAILED`，存在工件时将成功降级为部分结果。

CC Switch 火山凭据导入使用 SQLite `mode=ro` 和 `SELECT`。外部数据库与 CLI 文件作为只读来源，持久化只写 Bruce 自有存储。Bridge 凭据只经 stdin 发送；Runner 不把它放入命令行参数，子进程仅继承固定最小环境。自动化用例中的解析、门控和账号状态期望不能替代真实服务端有效性或系统授权验收。

依据：[`SubscriptionCredentialImport.swift`](../../apps/macos/Sources/BruceOnboardingCore/SubscriptionCredentialImport.swift) 的 `CCSwitchVolcengineImporter.importCredentials`；[`RefreshExecutionPipeline.swift`](../../apps/macos/Sources/BruceAppCore/RefreshExecutionPipeline.swift) 的 `finishPublishablePath`；[`CollectorRunner.swift`](../../apps/macos/Sources/BruceAppCore/CollectorRunner.swift) 的 `SystemCollectorProcessLauncher.launch`；[`OnboardingClaudeGrokAndConfiguredRuleTests.swift`](../../apps/macos/Tests/BruceOnboardingCoreHarness/OnboardingClaudeGrokAndConfiguredRuleTests.swift) 的解析用例。
