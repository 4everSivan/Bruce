# 模型价格表远端同步设计

Bruce 使用模型价格表将本地采集到的 Token 用量换算为参考费用。应用内置一份基线，也可以下载并启用同步价格表；用户自定义价格覆盖仍参与最终价格决议。同步机制提供手动更新、自动检查和恢复内置基线。

<a id="purpose"></a>
## 目标与职责

价格表同步负责取得远端目录、验证内容和版本，并在保存成功后切换当前活动目录。它更新的是本地费用计算所用的基准价格，不代表服务商的实际扣费账单。同步后的目录仍与用户单独设置的价格覆盖共同参与决议。

<a id="contract"></a>
## 对外契约

远端目录是 JSON，包含 `schemaVersion`、`updatedAt` 和 `models`。macOS 校验要求版本为 `1`、日期文本符合 `YYYY-MM-DD` 或 `YYYY-MM-DD.N` 形式，模型数组非空且不超过 2000 项。模型键、展示名和供应商名称不能为空；模型键按不区分大小写的方式查重；输入、输出及可选缓存读取价格必须为有限非负数。若提供 `cacheWrite`，必须有两个有限正数。`listed` 为 `false` 的模型不进入展示模型列表。

macOS 的默认同步地址为项目配置的 GitHub Raw HTTPS 地址；网络层设置 10 秒请求与资源超时，响应数据超过 512 KiB 时拒绝。Windows 实现也使用 10 秒与 512 KiB 上限，但其传输与错误分类由独立实现处理。以上限制是源码配置，不能保证实际网络请求一定在固定时长内成功。

<a id="structure"></a>
## 内部结构

macOS 由同步服务负责调度、下载和展示状态，由价格目录负责解析、校验与活动目录。目录选择优先使用通过校验且未早于内置基线的同步文件，否则使用编译期内置目录。活动目录是同步来源时，Collector 输入可携带原始价表；内置来源不注入同步价表数据。

Windows 使用独立的同步管理器、价格表解析器和活动目录。管理器将同步状态发布给桌面前端，并在成功同步或恢复内置后请求一次手动刷新，以便重新计算用量。

<a id="mechanism"></a>
## 详细设计

### 下载、校验与版本门禁

同步服务先下载字节，再解析价表并验证字段。`updatedAt` 按日期及可选的数字修订号比较；远端版本早于编译期内置基线时拒绝启用。这个门禁的比较对象是内置基线，不能将它理解为总是拒绝低于当前同步目录的版本。

macOS 若版本、模型数量和各模型的输入、输出、缓存读取价格与当前目录一致，就记录为 `upToDate`；否则计算新增和价格调整数量，先将下载内容原子写入同步文件，再切换内存中的活动目录并通知调用方。该相等比较只检查所列字段，不等于两个 JSON 文件逐字节一致。

Windows 同样先解析和比较内置基线，再判断是否已经是已同步目录的同版本且没有新增或调整；需要更新时先写入临时文件并重命名，再切换活动目录。Windows 的展示差异计算只遍历标为 `listed` 的模型。

### 手动、自动与恢复

macOS 的手动同步在开始时置为 `syncing`，完成后提供已更新、已是最新或失败状态；自动同步失败不显示手动错误。自动检查默认启用，第一次按启动后 30 秒安排，此后按上次自动尝试时间间隔 24 小时；即使自动开关关闭或手动同步正在进行，自动 tick 也会记录本次尝试时间。手动同步不通过这里的 `lastAttemptAt` 调整自动检查时间。

Windows 定时线程启动后等待 30 秒并读取自动同步设置，之后每隔 24 小时再次读取设置。同步管理器使用原子标志避免并发同步；手动失败时发布失败状态，自动失败时不发布手动错误。

用户选择恢复内置时，两个平台都会尝试移除本地同步文件并把内存活动目录切回内置。移除文件操作的失败被忽略，因此“内存已切回”不能证明磁盘文件一定已删除。

<a id="lifecycle"></a>
## 流程与状态

以 macOS 手动同步为例：设置页发起请求后，服务进入 `syncing`；下载和校验通过且版本满足内置门禁后，服务比较当前目录。内容被判定相同时显示 `upToDate`；不同则先保存、再启用、更新展示状态并触发目录更新回调。

macOS 在完成校验和版本门禁后、写盘之前更新 `lastSyncAt`。因此，如果后续写盘失败，这个时间本身不能证明新文件已成功保存或激活。

<a id="failure"></a>
## 异常与恢复

超时、离线、HTTP 错误、格式无效和版本过旧进入相应失败处理；远端内容未通过验证时不会切换为活动目录。macOS 手动同步会显示失败，自动同步失败保持静默。启动加载同步文件时，macOS 对无效文件回退内置目录；过旧文件会尝试删除。Windows 启动加载时对无效或过旧文件尝试删除并回退内置。文件删除都应以实际结果为准。
