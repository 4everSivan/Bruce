# Agent 用量分析设计

macOS 设置中心的 Agent 用量工作台读取已缓存的 `AgentUsageArtifact`，按所选时间范围生成 KPI、模型汇总、趋势和 Agent 对比。`WorkbenchAnalytics` 是本地纯计算入口；它使用工件中的明细和采集端计价结果，不以模型份额或固定单价重新估算缺失数据。本文描述当前源码契约，图表表现与真实数据覆盖还需在目标环境验证。

## 1. 目标

工作台向用户提供今日、近 7 天、近 30 天、本月和全部历史五档观察范围，以及总 Token、费用、缓存收益、活跃 Agent、模型和时间趋势。切换范围只从缓存工件计算快照，不启动新采集；重新检查来源由协调器触发。全部历史受已有工件覆盖范围限制，不代表本机所有历史记录。

<a id="chapter-2"></a>
## 2. 设计

<a id="time-kpi"></a>
### 2.1 时间范围与 KPI

`WorkbenchAnalytics.make` 先收集各 Agent 的 daily 日期并集并排序，取最后一天作为今日；没有日期时取 `generatedAt` 的前十位。近 7/30 天取排序日期的末 7/30 项，本月按今日的年月前缀筛选，全部历史使用日期并集。今日的各类 Token 来自 `today` 桶；其他范围累加选中日期的 daily 桶。daily 的 `input` 是包含缓存读写的展示口径，计算原始输入时减去 `cacheRead` 和 `cacheCreation`，结果不小于零。

明细来源按范围切换：全部历史使用 `monthModels`，其余范围使用日期匹配的 `dailyModels`。费用和缓存收益分别累加明细桶中非空的 `costUsd` 和 `cacheSavingsUsd`；没有明细字段时费用不可用，有明细字段但选中范围无桶时为 0，有桶而相关值全部缺失时为不可用。已定价和未定价 Token 分别按明细的费用是否为空累计。活跃数统计所选范围总量大于 0 的 Agent，最大者并列时保留工件中靠前者。

旧工件缺少选中 daily 的缓存拆分时，`cacheSplitAvailable` 为 false，视图对相应拆分指标显示不可用，不把缺失值解释成真实的缓存为零。今日始终取结构化的 `today` 四类桶。

<a id="model-normalization"></a>
### 2.2 模型归一化与渠道贡献

每个明细桶用 `ModelNormalizer.canonicalKey` 得到规范键，在同一规范键内按原模型名和所属 Agent 下标保留来源。模型按 Token 降序、键升序排列；来源按 Token 降序、原名升序、Agent 顺序排列。模型份额以全部归并明细 Token 为分母，来源份额以该模型的明细 Token 为分母。来源与模型费用只累加已有费用，缺失费用不凭比例补造。

例如，两个 Agent 分别提供映射到相同规范键的 100 与 200 Token，模型汇总为 300，来源分别占该模型约 33.3% 和 66.7%；如果第二条费用为空，模型费用只汇总有值的来源，不能将其当作完整账单。没有明细字段时模型列表为空，即使 daily 总量非零也不会按份额分配。

<a id="analytics-display"></a>
### 2.3 趋势、Agent 与项目下钻

今日趋势按 24 个小时点绘制，近 7 天、近 30 天和本月按日，全部历史按月；支持 Agent、模型、Token 构成和费用维度。模型图只显示所选范围汇总的前五个规范模型，但费用来自全部明细桶。日桶的 Agent 总量取 daily，小时的 Agent 总量取 hours；构成和模型的细分取对应明细。小时明细缺失或日缓存拆分不完整时，相关构成系列不生成。趋势累计费用把未定价桶按 0 累加，不能由曲线金额推断所有桶均已计价。

当前工作树的 Agent 和模型徽章由 `AgentBrandPalette` 按 Agent ID 或模型规范键选择；尺寸至少 14 且非 Nothing 时优先加载位图，否则绘制矢量图形或字标。较小尺寸使用系列色，Nothing 使用单色。位图加载失败时 macOS 回退矢量或字标；这些未提交的资源和源码需在交付前重新核对。

Agent 卡只保留范围内总量大于 0 的 Agent，按 Token 降序并以原顺序消除并列不确定性；模型来自该 Agent 的范围明细。项目分布仅在今日展示，因为工件中的 projects 是今日项目，不把它用于历史范围。

<a id="export"></a>
### 2.4 探针与导出

会话探针展示来源状态，重新检查调用协调器并受采集忙状态约束。CSV 导出当前范围的规范模型汇总，JSON 导出完整已解码 artifact；二者经保存面板选择路径。取消保存不写入，工件不存在、编码或保存失败时提示用户。完整 artifact 可能包含项目和用量信息，分享前应按内容判断。

## 3. 流程

<a id="model-flow"></a>
### 3.1 模型数据归并

![已解码工件按范围选择明细，经规范模型和来源汇总输出模型贡献](../assets/km/analytics-model-flow.svg)

图：模型数据由明细派生；缺少费用不以价格或比例补造。

视图读取 `AppModel.analyticsSnapshot(range:)`：没有可解码工件时返回空快照；有工件时选定日期和明细、累加各 Agent 的原始口径 Token，再分别构造模型、KPI、趋势和 Agent 卡。计算只读输入，不回写原工件或会话文件。价格由采集端写入明细；工作台不再次接收价格覆盖表做二次估算。

<a id="timeline-flow"></a>
### 3.2 时间桶与趋势系列

![所选范围决定小时、日或月的趋势桶及其系列](../assets/km/analytics-timeline-flow.svg)

图：趋势按工件中对应的汇总与细分桶生成。

今日从 `hours` 创建 00:00 至 23:00 的点；有 `hourModels` 时按小时归并模型、构成和费用。历史日点按选中日期读取 daily 与 `dailyModels`；全部历史按选中日期的年月分组，并使用相应 `monthModels` 汇总模型和费用。峰值只在总量大于 0 时出现；相同峰值保留第一个，均值为各点总量的整数平均。24 小时密度条固定汇总今日 hours，与选择的历史范围无关。

<a id="chapter-4"></a>
## 4. 数据与接口

| 输入或输出 | 契约与范围 |
|---|---|
| `today`、`daily`、`hours` | Agent 总量与时间分布；daily 输入含缓存 |
| `dailyModels`、`monthModels`、`hourModels` | 模型、费用和部分趋势细分；字段缺失与空数组有不同含义 |
| `WorkbenchAnalytics.Snapshot` | 范围、KPI、模型、趋势、Agent、今日 24 小时总量 |
| `ModelSourceContribution` | 保留原名、Agent、Token、可选费用和模型内份额 |

跨端 Windows 的分析计算由 Rust 镜像实现，使用同构快照与 golden fixture 对拍；各平台 UI、输入路径和窗口交互仍有各自实现。源码中的对拍用例是测试定义，不是本轮的执行或设备验收记录。

<a id="chapter-5"></a>
## 5. 异常与边界

工件不存在时返回空模型与趋势，并显示零量或占位；旧工件没有明细时不以估算替代模型或费用。部分桶有价而其他桶无价时，已计费用只是可用桶之和。项目不是历史范围内的逐日项目统计。工件含部分来源与诊断时，需要结合来源状态理解覆盖，不能推断本机所有 Agent 都已成功采集。

<a id="chapter-6"></a>
## 6. 验证要点

源码测试定义覆盖日期范围、模型合并、缺失明细、月份边界及跨端 golden 契约。按源码推演：非今日范围有 daily 总量但无模型明细时，Token 仍可显示，模型列表为空且费用不可用；若一日缓存拆分字段缺失，构成系列不应被解释为真实四类构成。本次文档更新没有执行这些测试，也没有验证目标设备上的图表字体、悬停和导出交互。
