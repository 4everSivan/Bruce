# 刷新生命周期设计

macOS 应用装配刷新所需的对象后，一轮刷新依次经过授权门控、调度、Rust 子进程执行和快照发布，最后更新界面模型。`RefreshScheduler` 决定执行时机，`RefreshExecutionPipeline` 编排单次执行的步骤，`CollectorRunner` 管理进程及 Bridge 协议。

## 1. 目标与范围

**功能需求**：用户动作、定时器或系统状态事件都可能触发一轮刷新，本轮以结果发布、不可发布错误或取消收尾。

**方案机制**：用户动作、定时器或系统状态事件触发刷新；结果发布、不可发布错误或取消结束本轮执行。

**边界与非目标**：本文集中说明 macOS 的跨模块主流程，Windows 的独立后台循环由对应平台文档说明。

<a id="chapter-2"></a>
## 2. 参与者与契约

<a id="triggers"></a>
### 2.1 启动与触发

**功能需求**：应用启动时接好回调并启动缓存恢复，调度器按统一同意、模块选择、就绪度和生命周期启用或禁用模块；定时、手动、唤醒和定向意图按规则排程与去重。

**方案机制**：`BruceApp` 装配 runner、快照库、运行输入提供器和共享凭据管理对象。`ApplicationBootstrap.startIfNeeded()` 先接好工件、状态、Provider 刷新及预警回调，再启动调度器读取缓存。配置侧完成扫描后，`OnboardingCoordinator.reconcileScheduler()` 依据统一同意、模块选择、就绪度、自有存储访问状态和应用生命周期启用或禁用模块。

调度支持定时、手动、唤醒/重新激活和 Provider 定向刷新。默认本地刷新与额度新鲜度周期均为 1800 秒；生产协调器初始化或保存间隔后，`updateRefreshInterval` 同时更新两者。唤醒去重窗口为 60 秒，缓存陈旧阈值为 3600 秒，容量上限为 2。启用模块且没有成功时间时，下一次调度延迟为 0；有成功时间时按剩余间隔计算，额度窗口边界可以提前唤醒。唤醒仅刷新已启用、允许自动刷新且到期的模块；运行中或距上次尝试不足去重窗口时不追加补偿，`authRequired` 不自动重试。

**边界与非目标**：当前 `CollectorModule` 只有 `agentUsage`，容量是实现边界，不表示实际有两个业务模块。

<a id="runner-contract"></a>
### 2.2 Bridge 子进程边界

**功能需求**：Runner 以受控参数启动 Collector 子进程，校验响应层次，取消或超时按宽限强制终止，不把迟到 stdout 当作成功。

**方案机制**：`CollectorRunner.run(module:context:credentials:) async throws -> CollectorRunOutput` 先校验可执行路径、同模块互斥与最多 2 个活动进程，再生成 `runId`，把 schema 版本、模块、超时、上下文和凭据编码为 stdin JSON。启动参数为空，环境只保留固定 `PATH`、locale 和临时目录；stdout、stderr 分别在 utility 队列读到结束，避免管道互相阻塞。

正常返回要求退出码为 0、响应可解码、schema 为 1、`runId` 一致，并且非 error 响应必须有工件。stderr 仅转为行数与字节数摘要；错误响应与进程失败是不同层次。默认本地扫描超时 30 秒、外部请求超时 10 秒、模块超时 90 秒；前两者随请求交给 Collector，Runner 自己监控模块超时。

取消或超时先 `Process.terminate()`，默认 2 秒后仍未退出则发 `SIGKILL`。完成时先移出活动任务、取消计时器，再恢复等待 continuation；被请求取消或超时的任务优先返回对应终止结果，不把随后到达的 stdout 当成功。

<a id="chapter-3"></a>
## 3. 流程设计

<a id="offline-quota"></a>
### 3.1 离线暂停与额度查询门禁

**功能需求**：离线时自动意图暂停、手动仍可尝试一次，联网后按暂停标记或陈旧补偿；额度策略在读取上一份工件后形成，跳过的服务由合并器按资格回填。

**方案机制**：`SystemNetworkReachability` 通过 `NWPathMonitor` 维护主线程可达性快照，首个真实回调前视为可用。调度器启动时先接监视，再读缓存和排程；停止时解除回调并停止监视。

离线时，定时、唤醒和退避意图不启动 Collector，也不继续堆积自动重试；直接手动意图仍允许执行一次。在途任务自然收尾，离线失败取消后续退避并设置 `offlinePaused`。网络恢复后，仅对已启用且允许自动刷新、处于 idle/backoff 的模块处理：有暂停标记或已陈旧则补偿一次，否则恢复缺失的正常定时器。`offlinePaused` 是补偿标记，不是新增调度相位。

![离线门禁抑制自动意图，手动可尝试一次，联网后按暂停或陈旧状态补偿](../assets/km/offline-refresh-gate.svg)

图：自动刷新网络门禁。抽象可达性和暂停标记，模块相位仍使用 disabled、idle、running、backoff、authRequired。

额度策略在读取上一份工件后形成。macOS 经进程内静态库 C ABI 调用共享 Rust 策略，传输 `policy-request-v1` / `policy-response-v1` 的 JSON 字节；请求只包含服务数据、时间、间隔和刷新意图，不携带凭据。共享策略按当前启用的 Provider 判断新启用或无历史数据的服务是否需要查询。`quotaRefreshInterval` 由生产协调器与本地 `refreshInterval` 联动设置，默认 1800 秒；429 冷却仍固定为 1800 秒。最近尝试或成功数据距今不足所选周期时可只采本地。多账号仅在全部账号都新鲜时跳过整个 Provider；窗口已重置时即使未到周期也需要重查。直接手动刷新绕过新鲜度与冷却，窗口边界强制刷新对非 Codex Provider 绕过新鲜度但保留冷却约束。Codex 在包含额度的轮次不进入 Provider 跳过集合；全部服务仍新鲜时仍可形成包含 Codex 旧值的本地专用轮次。

![非定向轮次通过进程内策略接口形成额度门禁](../assets/km/macos-quota-policy-sequence.svg)

图：额度门禁的进程内交接，展示非定向轮次从流水线到共享策略的调用与结果；请求或响应失败时不启动采集。

共享 Rust `collector-policy` 按 service ID 回填被策略跳过的服务，并标注实际尝试和限流时间。可保留的失败旧数据、冷却或超龄服务标为陈旧，无合格旧值的失败服务标为不可用；已经查询但缺席的服务不因旧快照而重新出现。本地专用轮次不进入 Codex 恢复与 finalizer，只将上一份 services 合入本地统计工件。

<a id="refresh-sequence"></a>
### 3.2 一次执行的交接顺序

**功能需求**：一轮流水线按读历史、定策略、装配输入、执行采集、条件恢复与回填、应用凭据轮换、发布快照的顺序前进；各阶段失败保留为不同结果类型。

**方案机制**：一次流水线先读取历史并决定额度策略，再按输入、采集、条件恢复、凭据写回和发布前进。图中“输入与凭据”表示职责集合，运行输入提供器和 `CredentialUpdateCoordinator` 是不同对象。

![单次刷新在调度器、输入凭据、Collector 与快照发布之间的顺序](../assets/km/refresh-sequence.svg)

图：单次刷新交互顺序。表示 `RefreshExecutionPipeline` 的主线及条件恢复；额度策略的进程内交接在前一幅图单独展开，不表示已执行的运行记录。

1. **读取上一份工件。** 每轮只从快照库读取一次，失败时用空历史继续；它同时供额度策略和后续失败保留使用。
2. **形成额度策略并装配输入。** 定向范围使用全查询策略与 `scopedRunInput(for:providers:)`；其它范围由 `CollectorQuotaPolicy` 的共享策略决定 `runInput(for:quotaPolicy:)`。门禁策略入口不可用、返回错误或响应无效时，本轮不猜测全查或全跳，而是按采集失败处理并保留上一份工件。采集后的回填或标注策略失败同样不发布本轮工件，但若 Collector 已返回非 error 的凭据更新，流水线会先尝试写回这些更新。输入授权错误直接返回，不启动进程；其它输入错误按依赖缺失处理。
3. **执行首轮 Collector。** Runner 接收 `context` 与 `credentials`，产生 Bridge 响应或执行错误。
4. **执行条件恢复与回填。** 定向范围由 `ScopedQuotaSnapshotMerger` 合回目标结果；本地专用轮次只回填历史服务；包含额度的普通 `agentUsage` 路径才进入 Codex 恢复与 finalizer，再应用服务回填策略。
5. **应用凭据轮换。** 非错误的可处理响应先应用 `credentialUpdates`。写回失败追加存储诊断，有工件且原状态成功时降为 `partial`。
6. **发布快照。** 没有工件时返回不可发布结果；有工件时经 `ArtifactStore.publish` 校验和保存。发布失败按存储错误处理，已写回的凭据不会因此回滚。
7. **评估并回传。** 发布后计算额度预警候选，调度器回调 `AppModel` 并更新相位、定时器和待处理意图。

Bridge `status == error` 或存在授权错误且无工件时，不应用凭据更新也不发布。流水线在运行输入后、首轮后和恢复后检查整体停止状态，停止则返回取消结果；执行器错误、输入失败和发布失败分别保留为不同结果类型。

<a id="screen-lock"></a>
### 3.3 锁屏暂停与解锁补偿

**功能需求**：锁屏只抑制非手动的新额度轮次并返回 localOnly，本地采集照常；解锁按开关、相位、去重窗口和门禁条件提交一次强制额度刷新。

**方案机制**：生产组合根注入 `SystemScreenLockMonitor`。监视器读取 `CGSessionCopyCurrentDictionary`，订阅锁定/解锁、屏幕休眠/唤醒和系统唤醒通知；屏幕休眠直接视为锁定，唤醒时重读控制台状态，缺少可识别字段时按未锁定处理。状态相同不重复通知，stop 移除观察器。执行时的 `isScreenLocked` 取缓存 `locked` 与即时系统探测的逻辑或，漏掉锁定通知时仍可能由即时探测拦截；缓存为锁定时不会仅凭即时返回 false 解锁，需要相应事件更新缓存。

`pauseSubscriptionRefreshOnScreenLock` 默认 true。执行开始时，只有 `isScreenLocked && pauseSubscriptionRefreshOnScreenLock && intent.reason != .manual` 才抑制订阅；策略直接返回 localOnly，仍允许本地采集。锁屏下不安排额度边界提前唤醒。门禁在执行时采样，不中断已经发出的网络请求；手动刷新仍可访问额度。

解锁仅在开关启用、模块启用且允许自动刷新、相位不是 authRequired 或 running、距上次尝试不少于 wakeDedupSeconds 时提交 `wake(forceQuotaRefresh: true)`。它绕过新鲜度但保留非 Codex Provider 的 429 冷却；离线自动门禁仍然有效。锁屏末尾刚执行过本地轮次时，60 秒去重也可能使解锁不立即查询。

两类事件的处理边界如下。

![锁屏自动轮次采用本地策略，手动和解锁事件按各自条件处理](../assets/km/screen-lock-gate.svg)

图：锁屏额度门禁。这里只控制新轮次的额度策略，已有请求不会被撤销。

按实现推演：锁屏后定时轮次不装配外部凭据，并保留历史 services；解锁时若上一尝试是 10 秒前则不补偿。若上一尝试超过 60 秒、模块 idle 且在线，才发起强制额度新鲜度刷新。关闭开关后锁屏不再改变策略，也不由该回调补偿。

**边界与非目标**：监视器的缓存与即时探测组合不构成所有系统场景均准确的实测保证。

## 4. 状态与数据变化

<a id="scheduler-state"></a>
### 4.1 调度状态与意图合并

**功能需求**：调度相位表达能否执行下一轮，界面状态表达如何呈现已有结果；同模块重复意图合并，失败按授权缺失、限流和其它错误分别进入对应相位。

**方案机制**：调度相位与界面状态分别表达“能否执行下一轮”和“如何呈现已有结果”。以下状态图概括启用、执行、失败与恢复；`stopped` 是调度器整体标记，不是模块相位。

![模块调度相位与带条件的执行、失败、取消转移](../assets/km/macos-scheduler-state.svg)

图：模块调度状态。展示网络可用时的常规启用与执行路径，离线门禁见下节；整体停止标记与各相位叠加；显式禁用后在途任务的结果收尾未在图中展开，见下文。

`disabled` 经启用转为 `idle`；`idle` 接收可执行意图后进入 `running`。运行中收到请求或容量不足时，请求保存在 `pendingIntent`。合并保留手动属性，两个定向范围取 Provider 并集，任一全量范围优先。成功发布后回到 `idle` 并先排空同模块待处理意图；非 idle 收尾会丢弃待处理意图。

授权缺失进入 `authRequired`，只允许手动意图重新尝试；部分 Provider 授权诊断若仍有可发布工件，不使整个模块进入该相位。网络可用时，非授权失败进入 `backoff`：限流固定等待 300 秒，其他错误从 30 秒指数退避并加最多 10% 抖动，封顶 1800 秒。边界唤醒与退避均经 C ABI 调用共享 Rust 刷新策略；策略入口不可用时，边界唤醒回退原间隔，退避回退上限。超过 5 次退避后归零计数、回 `idle`，等待正常周期。定向刷新失败后的退避重试范围为全量，`includesManual` 继续保留用于预警抑制，触发原因改为 `backoff`；该标记不使自动重试绕过离线门禁。

取消清空待处理意图；有历史成功时回 `idle` 并显示 `stale`，没有历史成功则转 `disabled` 并显示 `notConfigured`。该路径不会触发周期完成回调。`disableModule` 将模块设为禁用并取消该模块定时器，未直接取消已启动进程；整体 `stop()` 才取消全部执行器任务。禁用后若在途执行继续完成，收尾方法仍会处理结果：成功可发布工件并把相位改为 `idle`，失败可转 `backoff` 或 `authRequired`。`enabled` 仍为 false，后续正常调度及 `startRefresh` 不会启动新任务；不能仅凭相位判断模块是否启用。

<a id="snapshot"></a>
### 4.2 快照与界面更新

**功能需求**：当前快照原子发布并保留有效旧工件，损坏时按 previous 与一次底层回滚顺序恢复；发布成功后回调模型并由映射器生成卡片。

**方案机制**：快照默认保存在 `~/Library/Application Support/Bruce/snapshots/agent-usage.json`，上一份有效快照为 `agent-usage.previous.json`，元数据在 `metadata/modules.json`。`publish` 先验证新工件，保留有效旧工件，原子写入当前文件，最后写入成功时间等元数据。写后读取与编码字节比较；验证过的快照字节相同时复用验证结果。发布路径不再重复创建与 previous 同内容的备份。

读取失败的恢复路径如下。

![当前快照无效时按previous和一次底层回滚顺序恢复](../assets/km/snapshot-recovery.svg)

图：macOS 快照读取恢复。只有 previous 存在但读取失败时才尝试底层回滚；恢复结果标陈旧。

`load` 优先读取当前工件，损坏或不兼容时可回退 previous；previous 也失败时尝试一次底层备份回滚。schema v0 的迁移先保留原始备份，未知新 schema 拒绝；回退结果强制陈旧并记录 schema 错误。启动缓存恢复不要求先访问凭据。

发布成功后，调度器先回调新工件，再发布 `fresh` 或 `partial`。`AppModel` 失效相关缓存，按呈现门控过滤订阅服务，再经 `PanelViewModelMapper` 生成三类卡片。菜单栏和面板使用同一解码结果，分别维护摘要/映射缓存。Provider 定向刷新另有 `started/finished/failed/cancelled` 回调，仅维护目标按钮的刷新集合；它与凭据导入 busy 状态独立。

**边界与非目标**：`publish` 不是跨快照与元数据的单一事务；元数据失败仍可能已有新快照落盘，调度器只在整个发布调用成功后更新内存成功状态。

<a id="chapter-5"></a>
## 5. 异常与恢复

<a id="alert-shutdown"></a>
### 5.1 预警、后台与退出

**功能需求**：额度预警按阈值与去重投递并受开关控制；整体退出停止调度、取消子进程并按宽限强制终止，面板隐藏不关后台。

**方案机制**：预警仅处理 5 小时窗口，优先按 `windowMinutes == 300` 识别；该字段不是整数时才按 5h 或中文 5 小时标签识别。已用量超过 50% 为 50 档、超过 80% 为 80 档、达到 95% 为 95 档；`freshness == stale` 的服务被跳过。调度器按 `serviceID|windowLabel` 保存该窗口已见最高档位，每轮同步条目；仅非手动轮次跨越更高档位时回调。手动轮次仍更新已见档位，启动时从缓存恢复，避免重启重复提醒。窗口回落到低于或等于 50%、消失或被过滤而不再出现在结果中后，其记录才被移除；仅从 95 档回落到 50 档不会降低已记最高档。

![工件发布后比较预警阶梯并按开关决定是否显示气泡](../assets/km/macos-quota-alert-flow.svg)

图：预警评估与气泡显示。手动轮次仍同步档位记录，只有非手动的新跨越才进入显示门控。

应用的预警开关开启时，状态项控制器在菜单栏图标附近展示非激活气泡，不依赖系统通知授权；状态项按钮不可用时不展示。气泡默认 6 秒后淡出，悬停取消计时，移出后重新计时 3 秒；点击主体打开主看板，关闭按钮隐藏气泡。

整体退出先停止调度并取消子进程，等待默认 2 秒宽限后强制终止剩余任务。取消退出会恢复调度；手动刷新在调度器仍为停止状态时也会先调用 `start()` 恢复。面板隐藏只约束动画与视图计时器，不关闭后台调度。

## 6. 场景推演

按实现推演：选择 5 分钟后，调度器的本地周期与额度周期均为 300 秒；上一尝试距今 350 秒时需要查询，100 秒时仍按新鲜度跳过，429 冷却不会因此缩短。在线且额度到期时，定时意图先读旧快照，包含额度采集，成功写回轮换凭据，再发布新工件。若首轮额度失败但有可用本地工件，按服务资格保留旧窗口并标 stale，模块可发布 partial。若输入授权失败，Collector 不启动；若发布失败，已经写回的凭据不回滚。离线自动意图被暂停，手动仍可尝试一次。
