# 订阅配置与凭据管理设计

订阅配置模块负责 Provider 的非敏感设置、账号发现、凭据录入和刷新输入装配。应用装配采用受权限保护的本地文件保存 Bruce 自有凭据，并保留 Keychain 兼容读取。外部 CLI 凭据通过独立的只读路径获取，实际额度查询由 Collector 执行。

## 1. 目标与职责

**功能需求**：配置侧分别管理用户同意、账号身份、凭据和输入权限，让非敏感配置与敏感凭据各归其位。

**方案机制**：配置侧分别管理用户同意、账号身份、凭据和输入权限。

**边界与非目标**：“已配置”表示本地配置规则满足，不保证远端令牌仍然有效。外部额度不可用时，本地分析仍可继续。

<a id="chapter-2"></a>
## 2. 对外契约

<a id="credential-contract"></a>
### 2.1 配置、凭据与账号的边界

**功能需求**：设置页动作经协调器委托服务完成保存、导入和验证；Provider 注册表为每个 Provider 登记凭据键、注入类型与“已配置”判据，配置、凭据、账号摘要分属不同存储与接口。

**方案机制**：`OnboardingCoordinator` 接收设置页动作，把凭据保存、导入和验证委托给 `SubscriptionService`。`ProviderRegistry` 为每个 `SubscriptionProviderID` 登记凭据键、Bridge 注入类型和“已配置”判定规则。Provider 已列入配置、凭据可用、验证通过和允许刷新分别有自己的判据。

| 数据 | 存储或接口 | 含义 |
|---|---|---|
| 用户偏好、统一同意、Provider 状态 | `config/onboarding-v1.json` | 非敏感配置，包含刷新周期、主题、价格覆盖和访问配置 |
| Bruce 自有凭据 | `credentials.json` | `ProtectedFileCredentialStore` 的账户键到字符串映射 |
| 多账号索引与记录 | `CodexCredentialStore`、`ProviderAccountStore` | 在凭据存储抽象上组织账号元数据和完整记录 |
| 外部 Claude/Grok 登录态 | `ExternalCredentialReader.read(source:intent:)` | 只读外部来源，不回写 CLI 凭据 |
| 单次运行输入 | `CollectorRunInput` 的 `context`、`credentials` | 注入 Collector 的瞬时输入，不作为 UI 数据模型 |

`CredentialStore` 提供 `saveCredential(_:forAccount:)`、`loadCredential(forAccount:)` 和 `deleteCredential(forAccount:)`；意图感知接口区分后台自动操作和用户主动操作。UI 发布账号摘要、验证状态和存储健康，不以原始凭据 JSON 驱动呈现。多账号显示名采用“Provider 前缀 · 标签”，用户编辑标签而不能更改前缀。除 Codex 外，默认标签使用该 Provider 内最小未占用的“账号 N”；Codex 恢复默认时使用邮箱前缀，没有邮箱时使用账号 ID 前 8 位。自定义标签去除两端空白后最多 32 个字符，不允许控制字符；同 Provider 内完整显示名按大小写不敏感判重，完整显示名不得超过 256 UTF-8 字节。空标签表示恢复默认。改名不改变账号 ID、凭据键或 Collector service ID。普通 Provider 的存储先写账号记录、再写索引，任一步失败会上报，不能把两次写入理解为单一原子事务。

<a id="chapter-3"></a>
## 3. 内部结构

<a id="storage"></a>
### 3.1 文件存储与兼容读取

**功能需求**：非敏感配置与自有凭据分别落盘到受保护文件，采用原子写入、权限复位与备份回滚；损坏数据原地隔离，不用空数据覆盖现场。

**方案机制**：配置默认位于 `~/Library/Application Support/Bruce/config/onboarding-v1.json`，由 `OnboardingConfigurationStore` 串行读取和原子保存。保存使用 `AtomicJSONStore`，文件权限为 `0600`，目录权限为 `0700`，写入后重读验证并保留上一版本备份。新版本 schema 保守拒绝；损坏配置尝试备份回滚，不可读或无法恢复时返回默认配置。

自有凭据文件的写入顺序如下。

![临时凭据文件经同步校验备份替换和权限复位后才报告成功](../assets/km/protected-credential-write.svg)

图：自有凭据写入。错误会上抛；最终权限设置失败时目标内容可能已改变，不能把备份等同于自动回滚。

`ProtectedFileCredentialStore` 默认写入 `~/Library/Application Support/Bruce/credentials.json`。写入创建权限为 `0600` 的临时文件，写入并同步后重读解码，备份旧文件，再替换或移动到目标并复位权限。父目录创建为 `0700`；已有目录的权限校正是尽力执行。该文件保存凭据字符串，保护依赖本机文件权限，并未实现文件内容加密。

读取区分不存在和损坏：不存在返回空 payload；读入或解码失败时尽力将原文件移动为带时间戳的损坏副本并抛错，避免空数据覆盖现场。文件中没有某个账户键时，可以从装配的 Keychain fallback 读取并迁移到文件；迁移写盘失败上抛。类名和配置字段保留了 Keychain 字样；生产装配的主存储是受保护文件。

<a id="chapter-4"></a>
## 4. 详细设计

<a id="external-oauth"></a>
### 4.1 Claude 与 Grok 的外部读取

**功能需求**：运行输入装配时按固定顺序只读外部 Claude/Grok 登录态，较新的过期值只替换本轮输入，持久化由导入或轮换写回负责。

**方案机制**：Claude 读取顺序为外部 `/usr/bin/security find-generic-password -s "Claude Code-credentials" -w`、`~/.claude/.credentials.json`、`~/.claude.json`。执行器不存在、启动失败、非零退出或空输出时返回 nil，再尝试文件；文件不存在或不可读同样返回 nil。Claude 分支不受外部来源白名单与访问意图过滤；Grok 仍要求 `KeychainAccessController` 允许该来源后才读 `~/.grok/auth.json`。

`LocalCredentialProbe` 把 Claude 的 valid、refreshPending、expired 视为本机检测到；该标记不等于联网认证成功。显式导入经 `ClaudePasteParser` 规范包装并保留 OAuth 字段，`saveClaudeOAuthJSON` 允许 valid 与 refreshPending 入库，expired 要求重登。

运行输入先装配已存多账号，同时读取外部 CLI。账号集合为空时跟随 CLI；已含 `claude-cli` 时，只在外部嵌套 `expiresAt` 大于存储值时替换本轮输入。缺失或解析失败按 0 比较；其它账号不会因此被外部 CLI 覆盖。比较直接使用解析出的数值，不做秒/毫秒统一。选择较新 CLI 数据只改变当前输入，导入或轮换写回负责持久化。

**边界与非目标**：此实现将 Keychain 读取移到外部进程并捕获标准输出，未给该进程增加超时，也未传显式禁止系统交互的参数。原设计要求静默且不弹授权窗口；外部命令及 Mock 测试本身不能证明所有真实 Keychain ACL 场景均满足该目标。

<a id="codex-accounts"></a>
### 4.2 Codex 账号发现、登录与 token 决议

**功能需求**：Codex 发现登录只保存元数据、不导入外部 token；设备码登录成功后保存 Bruce 自有 token 链，输入只向 Collector 提供短期 access token。

**方案机制**：Codex 从 CLI `~/.codex/auth.json` 或 CC Switch 账号库导入时只保存发现的账号元数据，标为需要重新授权，不导入外部 token。已配置判定要求存在完整凭据记录，只有索引或账号名称不够。

用户发起设备码登录后，`SubscriptionService` 启动授权、打开验证页、轮询并交换结果，成功时由 `CodexTokenManager.storeLoginResult` 保存 Bruce 自有 token 链。该管理器对外提供 `validAccessToken(for:now:)` 和 `refreshAfterAccessRejected(for:now:)`，把存储及刷新决议委托给 resolver。输入只向 Collector 提供可用账号的短期 access token；refresh token 留在 Swift 凭据管理边界。

启动时，仅已启用 Codex 才执行旧库迁移。损坏 JSON、schema 不兼容或迁移失败会暂停 Codex 外部额度，不阻断本地统计。查询遇到符合条件的账号挑战时，刷新流水线可经 token manager 做定向恢复，随后合并账号状态和上一份额度。

<a id="local-only-input"></a>
### 4.3 本地专用输入的凭据边界

**功能需求**：额度策略不含外部查询时，本轮只装配本地能力与路径，不继续装配订阅凭据，也不改动持久化账号。

**方案机制**：`runInput(for:quotaPolicy:)` 在额度策略不包含外部查询时写入 `localUsageOnly=true`，返回本地能力与路径输入，不继续装配订阅凭据。包含查询时才沿用统一同意和 Provider 就绪门控，并把跳过集合写入 `quotaSkipProviders`。

**边界与非目标**：这条策略减少本轮输入，不改变持久化账号或现有凭据。

<a id="rotation-writeback"></a>
### 4.4 轮换合并与账号写回

**功能需求**：Collector 回传的 oauthTokens/replace 更新经协调器合并后写回 Bruce 自有存储；写回失败记录诊断，已写回的令牌不随后续快照失败回滚。

**方案机制**：`CredentialUpdateCoordinator.apply` 只消费可解析的 oauthTokens/replace 更新，不消费 Codex 更新。支持多账号轮换的 Provider 仅在索引存在该账号时写回；Claude 的 `claude-cli` 是例外，可以自动 upsert。新记录显示名为 Claude CLI，已有记录沿用索引显示名，成功后设置 connected。

Claude 合并先把白名单字符串写入顶层；只有原 JSON 已有 `claudeAiOauth` 或 `claude.ai_oauth` 对象时，才同步嵌套 `accessToken`、`refreshToken`，并把秒字符串 `expiry` 乘 1000 写为 `expiresAt`。没有旧记录时只生成顶层令牌字段，没有补建嵌套包装。

按实现推演：已有嵌套账号收到新令牌后保留原 scopes 等字段、更新 Token 和毫秒到期值。若存储抛错，协调器记录失败，流水线追加 `CREDENTIAL_PERSIST_FAILED`，有工件的 success 降为 partial；随后快照保存失败也不会回滚已写入的令牌。

输入与写回的数据边界如下。

![配置与凭据经门控装配输入，轮换只回写Bruce自有存储](../assets/km/credential-input-flow.svg)

**边界与非目标**：Collector 的 Claude 解析器仍要求嵌套 OAuth 对象，因此“已落盘”不能直接推出下一轮可独立复用；该路径需要外部 CLI 回退或完整导入数据。

## 5. 流程与状态

<a id="activation-gate"></a>
### 5.1 统一同意与调度门控

**功能需求**：模块启用前先过激活门控，输入提供器再做第二道自动访问检查；同意撤销后模块转禁用，外部来源按各自策略放行。

**方案机制**：`CollectorActivationGate.canActivate` 默认拒绝。参数分别为 `module`、`readiness`、`isModuleSelected`、`appIsAcceptingNewTasks` 和 `keychainAccessConfigured`。当前 `agentUsage` 模块需要同意版本匹配、用户选中、Bruce 存储允许自动访问、应用接受任务，以及就绪度为 `ready` 或 `partial`。撤销同意清除已确认版本并重新协调，模块转为禁用。

输入提供器还有第二道检查：`agentUsageInput()` 要求 Bruce 自有存储允许 `.automatic`，否则返回 `missingAuthorization`，进程不启动。通过后先授予本地会话和本地价格能力，按已启用 Provider 装配凭据；配置已有同意版本且装配结果非空时，才加入 `externalQuotas`。版本的精确匹配由前面的激活门控负责。

`KeychainAccessPolicy` 中，Bruce 自有存储的自动访问要求状态为 `allowed` 且存储版本就绪，用户主动配置可以进入准备流程。外部来源策略要求状态允许且来源在白名单；当前 Claude 读取器有专门例外，见下节。访问策略、Provider 启用状态和面板验证过滤分别作用于存储、运行输入和展示层。

<a id="chapter-6"></a>
## 6. 异常与恢复

<a id="credential-failure"></a>
### 6.1 失败与安全边界

**功能需求**：解析、存储、重登失败写入所属 Provider 错误状态；凭据轮换在发布工件前应用，写回失败降级为部分结果；外部来源只读，凭据仅经 stdin 注入。

**方案机制**：凭据解析失败、存储失败和需要重新登录分别写入所属 Provider 的错误状态；UI 的保存/导入 busy 集合与额度定向刷新集合分开维护。Collector 返回的凭据轮换由 `CredentialUpdateCoordinator` 在发布工件之前应用，写回失败追加 `CREDENTIAL_PERSIST_FAILED`，存在工件时将成功降级为部分结果。

CC Switch 火山凭据导入使用 SQLite `mode=ro` 和 `SELECT`。外部数据库与 CLI 文件作为只读来源，持久化只写 Bruce 自有存储。Bridge 凭据只经 stdin 发送；Runner 不把它放入命令行参数，子进程仅继承固定最小环境。

**边界与非目标**：自动化用例中的解析、门控和账号状态期望不能替代真实服务端有效性或系统授权验收。
