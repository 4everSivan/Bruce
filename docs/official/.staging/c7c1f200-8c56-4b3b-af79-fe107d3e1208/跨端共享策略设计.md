# 跨端共享策略设计

Bruce 的刷新宿主需要根据上一份快照决定是否查询额度、保留哪些旧值以及何时再次唤醒。共享策略核心把这些规则集中在 Rust 纯计算库；网络请求、磁盘写入、凭据读取和调度执行仍由各平台宿主负责。本文描述静态实现，不把共享规则或夹具对拍等同于两端运行环境验收。

## 1. 目标与职责

`collector-policy` 负责额度查询门禁、旧快照回填、尝试时间标注、窗口边界唤醒及退避计算。Windows 进程内直接调用 Rust 实现；macOS 把纯数据编码为 JSON，经静态链接的 C ABI 调用同一实现。共享库不持有账号凭据，也不执行采集、网络或存储操作。

## 2. 对外契约

macOS 使用 `policy-request-v1` 和 `policy-response-v1` 的 JSON 字节交互。请求上限为 4 MiB，`schemaVersion` 为 1，操作包括 `quotaPlan`、`quotaMerge`、`quotaAnnotate`、`boundaryIds`、`boundaryWake` 和 `backoff`。入口拒绝未知字段，并检查任意层级的凭据形态字段；格式、版本、操作或字段不合规时返回带诊断的错误信封。成功信封包含操作名和结果。

C ABI 的 `bruce_policy_call` 接收请求缓冲区及长度，并返回响应指针和长度；调用方必须用相同长度调用 `bruce_policy_free` 一次。入口捕获 panic 并转成错误信封。macOS 的策略调用未取得成功结果时由调用方选择安全回退：边界唤醒使用原间隔，退避使用上限。

## 3. 内部结构

| 职责 | 输入 | 结果与边界 |
|---|---|---|
| 额度门禁 | 上一份 services、启用的 Provider、当前时间、周期及刷新意图 | 返回是否查询外部额度、跳过集合与限流集合；不执行请求 |
| 额度回填与标注 | 新旧 services、门禁结果与时间 | 合并可保留的展示信息、标注尝试时间；宿主负责发布 |
| 窗口边界 | 窗口重置时间、当前时间、原间隔及已消费集合 | 返回下次等待秒数与更新后的集合 |
| 重试退避 | 次数、限流标记、基础值、上限及抖动比例 | 返回计算后的秒数；调度器负责实际等待 |
| JSON 与 FFI | 有界纯数据请求 | 校验并封装计算结果；不授权访问外部凭据 |

## 4. 详细设计

### 4.1 额度门禁与旧值回填

门禁按 Provider 检查上一轮额度尝试时间：优先 `quotaAttemptedAt`，否则回退 `capturedAt`；失败 service 还可回退 `rateLimitedAt`。额度仍在刷新周期内时可跳过查询；服务存在尚未结束的 429 冷却时按 Provider 跳过，冷却期为 30 分钟。手动刷新可绕过新鲜度和冷却，窗口边界意图绕过新鲜度但仍受冷却约束。Codex 是不进入跳过集合的特殊 Provider；锁屏等整体抑制场景由输入参数要求不执行外部额度查询。

本轮被跳过的 Provider 从上一份结果回填。真实查询失败时，策略可以从符合条件的旧 service 借用窗口、余额、币种、套餐、附加信息、类型和采集时间，并标记旧值；调用方不得把这些字段当成本次成功查询的证明。限流判定优先使用显式 `failureKind`；只有旧数据缺该字段时才回退匹配备注。Provider 身份优先读取显式 `provider`，缺失时按 service ID 前缀推断。

### 4.2 窗口边界与退避

边界提取仅处理 `kind` 为 `windows` 的 service 中可解析的 `resetsAt`。计算唤醒时先移除已过去的已消费边界，再从严格晚于当前整秒且未消费的边界中选取最近候选。候选延迟按边界加 `slack` 减当前时间计算；若不小于原间隔则保持原间隔，否则选中该边界并记入已消费集合。默认 `slack` 为 20 秒。

限流退避直接返回调用方给定的固定限流秒数。其他失败按 `min(base × 2^(retry−1), max)` 计算基础退避，重试次数 0 与 1 使用同一首档，指数移位最多为 10；再根据输入抖动比例增加等待并受上限约束。共享函数将比例限制在 0 至 1；平台调用方采用何种比例，应以调用方配置为准。

## 5. 流程与状态

一次额度刷新先由宿主组装上一份快照和本轮意图，策略返回查询计划；宿主按计划运行采集，再将新旧结果交给策略回填，最后由宿主决定发布。共享库只返回数据，不维护全局调度状态。边界去重集合随请求传入并随结果返回，持久与生命周期由宿主负责。

例如，某 Provider 上一次额度尝试仍在周期内时，自动轮次可跳过并回填上一份数据；同一 Provider 因 429 进入冷却时，边界唤醒也不能绕过冷却。用户手动刷新若未被其他宿主门禁阻止，可传入绕过条件重新查询；最终网络结果与快照发布结果仍分别处理。

## 6. 异常与恢复

无效 JSON、超限、未知操作或凭据形态字段不能进入计算，错误以响应诊断返回。调用桥不可用时，macOS 的边界和退避包装使用各自安全回退，不能把该回退解释为共享计算成功。服务查询失败时借用旧展示字段只保护可用信息，不能替代真实新数据；无合格旧值时也不能假定能恢复。实际平台状态、外部服务和进程生命周期不由纯计算库保证。
