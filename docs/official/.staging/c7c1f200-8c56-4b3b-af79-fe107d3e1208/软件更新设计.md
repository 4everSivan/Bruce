# 软件更新设计

Bruce 的软件更新入口位于设置中心维护页。用户可以检查版本、跳过特定版本、下载安装包并发起安装；自动检查和手动检查共用更新信息，但失败提示不同。macOS 和 Windows 使用同一份发布清单，安装机制分别由原生安装器和 Tauri updater 承担。本文描述源码中的静态行为；成功发布、下载与安装需要各自的运行环境证据。

## 1. 目标

更新功能使用户在应用内了解新版本并选择何时升级。发布方提供清单和完整安装包，客户端比较本地与远端版本；它不做差量更新，也不在发现版本后强制安装。开发构建在 macOS 缺少有效应用包版本时禁用检查。

## 2. 设计

### 2.1 清单与版本

`latest.json` 包含版本、发布时间、更新说明和按平台区分的资产。`darwin-universal` 项提供下载 URL、SHA-256 和签名；`windows-x86_64` 项提供 URL 和签名。macOS 解析版本、说明、下载地址和哈希，不在此步骤使用签名；Windows 更新插件需要清单中每个平台注册项具有 URL 和签名。包体尺寸不在清单中，客户端可通过 HEAD 获取，缺失时不显示确定总量。

macOS 版本解析器接受三段数字和可选 `v` 前缀，按主、次、修订号逐级比较；清单还须提供 `https` 协议、`github.com` 主机和 64 位十六进制 SHA-256，否则认为清单无效。Windows 由 updater 插件判断可用更新；辅助比较函数解析每段开头的数字，无法解析的部分按零处理，因此不应把 macOS 的严格解析规则归为双端同一实现。

### 2.2 检查、跳过与显示

自动检查在启动约 30 秒后首次执行，随后以 24 小时节奏执行；用户关闭开关时不发起自动检查。手动检查不受自动周期限制。自动检查失败保持原有主要状态，不显示失败状态；手动失败可呈现网络、HTTP 或清单错误。成功检查后记录最近检查时间。

设置页显示当前版本、自动检查开关、检查入口和对应状态。发现可用版本时可展开更新说明、打开发布页、下载或跳过。macOS 在自动检查尚未返回时允许手动检查接管同一请求；迟到的检查结果不会覆盖下载、就绪或重启状态。Windows 的检查由独立后台线程执行，不能据此推断它具有相同的并发合并规则。

跳过记录持久化。macOS 对远端版本小于或等于已跳过版本保持跳过；远端出现更高版本或本地追平已跳过版本时清除记录。Windows 的辅助判定对相同版本维持跳过；更高版本会清除记录，另在本地版本追平时清理。用户也可以手动恢复。

### 2.3 下载、安装与重启

macOS 开始下载前检查当前应用和更新目录是否位于同一可写卷，并排除 App Translocation 等不满足替换条件的位置；不满足时转到手动更新。下载的 ZIP 先核对 SHA-256，再解压并清理扩展属性，检查应用包标识（存在当前标识时）、可执行文件和版本。待安装版本必须高于本地且与清单一致。校验通过后进入就绪态；选择稍后时保留暂存文件。

图：macOS 从可用版本进入下载、就绪和安装重启的状态；这是局部状态图，检查版本与跳过版本的规则见本文第 2.2 节。

安装时 macOS 先将旧应用移动到备份位置，再将暂存应用移到原位置。第二次移动失败会尝试恢复备份；若恢复也失败，保留备份供后续处理。替换成功后启动独立等待进程，等待旧进程退出后打开新应用，等待上限约 30 秒；如果等待器启动失败，新版本已放到原位置，旧进程仍运行，需要用户手动重开。

Windows 通过 updater 下载完整包并保存于内存，就绪后将字节交给插件安装；插件验证 minisign 签名并执行 NSIS 安装。取消操作设置取消标志，停止进度呈现并在网络下载结束后丢弃结果；该接口不会中止底层传输。签名或安装失败返回可用状态并报告错误。

## 3. 流程

### 3.1 正常路径

1. 启动自动检查，或用户从维护页手动发起检查。客户端读取清单并比较版本。
2. 远端版本较新且未被跳过时显示可用版本。用户选择下载；状态进入下载中，展示可取得的进度。
3. 下载与平台校验完成后进入就绪态。用户选择安装并重启，平台安装器接管替换或安装过程。

### 3.2 替代路径

本地版本不低于远端时显示已是最新；选择跳过后，同版本不再提醒。检查失败时，自动检查静默，手动检查显示错误。macOS 取消下载会使在途回调失效并返回可用状态；Windows 等待底层下载结束后丢弃结果。选择稍后不会立即安装。

## 4. 数据与接口

| 对象 | 生产者与消费者 | 关键约束 |
|---|---|---|
| 更新清单 | 发布流程生成，双端检查组件读取 | 按平台提供 URL 和签名；macOS 另要求 SHA-256 |
| 更新偏好 | 设置持久层保存，检查调度器读取 | 自动检查开关、上次成功检查时间和跳过版本分别保存 |
| 更新状态 | 平台更新服务生成，设置页消费 | 空闲、检查、最新、可用、下载、就绪、失败、跳过和重启过渡等状态不等同安装成功 |
| 安装包 | 发布流程提供，平台安装器读取 | macOS 检查哈希与应用包；Windows 由插件验证签名 |

发布流程从 `VERSION`、发布资产与说明生成清单；Windows 更新签名所需私钥由发布环境注入，缺少必要签名时生成流程不能构造合规更新清单。源码中的发布约束不证明当前外部发布环境已配置。

## 5. 异常与边界

检查与安装是不同阶段。清单格式正确不证明包体完整，包体哈希匹配也不证明应用已安装或成功启动。macOS 仅在替换动作失败时尝试所述回滚；等待器启动失败发生在新应用已就位之后。Windows 下载取消不保证立即停止网络传输。两端使用不同的版本辅助解析、存储和安装机制，共享状态文案或测试夹具不代表系统行为完全相同。

## 6. 验证要点

应分别覆盖有效和无效清单、较新与已跳过版本、自动和手动检查失败、下载取消、安装校验失败及恢复路径。macOS 安装器可注入命令与移动操作供临时目录测试；Windows 纯逻辑测试覆盖版本比较、跳过和状态序列化。测试代码表达的是预期，本说明不声称这些测试、真实发布服务器或两端设备本次已运行通过。
