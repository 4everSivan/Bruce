## ADDED Requirements

### Requirement: 独立 Dock 应用生命周期

系统必须 (MUST) 以独立 macOS 应用运行, 在 Dock 中显示应用图标并提供可重复打开的主窗口. 用户关闭主窗口时, 应用必须继续驻留并执行已授权的定时刷新, 直到用户显式退出应用.

#### Scenario: 首次启动应用

- **WHEN** 用户从 Finder、Launchpad 或 Dock 启动应用
- **THEN** 系统显示 Dock 图标和主窗口, 并进入本机状态检查流程

#### Scenario: 关闭后重新打开主窗口

- **WHEN** 用户关闭主窗口但未退出应用, 随后再次点击 Dock 图标
- **THEN** 系统重新显示现有主窗口或创建等价主窗口, 且不会创建重复调度器

#### Scenario: 显式退出应用

- **WHEN** 用户选择退出应用
- **THEN** 系统停止调度新任务, 取消或安全结束当前子进程, 然后退出

### Requirement: 模块化看板导航

系统必须 (MUST) 在同一主窗口中提供 Agent 用量、GitHub 热力图和 GitLab 热力图三个独立模块的导航, 并为未配置或被禁用的模块显示明确状态.

#### Scenario: 切换看板模块

- **WHEN** 用户在侧边栏或等价导航中选择另一个模块
- **THEN** 系统显示该模块最近一次有效快照及其更新时间, 且不会重置其他模块状态

#### Scenario: 打开未配置模块

- **WHEN** 用户选择尚未完成依赖或登录配置的模块
- **THEN** 系统显示缺失项和可执行的配置入口, 而不是将其呈现为空数据

### Requirement: 本机设置与刷新入口

系统必须 (MUST) 提供应用内设置, 允许用户启用或禁用模块、查看依赖和授权状态、调整自动刷新开关, 并对单个模块或全部模块执行手动刷新.

#### Scenario: 手动刷新单个模块

- **WHEN** 用户在某个模块选择手动刷新
- **THEN** 系统仅为该模块提交刷新请求, 显示进行中状态, 并保留当前快照直至新数据验证成功

#### Scenario: 禁用模块

- **WHEN** 用户在设置中禁用某个模块
- **THEN** 系统停止为该模块创建新的自动刷新任务, 同时保留其本机历史快照供用户决定是否清除

### Requirement: 隐私安全的 Dock 状态

系统必须 (MUST) 通过 Dock badge 或等价的 Dock 状态表达总体刷新或风险状态, 但不得在 Dock 中显示账号名、仓库名、访问令牌或其他敏感标识.

#### Scenario: 正常刷新完成

- **WHEN** 所有已启用模块完成刷新且没有需要用户处理的错误
- **THEN** 系统清除错误 badge, 并可显示经过压缩的非敏感汇总状态

#### Scenario: 存在需要处理的授权错误

- **WHEN** 任一已启用模块因授权失效而暂停
- **THEN** 系统显示通用提醒 badge, 并仅在用户打开应用后展示具体服务和处理建议

### Requirement: 缓存优先启动体验

系统必须 (MUST) 在启动时优先呈现已验证的本机快照, 不得等待依赖扫描或网络刷新完成后才显示主界面.

#### Scenario: 有可用缓存时启动

- **WHEN** 应用启动且某模块存在有效的最近成功快照
- **THEN** 系统立即渲染该快照并标注其更新时间, 同时在后台判断是否需要刷新

#### Scenario: 无缓存时启动

- **WHEN** 应用启动且某模块没有有效快照
- **THEN** 系统显示非阻塞的初始配置或加载状态, 并保持其他有缓存模块可用
